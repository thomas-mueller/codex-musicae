# App V2: Consolidated Requirements (status: V1 check done 2026-11-20, interview continues)

## 0. How to use this document
- Requirement IDs (R-xxx) carry the latest agreed wording. Idea numbers (#n) and backlog IDs (BKL-xxx) are kept for traceability.
- Answer categories used in the interview: (1) details now, (2) queue for later, (3) postpone until V1 can be checked, (4) clarify interactively during implementation.
- "Tunables" means the bundled tunables file (see R-12d). "V1 check" means the review of the V1 app/code (category 3). It is done: results are in section 12. Items that depended on it are resolved inline or point to an open question `Q-n` in section 11.
- Lines starting with "_V1:_" state V1 facts, with V1 requirement or decision IDs (`docs/requirements.md`, `docs/decisions.md`, `docs/limitations.md`) or file paths.
- Process (#45): the public "grillme" skill was not available. The interview was run manually, one question at a time.

## 1. General rules
- **R-UX1:** User-facing settings are abstract and non-technical. Algorithm parameters live in tunables. Explicit exception: the detection popup (R-19c).
- **R-6e:** Wherever a long click is specified, the desktop equivalent is holding the mouse button for the long-press time (as V1). No special right-click rule. _V1: `LongPressDirective` uses pointer events for every pointer type, `T:layout.longPressMs` = 500 ms, the context menu is suppressed. Right-click is used only on the open-file control (recent files, DEC-087)._
- **R-6d:** One global "Reset all settings" in global settings resets all user settings (palette colors, thicknesses, language, highlight mode, marks switch, dead time, suppressed warnings, per-file choices, first-run hints, stylus detection flag, see Q-17). It never touches file content (marks, annotations). Confirmation precedes it (assumed).
- **R-14b:** No significant changes to V1 code, no architecture changes unless well justified and explained first. Clean, minimal, readable code, no leftovers, use existing libraries.
- **R-14c:** Automated checks (unused code/dependencies, lint, license check) run in the fast CI workflow. _V1: `lint-test` runs ESLint (boundaries), template, static-compliance, iOS-config, agent-copy and traceability checks. There is no unused-code, unused-dependency or license check._
- **R-14a:** V1's dummy-data mechanism is removed and replaced by real PDFs. _V1: the "dummy data" is the generated synthetic PDFs: `scripts/make-test-pdfs.mjs` (`e2e/fixtures/synthetic-score.pdf`, `damaged.pdf`), `scripts/make-corpus.mjs` (8 PDFs in `e2e/corpus/`, DEC-113) and `scripts/make-large-pdf.mjs` (`e2e/perf/reference-120.pdf`, built in CI, DEC-115). There is no demo data inside the app. Replacement goes with R-13; synthetic edge cases without a real equivalent (damaged, blank, encrypted) may stay as fixtures, see Q-22._
- **R-12c:** Tunables file is self-explanatory with comments (units, meaning), defaults visible. _V1: mostly done. A units header and requirement IDs per value exist; some values lack a unit or meaning comment. Small work item._
- **R-12d:** Tunables and feature configuration are bundled at build time. _V1: already so. `src/config/tunables.ts` is a TS constant compiled into the bundle; nothing is loaded at runtime. No change._

## 2. Editions, monetization, legal
- **R-22a:** Free mode is strictly read-only: no save, no Send to, no export, no persistence of any kind. In-session changes (annotations, marks, organization) work but stay temporary.
- **R-22b/c/d:** Blocked actions are visible but disabled (shows what paid offers). Web app behaves exactly like the free version. Free version persists no app state (settings, zoom, recent files, per-file choices). _V1 has no edition concept and no feature flags; everything is new. V1 persists on every platform: session (open tabs, positions), recent files, tool settings, ratio defaults, stylus flag (FIL-015, DEC-031)._
- **R-22e:** Free feature set is configured per platform in two separate feature-configuration files (web, native). The paid native build enables all. Separate from general tunables. Each build bundles only its own file. Each feature has an on/off switch with a comment.
- **R-22l:** Web-only organizational features (V3: imprint, documentation, manual, advertisements) are controlled by the web file only.
- **R-22g:** Free and paid are separate apps per store (4 listings). One codebase, feature set selected at build time. Web = free.
- **R-22h:** Paid is a one-time purchase. Price decided at release (suggestion about 4.99 EUR).
- **R-22i:** Distinct app IDs for free and paid, fixed before first publish (decide during implementation). _V1: one ID `T:identity.appId` = `app.web.codexmusicae` for Android and iOS (GEN-002/003)._
- **R-22j/k:** Tests: free build disables every paid feature and contains no file-writing path, paid enables all, each configuration is tested separately, a feature without a switch in every configuration fails the build.
- **R-32a:** You own the store accounts. I guide setup. Paid-app tax and banking steps are done by you (Germany: business registration, tax number, imprint; consult a Steuerberater). Add a plan step "business and tax preparation" before the first paid release.
- **R-8a:** V2 sends no data to any server (no crash reporting/analytics, BKL-020 not in V2). _V1: none (GEN-005/006)._
- **R-8b:** Web app must store no cookies/local storage/IndexedDB. Add an automated test. _V1 check: V1 web uses `localStorage` (`adapters/web/web-preferences.ts`, prefix `cm.v1.`: session, recent files, tool settings, ratio defaults, stylus flag) and IndexedDB (`adapters/web/web-file-access.ts`, database `cm-files`: file handles). No cookies. The PWA service worker (production web build, `ngsw-config.json`) stores the app's own files in Cache Storage for offline use (PLT-009). Both direct uses must go; on web this also removes session restore, recent files and permission re-grant. Service-worker cache: Q-9._
- **R-8c:** Native apps store PDFs and configuration locally only. Store privacy declarations state "no data collected". Legal assessment is yours or a lawyer's.
- **R-8d:** V1 loads no third-party libraries, fonts or CDN resources (verified). Add an automated test failing on requests to external hosts. _V1: pdf.js worker, cmaps, standard fonts, wasm and ICC files, OpenCV.js, icons (sprite) and translations are served from the app's own assets (GEN-005, NFR-012). `scripts/check-static-compliance.mjs` only checks the index template for foreign URLs and analytics names. No runtime test watches network requests: the test is new._
- **#42 Legal protection:** Closed-source license (EULA/proprietary terms), technical protection: no source maps in production builds. **#48:** Minify production builds. **#49:** Automated dependency license check for closed-source commercial compatibility (no GPL/AGPL). (Not yet discussed in detail.) _V1: the repository `LICENSE` is proprietary (DEC-125). The production build is minified and has no source maps (Angular production defaults, verified in `dist/`), third-party licenses are extracted, and `THIRD_PARTY_NOTICES.txt` exists. No automated license check yet. Store-facing EULA text does not exist._

## 3. Files and top bar
- **R-1a:** No Save button. Autosave as in V1. In free/web, autosave is off. _V1 triggers (SAV-008, DEC-034): `T:saving.autosaveIdleMs` = 3000 ms after the last change, tab switch, tab close, app hidden or paused; never during a stroke. Also an automatic save after detection completes on a writable file (SAV-012), see Q-5. On failure the next trigger retries (SAV-009). Web writes in place only in Chromium (File System Access); Safari and Firefox offer "save a copy" only (SAV-011, LIM-008). V1 has no Save button; "save a copy" sits in the overflow menu and behind the tab's lock icon (ASM-24)._
- **R-1b:** Open is integrated with the file title. No Save button.
- **R-1c:** File entry shows name, modified marker, "x" (in that order). _V1 tab: name, close icon and one status marker (unsaved dot, error, read-only lock, needs-re-open; FIL-003). The error, lock and needs-re-open states still need a place in V2 (assumed: the marker position shows them)._
- **R-1d:** Modified marker shows unsaved changes. In free/web it is the only indicator.
- **R-1e:** Click on current file entry opens the list of all open files. Replaces V1 tabs. _V1: expanded layouts show a tab bar, compact layouts already use one button with the list (FIL-004, `features/tabs/tab-switcher.ts`). V2 uses the compact behavior everywhere._
- **R-1f:** Previous/next file buttons left and right of the entry, no labels. Disabled at the ends (assumed).
- **R-1g:** "+" button right of them opens a new file, replaces V1 Open button. _V1: a long press or right-click on the open button opens the recent-files list (FIL-008, DEC-087). V2 does not mention recent files: Q-20._
- **R-1h:** Entry uses almost the full top-bar width. Drop-down list also full width. Ellipsis only as fallback.
- **R-1i:** No reordering in V2. Order is opening order.
- **R-1j:** Opening via file picker as in V1. New: accept PDFs from the system share sheet / "Open with" on Android and iOS (not web). _V1: Android has an "Open with" `VIEW` intent filter for `application/pdf` (content and file schemes, FIL-018) but no `SEND` filter, so the app is not in the share sheet: new. iOS: Info.plist declares PDF (`com.adobe.pdf`, role Editor, rank Alternate) with `LSSupportsOpeningDocumentsInPlace`; files arrive by the URL-open event (PLT-012/013), unverified. Web: the PWA file handler (launchQueue) works in desktop Chromium (FIL-019); it is out of scope for V2 and may stay._
- **R-1k/l/m/n:** No file-count limit, no eviction logic. Inactive files release rendered data. Referenced files look like other files. Stress test with many real PDFs on an emulated low-memory device. _V1: no tab limit and no eviction (fits R-1k). Inactive tabs keep their bitmaps in the shared LRU cache until evicted by budget; they are freed only on close and, for all inactive tabs, at memory-governor level 3 (NFR-009, DEC-085). R-1l is a change: free on switching away._
- **R-54a/d:** Overwrite confirmation at the first autosave of a file per session, once per file per session. Autosave does not overwrite before the answer (safe default; V1 has no dialog, so there is no V1 behavior to keep). Changes stay in memory and the modified marker stays until the answer. See Q-5 for the save after detection.
- **R-54b:** Dialog offers "Overwrite", "Save as new file" (new location becomes the input file), "Cancel". _V1 "save a copy" (FIL-017) writes a new file but keeps the original as the tab's file; V2 switches the tab to the new file._
- **R-54c:** Option to disable for this file or for all files, persists across sessions.
- **R-54e/f:** iOS autosave/reopen must be verified (Files app, iCloud Drive, other providers). Unwritable file: warn once per file per session, offer "Save as new file", modified marker stays. Shared-in copies are treated as read-only if no write access. _V1: iOS write-back writes a temp file and replaces the original in one coordinated step, with a copy fallback; mail attachments open read-only (lock icon). All iOS code is `UNVERIFIED(ios)` and the repository has no tester results (`docs/ios-unverified.md`). V1 shows the lock icon on unwritable files, without a warning (FIL-016)._
- **R-54h/i/j/k:** Per-file choice uses one single file-identification mechanism everywhere, stored in local settings, cleared by Reset. Which mechanism: Q-1. _V1 identifies files by platform reference: web `isSameEntry` on file handles, Android document URI, else equal name, size and last-modified time (FIL-002). There is no path and no content fingerprint._
- **R-21a:** "Send to" produces one PDF with annotations flattened as standard PDF content and marks in the file metadata.
- **R-21b/c/e:** Sent via system share sheet where available or saved as a local copy. Paid native only. Desktop browsers behave like free (visible, disabled, no download).
- **R-21d/f/g:** No printing at all. Exported annotations need not stay editable. Original PDF is never changed. Working file (editable data via autosave) and exported flattened copy are distinct.
- **R-30f/g/h:** Opening a file with cross-file marks tries to open referenced files too. On failure: warning, metadata untouched. In slide mode, an unresolved jump stops the presentation at that position. _V1 has no cross-file marks and no way to find a file by itself: a file can only be reopened through a stored handle (web, IndexedDB) or a persisted URI permission (Android) of a file the user picked before (DEC-111, DEC-112). On web without persistence (R-8b) referenced files can never open automatically: Q-8._
- **R-30i:** Closing a referenced file keeps marks and shows an immediate warning with "Don't show again" (persisted, cleared by Reset).
- **R-30j:** Already open file stays current. Referenced files open in the background.
- **R-30k:** Opening a file whose content matches an open file reuses and switches to the open one. _V1 only detects the same file entry (FIL-002), not the same content in another file: needs Q-1._
- **Closing files (new from V1 check):** _V1 saves before closing; if saving fails the tab stays open with the error icon (FIL-006). A read-only tab closes without asking and drops its in-memory changes (LIM-029). In free/web every close drops changes: Q-6._

## 4. Marks, jumps, bookmarks
_V1 model (ORG-008…024, PLY-001…013): all marks sit on **junctions** (the gaps between systems, drawn as tappable bars), not on systems. Kinds: jump (origin junction, target junction, **pass number** ≥ 1), slide break, stop. There are no start marks and no bookmarks. A system end maps exactly onto a junction: the right end of system k is junction k, the left end of system k is junction k−1. So the V2 system-end interaction can keep the V1 junction model and the playing-order logic (R-14b). New data (start marks, bookmarks, labels, cross-file references) needs a new `schemaVersion` with a migration (SAV-002/003)._
- **R-19b/R-19f/R-28n:** Organization mode has tools: detection, refine, delete, bookmarks, start, stop, jumps. No tool active by default. Pressing the active tool again deactivates it. Only one active at a time. Choosing another tool cancels a half-defined mark. _V1 has no tools in organization mode: a tapped bar shows a chip with jump, slide break, stop and delete (ORG-014). The V2 list has no slide-break tool and no pass number: Q-10, Q-11._
- **R-28a-c/o:** Actions trigger on systems, not bars. Active areas are the left and right ends of a system, width from tunables (start value 20%, tuned in implementation). Right end: jump start, stop mark. Left end: jump target, start mark, bookmark. With the jump tool, right end sets the start, left end sets the target. Wrong end does nothing. _Note: junction 0 (before system 1) and junction N (after the last system) are reachable as the left end of system 1 and the right end of system N. V1 allows a jump from junction N (D.C. at the end, DEC-066) and a target at junction 0; both stay possible._
- **R-28d:** Choosing jump start prompts for the target and vice versa. _V1: only start-then-target: select the origin, tap the jump icon, all other bars become targets with a hint bar and a cancel icon, then the pass stepper opens (ORG-015/016). "Vice versa" (target first) is new._
- **R-28e/f:** Every mark can have a user text label. Every mark is automatically labeled with the original PDF page number. Jumps show "start page -> target page". Both shown together. _V1 labels marks with playing-order numbers ("4 → 5 ×2", break "4 | 5", stop "4"; DEC-102, ORG-018, ORG-021) and has no user labels. V2 replaces this: Q-12._
- **R-30a/e:** Cross-file marks label "filename:page" (jumps "fileA:5 -> fileB:2"). Same-file marks show page only.
- **R-28g/h/i:** Chosen system gets a highlight at the clicked end, candidates (both directions, all systems) at the opposite end, same width setting. Candidate opacity modes chosen by the user with abstract labels: linear (default), exponential, constant. N, H, floor in tunables.
- **R-28j:** Cancel half-defined jump by tapping elsewhere, Escape, tapping the chosen system again, Android back. _V1: Esc, Android back and the cancel icon (ORG-015, NAV-018)._
- **R-28k:** Conflicts as in V1: no conflict checks. _V1: several jumps may share a junction, also with the same origin and pass (the earliest created wins, PLY-006); no plausibility checks (ORG-017); slide break and stop toggle on their junction; at most one stop per junction (PLY-009); stop and break only at junctions 1..N−1. Open for V2: what one start mark per file means and whether several bookmarks per system are allowed (assumed: one start mark per file, several bookmarks allowed side by side, R-29)._
- **R-28l:** Labels inside the colored marker, shown in organization mode and marks list.
- **R-28m:** Marks hidden in annotation mode by default, optional global setting "Show marks while annotating". Never shown in slide mode. _V1 shows marks only in organization mode._
- **R-28p/q:** Creating marks never scrolls the view on its own (except user-triggered file switch for cross-file). Tests compare scroll position.
- **R-28r:** No label length limit. Marker grows or wraps, never overlaps or leaves the screen.
- **R-29a-f:** Bookmarks have their own color set in tunables, cycling assignment as V1 jumps. Start marks fixed green, stop marks fixed red (tunables). Multiple marks on one system sit side by side. _V1 jump colors: `T:colors.jumpPalette` (8 colors), assigned cyclically by jump id, both ends the same color (ORG-018). V1 stacks several markers on a system from the edge._
- **#50/R-59a:** Stop marker larger and colored. **#59:** Start marker similar, labelable. _V1 stop: a `stop_circle` icon (16 px, `T:layout.barRowIconPx`) in the bar row (ORG-023)._
- **Start mark (new, semantics open):** Q-13.
- **R-30b/c/d:** Cross-file bookmarks and jumps. Targets only from open files, picked by switching to the other file. Pending state survives the file switch. Closing the source or other file cancels it.
- **R-40a/b/c:** Marks list button grayed out when no marks (including cross-file ones referencing the file). Tapping an entry scrolls to it in the current mode. Reading order. Delete from list as V1. No editing from list, no filter. _V1: the marks list exists only in organization mode (tool strip, compact sheet), disabled only without an open file; entries are ordered by the **playing order** (unreached items dimmed at the end, DEC-099), not by reading order; tap navigates and selects; delete by swipe left or trash icon (ORG-021). V1 has no marks list in annotation or slide mode, so there is no slide-mode behavior to copy: Q-14._

## 5. Detection and refinement
- **R-18a/b:** Auto-detection on loading a new file. Metadata with systems skips detection. _V1: already so (DET-001, DET-023). If the embedded page count differs, the data is discarded and detection reruns (SAV-005)._
- **R-18c:** Short click on the detection tool offers: rerun all pages, current page, cancel. No extra confirmation for refinements (undo covers it). _V1 can only rerun the whole document (level change with confirmation, DET-014/015); rerun of one page is new. V1 rerun rule: previous results stay active until done, then jumps, breaks and stops are kept only if the total system count is unchanged (DET-015). For V2 with marks on systems this rule must be revisited, assumed: per-page rerun keeps marks of systems that still exist (to settle in implementation, category 4)._
- **R-18e (requirement):** Detection continues when the app is not in focus. Resumes cleanly. Report platform limits to the owner. _V1 pauses on purpose while the app is hidden, for `T:detection.idleBeforeResumeMs` = 1000 ms after user input, and under battery saver (DET-017, tunables `pauseWhenHidden`, `pauseOnBatterySaver`). Per platform: web: set `pauseWhenHidden` to false; the worker keeps running in a hidden tab (browsers may throttle it). Android: the WebView and its workers are suspended when the app goes to the background; continuing needs a native foreground service (new native code, not small). iOS: background execution is limited to a short grace period. Decision: Q-16._
- **R-18f:** No cancel of a running detection. Short click on the tool during a run is ignored. _V1 has no cancel either._
- **R-18g:** Behavior during detection as V1: _pages are processed in page order, one at a time, in a worker (DET-002); a page navigated to in organization mode is processed next (DET-021); slides, bars and marks are usable for the finished prefix of pages (DET-019), unfinished pages show provisional bars that are not selectable; scrolling, zoom, mode switches and drawing stay possible; detection yields to user input (DET-017)._
- **R-19a/c:** V1's three manual detection buttons removed. Long click on the detection tool opens a popup: min/max system width (units of page width), min/max system height (units of page height), resolution in DPI. Technical on purpose. Defaults from V1 internal values. _V1: the three buttons are the detection-level selector fast / standard / fine (DET-013/014). Level values (`T:detection.levels`): resolution 100 / 150 / 200 dpi, `minSystemWidthRatio` 0.5 / 0.5 / 0.4, `fullWidthSystemRatio` 0.75 / 0.75 / 0.7 (at least this wide is always a system), `adaptiveBlockSize` 31 / 47 / 63 px, `adaptiveC` 15; default level `fast`. V1 has **no** maximum width and no minimum or maximum height filter: Q-15._
- **R-19d/i/j:** Global settings checkboxes: highlight systems (filled transparent area with soft fading edges), highlight vertical-space bars (V1), number systems. When fill is on, numbers get a cut-out or contrasting color. _V1 draws no system outline: a system is visible only through the junction bars around it (`T:colors.orgBar`: tint #00897B, opacity 0.3, selected 0.55, provisional 0.12), its number label and its jump markers. "Number systems" in V1 means playing-order numbers (ORG-012): Q-12._
- **R-19g:** Bars are no longer clickable. _V1 bars are the only tap targets for marks (ORG-013)._
- **R-36a-d:** Refine tool = rectangle tool, resizable via corners/edges. Long click popup with one boolean: (a) save rectangle as new system box at the right position in the list, or (b) hint mode: largest combined bounding box of detected boxes inside. **R-36h:** If hint mode finds nothing, the drawn rectangle is accepted, no message. Delete tool deletes any system with a click. Move/split via delete plus redraw. _V1 has no box editing (LIM-006, BKL-006: promoted by this). Hint mode needs the component boxes, which V1 discards after selection (DET-020, DEC-101): the engine must keep them per page in memory or rerun the page._
- **R-36i:** Refinement only works on pages whose detection has finished.
- **R-55a:** Undo/redo covers all tools in both modes, separate history per mode. Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z work in annotation and organization mode. _V1: undo/redo covers strokes only, per document, up to `T:annotation.undoDepth` = 200 steps (ANN-006); jumps, breaks and stops have delete without undo (ORG-024, LIM-018); the buttons exist only in annotation mode; keys with Ctrl, Alt or Meta are ignored (NAV-002), so there are no keyboard shortcuts. All new except stroke undo._
- **R-10a-h:** System number weight depends on the aspect ratio of the system's own box (wide and flat bolder, mapping in tunables). Size as V1, reduced when it doesn't fit the width. Tiny safety floor in tunables. _V1: digits cover `T:layout.systemLabelHeightRatio` = 0.8 of the system height, font weight 200 (light), digit height 0.72 em, bar color and opacity, centered on the page (ORG-012); no width check, no floor._
- **R-37a/b/c:** Organization mode uses annotation mode's progress indicator: x/n page counter at the right end of the horizontal scroll bar, n = processed pages with trailing "+" during detection. V1's separate left counter is removed. _V1: organization mode shows a processing icon with "processed/total" pages plus a per-page processing icon (DET-016) and "page x / n" in the bottom bar (ORG-004); annotation mode shows "slide x / n+" while detection runs (SLD-016)._

## 6. Annotation tools
- **R-20a:** Tools: pen, highlighter, eraser (V1) plus text, music stamps, mover. **#56:** hand drawing button removed (drawing/scrolling switch as V1, R-56a/b). _V1 drawing vs scrolling: with a tool active one pointer draws and two pointers zoom and pan, tap zones and swipes are off; with no tool active one finger pans (when zoomed) or swipes (ANN-008, ARC-006). Stylus (STY-001…004): the first `pen` pointer event sets the persisted flag `stylusSeen`; from then on only the pen draws and fingers navigate, even with a tool active; touches are ignored while the pen is near and 300 ms after. The "hand drawing button" is the finger-drawing toggle (`touch_app`) in the pen popup (STY-003), default off. Stylus mode covers the base need; removing the toggle has a consequence: Q-17._
- **R-20i:** Pen, text and stamp share one color. Palette and color chooser exist only in the pen popup. Highlighter has its own color.
- **R-6a/b/c:** Long click on a tool opens palette plus stroke width settings (V1). New: long click on a palette color opens a color chooser. Defaults and long-click duration in tunables. _V1: long press on the pen or highlighter button activates the tool and opens the popup (DEC-106); 6 color presets each (`T:colors.penPresets`, `highlighterPresets`); the eraser has no popup; no color chooser._
- **R-7a-g:** Thickness is one value per tool with thinner/thicker buttons (replace the 3 presets). Step/min/max in tunables, buttons disabled at limits, per-tool memory. Preview next to the buttons. Pointer cursor: circle at actual stroke size in tool color with contrasting ring, crosshair only for very thin strokes, plain circle for thick ones, scales with zoom. Touch: temporary preview after each change. _V1 presets: pen 0.5 / 1 / 2 pt, highlighter 8 / 14 / 22 pt, default index 1 (ANN-003/004); no custom cursor._
- **R-20b-c:** Stamp tool draws on each click, size via smaller/larger like thickness.
- **R-20p:** Stamp popup shows n (default 8, tunables) most recently used stamps in a 3x3 grid, the ninth cell is three dots opening a scrollable submenu with all symbols. Free/web always starts with the tunables set. Tool button shows the selected symbol. Cursor shows a stamp preview. No stamp group text needs translation.

Initial 8 finalized in implementation. _V1 icon set is Material Symbols only (DEC-080), which has no music glyphs: Q-21._
- **R-20j:** Text tool with default size and smaller/larger. Writing cursor on click, cursor also serves as preview.
- **R-20m/n:** Multiline text, confirmed by tapping elsewhere, editable by clicking it with the text tool active. Empty text creates nothing (assumed).
- **R-20g/h:** Mover tool moves any annotation in x/y, selects like the eraser. No resize after drawing.
- _Storage of text and stamps (new from V1 check): V1 writes only `/Ink` annotations and does not display other annotation types (SAV-006, LIM-025, LIM-030). Text and stamps need a storage form that other viewers display and the app can read back and edit (assumed: standard PDF annotations with appearance streams written by the app, like ink; settle in implementation)._
- **R-52a/b/c:** Only the highlighter gets less transparent/darker, fixed value in tunables, tested on real PDFs. _V1: `T:annotation.highlighterOpacity` = 0.35 with multiply blending (ANN-004, DEC-107). The new value is chosen during implementation on real PDFs; loaded ink with opacity below 1 counts as highlighter (ASM-18)._
- **R-53a/b:** After changing tool, color, thickness or closing a popup, drawing works immediately. A tap that closes a popup never draws. Drawing only on the drawable PDF area. _V1: a stroke started on canvas grey is ignored (ANN-010)._

## 7. Slide construction, zoom, rendering
- **R-4b/c:** Annotation mode bottom bar (right side): aspect ratio increase/decrease (steps as V1), start value = device full screen ratio in current orientation. The PDF area is the largest area for that ratio, remaining strips dark gray (tunables). On change, briefly show highlighted rectangle and value. _V1 steps (SLD-013, DEC-044): range `T:aspectRatio.min` 0.5 to `max` 2.0, each press moves to the next multiple of 0.1 strictly below or above (1.78 → 1.7 / 1.8). V1 start value: the presentation viewport ratio captured at the first presentation entry per orientation, before that the screen ratio (SLD-014). ## 11. Open conflicts and questions
Each question names a recommendation (Rec). Q-1 to Q-4 existed before the V1 check; Q-5 onwards come from it.
1. **Q-1 File identity:** Cross-file marks, duplicate detection (R-30k) and per-file choices need one identity. V1 has no name/path identity: it uses platform references (web file handle, Android URI) with a name+size+last-modified fallback (FIL-002). Paths are not available on web or Android. Rec: identify documents by the pdf.js document fingerprint (already computed by pdf.js on load, no new dependency, survives renames and moves, changes when the content changes) for cross-file references, duplicate detection and per-file choices; keep the V1 references for access only. Caveat: two copies of the same PDF share a fingerprint, which is the wanted R-30k behavior; a file saved by the app keeps the original fingerprint only if pdf.js reads the original `/ID` (to verify).
2. **Q-2 Default values to choose:** stamp initial 8, active-area width, highlight colors/fade, tooltip max width, dead-time limits, highlighter opacity (R-52).
3. **Q-3** Native-speaker review plan for the six non-German languages.
4. **Q-4** Price and Impressum/tax details at release.
5. **Q-5 Save after detection vs. overwrite confirmation:** V1 saves automatically when detection finishes on a writable file (SAV-012), so a new file would ask "Overwrite?" right after opening, before the user changed anything. Rec: the detection result alone does not trigger a save or the dialog; it is saved with the first user change (or never, if there is none, and detection reruns next time).
6. **Q-6 Closing with unsaved changes in free/web:** every close drops in-session changes. Rec: no confirmation (consistent with "read-only", the modified marker is the indicator, R-1d); alternative: one confirmation per close.
7. **Q-7 Permission re-grant on web:** without IndexedDB (R-8b) Chromium cannot keep file handles, so session restore and "needs re-open" (FIL-011/013) disappear on web. Rec: accept; web starts empty every time.
8. **Q-8 Cross-file marks on web and after restart:** referenced files can open automatically only where the app may keep file access (Android persisted URI permissions, iOS bookmarks). On web (no persistence) and for files never opened on this device, they cannot. Rec: cross-file marks are paid-native; the warning of R-30g applies otherwise.
9. **Q-9 Service-worker cache vs. R-8b:** offline use of the web app (PLT-009) needs Cache Storage of the app's own files. Rec: allowed (contains no user data); R-8b covers cookies, localStorage, sessionStorage and IndexedDB.
10. **Q-10 Pass number:** V1 jumps have a pass number (which arrival at the start fires the jump, ORG-016, PLY-003); V2 does not mention it. Rec: keep it, with the V1 default (number of existing jumps from the same start + 1) and the stepper, shown in the label ("5 → 2 ×2").
11. **Q-11 Slide breaks:** V1 has slide breaks (ORG-022); the V2 tool list has none, but R-60 refers to "fixed breaks". Rec: keep as a tool (right end of a system, like stop).
12. **Q-12 Labels and system numbers:** V2 labels marks by page; V1 shows playing-order numbers on systems and in labels (DEC-102). Rec: marks use page labels as specified; "number systems" (R-19j) shows the playing-order numbers as in V1 (the only per-system number V1 has); print-order numbers are not added.
13. **Q-13 Start mark semantics:** V1 always starts at junction 0. Rec: the playing order starts at the start mark (at most one per file; the last one set wins); systems before it are not played; this changes PLY-002 and needs a new `schemaVersion` together with bookmarks and labels.
14. **Q-14 Marks list:** which modes (V1: organization only), and order: V1 orders by playing order, V2 says reading order. Rec: available in organization and annotation mode; reading order (print order of the start position), which stays stable while jumps change; in annotation mode a tap goes to the slide with that system.
15. **Q-15 Detection popup parameters:** V1 has no max width and no min/max height. Rec: the popup shows the parameters V1 really has: min system width, full-width threshold, resolution (dpi); add min/max height only if the real-PDF corpus shows a need.
16. **Q-16 Background detection on Android/iOS:** continuing needs a native Android foreground service (new native plugin and a notification) and is not possible on iOS. Rec: web: continue (tunable change); Android/iOS: pause in the background and resume on return (as V1), recorded as a platform limit; revisit if real use shows long waits.
17. **Q-17 Finger drawing after a stylus:** removing the finger-drawing toggle (#56) means fingers never draw on a device that has seen a stylus. Rec: keep the toggle in the pen popup (it is not a toolbar button), or clear `stylusSeen` with "Reset all settings".
18. **Q-18 Per-PDF aspect-ratio override:** V1 stores a ratio per file and orientation (SLD-015); R-60 says "user setting, per app". Rec: drop the per-PDF override (simpler, fewer writes; read-only migration ignores stored overrides).
19. **Q-19 Page scroll bar:** V1 hides page scrolling (`overflow: hidden` on html and body). Which scroll bar do you see (browser, OS, mode)? A screenshot settles it.
20. **Q-20 Recent files:** V1 has a recent-files list on the open control (FIL-008); V2 does not mention it. Rec: keep it in paid native (long press on "+"), off in free/web (R-22d).
21. **Q-21 Music symbols for stamps:** Material Symbols has no dynamics, accidentals or segno/coda glyphs. Rec: a free music font with a license fitting closed source (e.g. Bravura, SIL OFL) as a new dependency recorded in `decisions.md`, or hand-drawn SVGs.
22. **Q-22 Synthetic test PDFs:** R-14a replaces dummy data with real PDFs. Rec: keep the few synthetic fixtures that test failure cases real PDFs cannot cover (damaged, zero pages, blank page); replace the synthetic scores and the generated 120-page reference with real PDFs.
23. **Q-23 Real emulators:** R-11a lists device kinds; V1 covers them with Playwright profiles. Rec: Playwright profiles plus a small-phone profile; one Android emulator smoke job (open, detect, draw, save) before releases only.
