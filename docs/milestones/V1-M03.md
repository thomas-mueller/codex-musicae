# V1-M3 — Capacitor, Android shell, App Distribution

**Tag at the end:** `v0.3.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M2 done.

**Requirements:** GEN-002, PLT-002, PIP-003, PIP-006.

Goal: the web app runs as an Android app (APK), built and signed by a pipeline and delivered to testers through Firebase App Distribution.

## Owner prerequisites (before the agent starts)

1. **Tools on the Ubuntu PC:** Android Studio (includes the SDK, platform tools and an emulator), and the JDK version required by the Capacitor major version the agent will install (see the Capacitor Android docs; Android Studio's bundled JDK is usually fine).
2. **Release keystore** (keep it safe and backed up; the same key is needed for every update install):
   ```
   keytool -genkeypair -v -keystore codexmusicae.jks -keyalg RSA -keysize 2048 -validity 10000 -alias codexmusicae
   base64 -w0 codexmusicae.jks > codexmusicae.jks.base64
   ```
   Never commit the keystore or the base64 file.
3. **Firebase:** register an Android app in the Firebase project with package name `app.web.codexmusicae`; copy the app ID (`1:…:android:…`). Confirm the tester group exists in App Distribution.
4. **GitHub:** set `ANDROID_KEYSTORE_BASE64` (content of the base64 file), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD` as secrets and `ANDROID_KEY_ALIAS`, `FIREBASE_ANDROID_APP_ID`, `FIREBASE_TESTER_GROUPS` as variables (names in `V1-M00.md`). Tell the agent when this is done; it must not ask for or print secret values.

## Steps (commit after each)

### S1 — Capacitor and Android project (GEN-002, PLT-002)

1. Install `@capacitor/core`, `@capacitor/cli`, `@capacitor/android`. Create `capacitor.config.ts`: `appName` and `appId` imported from `src/config/tunables.ts` (`identity`), `webDir` = the Angular build output (`dist/codexmusicae/browser`), `server.androidScheme: 'https'`, no remote `server.url`.
2. `npx cap add android`; commit the `android/` folder (generated `.gitignore` respected).
3. Set `minSdkVersion` to 29 in the single place Capacitor uses (`android/variables.gradle`); `targetSdkVersion`/`compileSdkVersion` as generated by the installed Capacitor version.
4. Gradle reads `versionName` from env `APP_VERSION_NAME` and `versionCode` from env `APP_VERSION_CODE` (defaults for local builds: `0.0.0-local` and `1`).
5. Release signing: `signingConfigs.release` reads keystore path, store password, alias and key password from env vars; if they are absent the release build is unsigned (local debug builds still work).
6. Placeholder launcher icon and splash screen (simple generated assets; replaceable later, for example with `@capacitor/assets`).
7. npm scripts: `cap:sync` (build web + `npx cap sync android`), `android:debug` (assembleDebug).

### S2 — Composition-root guard

The service worker (M2) must not register inside the native app. Add the platform check (`Capacitor.isNativePlatform()`) in the composition root only. Add a unit test that registration is skipped when the check returns true (use a fake).

### S3 — Android pipeline (PIP-003, PIP-006)

Workflow `.github/workflows/android.yml`, name `android`:
- Trigger: `workflow_run` on `lint-test`, completed, branch `main`; job runs only if the conclusion is `success`.
- Steps: checkout `ref: ${{ github.event.workflow_run.head_sha }}` with `fetch-depth: 0`; composite action `build-web`; setup JDK (version required by the installed Capacitor); setup Android SDK if the runner lacks it; `npx cap sync android`.
- Version: `APP_VERSION_NAME` = `git describe --tags --always --long` (strip the leading `v` if Gradle needs it); `APP_VERSION_CODE` = `git rev-list --count HEAD`.
- Decode `ANDROID_KEYSTORE_BASE64` to a file in the runner temp directory, export the keystore env vars, run `./gradlew assembleRelease` in `android/`.
- Upload the signed APK to Firebase App Distribution (Firebase CLI `appdistribution:distribute` or a maintained action) with `FIREBASE_ANDROID_APP_ID`, groups from `FIREBASE_TESTER_GROUPS`, credentials from `FIREBASE_SERVICE_ACCOUNT_CODEX_MUSICAE`, release notes = version string + commit subject.
- Never print secrets; delete the decoded keystore at the end.
- Optional: also upload the APK as a workflow artifact.

## Tests and checks

- Unit: the platform guard test from S2.
- CI: the `android` job builds a signed APK on a push to `main`; the APK's `versionName`/`versionCode` match the computed values (a script step using `aapt2` or `apkanalyzer` asserts it).
- Manual (owner): install the APK from the App Distribution link on a real tablet or emulator; the app opens and shows the placeholder (no visible text); the app works without network.

## Do not

- Do not add iOS (M18), any Capacitor plugin beyond core and android, or native code.
- Do not use a remote `server.url` or enable cleartext traffic.
- Do not build an AAB or touch Google Play.
- Do not change the web pipeline or the `lint-test` workflow except where this milestone says so.
- Do not commit the keystore, passwords, service-account files or Firebase config containing secrets.

## Acceptance criteria

- [x] `npm run cap:sync` and `npm run android:debug` work locally.
- [x] On push to `main` (after `lint-test`), `android` produces a signed APK and delivers it to the tester group.
- [x] The APK has package `app.web.codexmusicae`, `minSdk` 29, and the expected version values.
- [x] No service worker registers in the native app (test proves the guard).
- [x] Requirement statuses updated; `AGENTS.md` "Commands" lists the Android scripts.
