# V1-M2 — Versioning and PWA

**Tag at the end:** `v0.2.0`. **Model:** smallest tier that works, low effort. **Prerequisite:** M1 done.

**Requirements:** PIP-005, PIP-009, PLT-009.

Goal: every build knows its exact version (tag + commits since + SHA) and the web app is an installable, offline-capable PWA whose updates never interrupt use.

## Steps (the owner commits after each)

### S1 — Version string (PIP-005, PIP-009)

Contract (put it in `src/app/core/version/`, pure):

```ts
export interface ParsedVersion {
  raw: string;            // e.g. "v0.5.0-12-g3f2a9c1"
  tag: string | null;     // "v0.5.0" or null when no tag exists
  commitsSinceTag: number | null;
  sha: string | null;     // without the leading "g"
  dirty: boolean;
}
export function parseGitDescribe(raw: string): ParsedVersion;
```

Test table (write these tests first; names contain `PIP-005`):

| Input | tag | commitsSinceTag | sha | dirty |
|---|---|---|---|---|
| `v0.5.0-12-g3f2a9c1` | `v0.5.0` | 12 | `3f2a9c1` | false |
| `v0.5.0-0-g3f2a9c1` | `v0.5.0` | 0 | `3f2a9c1` | false |
| `v0.5.0-12-g3f2a9c1-dirty` | `v0.5.0` | 12 | `3f2a9c1` | true |
| `3f2a9c1` (no tag, `--always`) | null | null | `3f2a9c1` | false |
| `` (empty) | null | null | null | false |

Tasks:
1. Script `scripts/generate-version.mjs`: runs `git describe --tags --always --long --dirty`, writes `src/config/version.generated.ts` exporting `APP_VERSION_RAW`. If git is unavailable, write `unknown`. The generated file is git-ignored. Run it as a `prebuild`/`prestart`/`pretest` step so every build has it.
2. Provide the version through an injection token `APP_VERSION` (composition root). The UI display comes in M7; do not expose the version globally (no `window` property). Add a unit test that the token resolves.
3. Every workflow checkout that builds uses `fetch-depth: 0` (the composite action and `lint-test`); verify they already do.
4. Document in `AGENTS.md` ("Naming and versions") how to read the version.

### S2 — PWA and update policy (PLT-009)

1. Add the Angular service worker (`ng add @angular/pwa`, or equivalent manual setup). Manifest: `name` and `short_name` from `T:identity.appName`, `display: standalone`, `background_color` and `theme_color` = `T:colors.canvasGrey`, `start_url: "./"`, placeholder icons (192, 512, maskable) — generate simple placeholders; they are replaceable later. **Do not** add `file_handlers` (that is M16).
2. `ngsw-config.json`: prefetch all app assets (app shell, i18n, icons). Leave room for large lazy assets (OpenCV.js in M10) via a `lazy` asset group with `prefetch`.
3. Register the service worker only in production builds and only on the web: skip registration when running inside Capacitor (the check lives in the composition root; native bundles ship their assets).
4. Update policy: the app may check for updates at startup but **never** calls `activateUpdate()`, never reloads the page and never shows a blocking prompt. A new version is used at the next app start.
5. Add a short section "Update policy" to `docs/decisions.md` (new `DEC-071`).

## Tests

- Unit: the `parseGitDescribe` table above; a test that the update service never calls `activateUpdate` or `location.reload` (spy on a fake `SwUpdate`).
- E2E (Chromium only; WebKit and Firefox skip with a note): production build served statically; open the page; wait until the service worker is active; set the context offline; reload; the page still loads (`PLT-009`).
- Manual (owner): deploy a second build; an already open tab keeps running the old version until reloaded.

## Do not

- Do not add Capacitor, a push-notification feature or any runtime caching of PDF data.
- Do not show or design the version in the UI (M7).
- Do not change pipelines beyond the `fetch-depth` check.
- Do not call `skipWaiting` or force a reload.

## Acceptance criteria

- [x] `parseGitDescribe` tests pass; the generated version is correct after a local build with a tag present.
- [x] The deployed web app is installable (manifest valid) and loads offline after the first visit in Chromium E2E.
- [x] No code path activates an update or reloads automatically (test proves it).
- [x] Requirement statuses updated; `AGENTS.md` mentions the version mechanism.

## Owner step

Review, merge, check the deploy and the install prompt in Chrome, then `git tag v0.2.0 && git push --tags`.
