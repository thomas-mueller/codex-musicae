# V1-M8 — Files, tabs, PDF renderer, cache, scheduler

**Tag at the end:** `v0.8.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M7 done; M4 ports are in `src/app/ports/`.

**Requirements:** FIL-001, FIL-002, FIL-003, FIL-004, FIL-005, FIL-008, FIL-009, FIL-015, GEN-005, NFR-003, NFR-004, NFR-005, NFR-006, NFR-008, NFR-009, NFR-010.

Goal: open local PDFs into tabs, render pages through a bounded cache, schedule work by priority, remember recent files. No organization viewer yet: after opening, the canvas shows page 1 at fit-width as a temporary preview (removed in M9).

## Steps (the owner commits after each)

### S1 — Core: cache and scheduler (NFR-003, NFR-004, NFR-009, NFR-010)

Copy `docs/contracts/core/lru-cache.ts`, `scheduler.ts` and their fixtures into `src/app/core/`; write specs from the fixtures first (red, `not implemented`), then implement. Hints:

- `LruByteCache`: a `Map<string, {value, bytes}>` whose insertion order is the recency order (delete + set on `get`/`set` moves to the end). `onRemove` is called for **every** value that leaves, in order, with the reason. Replacing a key: remove the old with `'replaced'` first. A value larger than the budget: call `onRemove(key, value, 'rejected')`, store nothing.
- `pickNext`: filter eligible tasks by the rules in the doc comment, sort by `TASK_PRIORITY` then `seq`, take the first.

### S2 — Test PDFs and the pdf.js adapter (FIL-009, NFR-005, NFR-006, NFR-008, GEN-005)

1. Dev dependency `pdf-lib`. Script `scripts/make-test-pdfs.mjs` generates into `e2e/fixtures/` (committed):
   - `synthetic-score.pdf`: 3 pages A4 (595×842 pt), each with **4 systems**; a system = 2 staves of 5 horizontal lines (x from 50 to 545, line spacing 5 pt, staves 40 pt apart) joined by a vertical barline at both ends and 3 inner barlines, plus a few small filled rectangles as noteheads; systems at y = 100, 280, 460, 640 (from top). A title text on page 1 above the first system.
   - `damaged.pdf`: 2 kB of fixed pseudo-random bytes (a deterministic string, not random at run time).
   The generator is deterministic (same bytes every run).
2. Install `pdfjs-dist`; copy its worker file into the build assets (angular.json `assets`); set `GlobalWorkerOptions.workerSrc` to that local path. No CDN (GEN-005).
3. `adapters/pdfjs/PdfJsRenderer implements PdfRenderer` (see `ports/pdf-renderer.ts`):
   - `open(bytes)`: `getDocument({ data })`; map `PasswordException` → `'encrypted'`, `InvalidPDFException`/others → `'invalid'`, `numPages === 0` → `'empty'`. Never throw out of the port.
   - `getPageInfo(i)`: `page.view` and `page.rotate` → `PageBox`; display size = `page.getViewport({ scale: 1 })` width/height.
   - `renderRegion({ pageIndex, region, scale }, signal)`: canvas (`OffscreenCanvas` where available, else a detached `<canvas>`) of `ceil(region.width*scale) × ceil(region.height*scale)`; viewport `getViewport({ scale, offsetX: -region.x*scale, offsetY: -region.y*scale })`; render; `createImageBitmap(canvas)`. On `signal.abort` cancel the render task and return `err('cancelled')`. Check the pixel count against `T:resources.maxCanvasPixels` before allocating: if exceeded return `err('out-of-memory')` (the caller lowers the scale via `fitScaleToPixelCap`). Map allocation failures to `'out-of-memory'`.
4. Adapter unit tests with a fake pdf.js module for the error mapping (`encrypted`, `invalid`, `empty`). E2E (Chromium): render a region of `synthetic-score.pdf` and assert the bitmap has dark pixels; render of `damaged.pdf` gives the `invalid` error state.

### S3 — File access and preferences adapters (FIL-001, FIL-002, FIL-008, FIL-015)

1. `adapters/web/WebPreferences implements Preferences`: `localStorage`, keys prefixed with `T:persistence.keyPrefix`, JSON values; read/write errors are swallowed (return `undefined`).
2. `adapters/web/WebFileAccess implements FileAccess`:
   - `pickPdfs()`: if `showOpenFilePicker` exists (Chromium) use it with `multiple: true` and the PDF type filter and store each handle in IndexedDB (database `cm-files`, store `handles`, key = generated `FileRef.id`); otherwise a hidden `<input type="file" multiple accept="application/pdf">` (no handle stored; `writable: false`).
   - `reopen(ref)`: load the handle from IndexedDB; `queryPermission({mode:'readwrite'})`; if `'prompt'` call `requestPermission` (works inside a user gesture, else return `err('needs-user-gesture')`); read the file. Missing handle → `err('not-found')`; denied → `err('denied')`.
   - `isSame(a, b)`: both handles → `a.isSameEntry(b)`; else equal name, size and lastModified.
   - `forget(ref)`: delete the handle. `write` and `saveCopy`: return `err('unsupported')` for now (M15).
   - File refs and handles never include PDF bytes (FIL-015).
3. Register both adapters in the composition root. The Capacitor implementations come in M16.
4. Tests: adapter unit tests with fake `indexedDB`/handles for `isSame`, `reopen` outcomes; E2E uses `page.addInitScript(() => { delete window.showOpenFilePicker; })` to force the `<input>` path and `setInputFiles`.

### S4 — Stores and resource governor (FIL-005, NFR-003, NFR-004, NFR-009, NFR-010)

- `PreferencesStore` (`state/`): signals for `recentFiles` (list of `FileRef`, max `T:resources.recentFilesMax`, newest first, no duplicates by `isSame`), persisted through the `Preferences` port under keys `recent`.
- `SessionStore`: `tabs` (signal list of `Tab { id, ref, name, status }`), `activeTabId`, `openFiles(files)` (applies FIL-002: if `isSame` with an open tab → focus it), `closeTab(id)` (selects the neighbor), `setActive(id)`.
- `DocumentStore` (one per tab; created lazily): `handle` (`PdfDocumentHandle | null`), `pageInfos`, `status` (`'loading' | 'ready' | 'error'`), `errorCode`. Per-tab state kept when switching (FIL-005): later milestones add position, zoom, marks.
- `BitmapCache` service: `LruByteCache<ImageBitmap>` with `onRemove` → `bitmap.close()`; budget from `navigator.deviceMemory` using `T:resources.cacheBudgetByDeviceMemoryGb` (nearest lower bucket; default `T:resources.cacheBudgetDefaultBytes`); one cache per tab key prefix; `releaseTab(id)` clears that tab's entries (NFR-009).
- `Scheduler` service: wraps `pickNext`/`tasksToCancel`; every task has an `AbortController`; `submit(cls, fn)` returns a promise; running low-priority tasks are aborted when a visible/input task arrives; stale render tasks are aborted when their view key changes (NFR-008). Concurrency: 1 running `visible` render at a time plus at most 1 of each lower class.
- `ResourceGovernor` (`state/`): signal `level` 0…3. `reportFailure()` (allocation failure or cache over budget after eviction) raises the level by one, at most once per `T:resources.governorEscalateCooldownMs`; after `T:resources.governorRecoverMs` without failures it steps down by one. Effects exposed as computed signals: `prefetchNeighbors` (0 at level ≥ 1, else `T:resources.prefetchNeighbors`), `renderScaleFactor` (`T:resources.governorLowResFactor` at level ≥ 2, else 1), and at level 3 `SessionStore` releases the bitmaps of all inactive tabs. Unit-test the level transitions with a fake clock.
- Render helper `renderRegionCached(doc, request)`: key `${tabId}|${page}|${x}|${y}|${w}|${h}|${scale}`; cap `scale` with `fitScaleToPixelCap` and the device pixel ratio with `T:resources.devicePixelRatioCap`; on `'out-of-memory'` call `governor.reportFailure()` and retry once at the capped smaller scale.

### S5 — UI: opening, tabs, recents, preview (FIL-001, FIL-003, FIL-004, FIL-008, FIL-009)

- `openFile` button: tap → `FileAccess.pickPdfs()` → `SessionStore.openFiles`; long press (or a small chevron next to it) → `RecentFiles` popup listing `recentFiles` (file names); choosing one calls `reopen(ref)`; on `'not-found'`/`'denied'`/`'needs-user-gesture'` after the tap, offer the picker instead (a second tap).
- `TabBar` (expanded) and `TabSwitcher` (compact): tabs show file name, a close icon and a status marker: `error` icon if `status === 'error'` (tooltip from the error code). Markers for unsaved/lock/needs-re-open are rendered when the corresponding store field is set (set by later milestones); implement the marker slot and the three icons now. Compact: one button with the current name opening a sheet list of all tabs.
- Opening runs `PdfRenderer.open`; on error the tab exists in error state (FIL-009); no crash.
- Temporary `PagePreview` in the canvas area: renders page 1 at fit-width into a canvas via `renderRegionCached` through the scheduler (class `visible`). Mark the component `// TEMPORARY(M9): replaced by OrganizationViewer`.
- Controls that need a document become enabled when the active tab has `status === 'ready'`.

## Tests

- Unit: S1 specs; stores (`SessionStore` dedupe, close selects neighbor, recent-list ordering and max); governor transitions; render helper retry with a fake renderer.
- E2E (three engines, input path): open `synthetic-score.pdf` → a tab with the name appears, page preview non-blank; open the same file again → still one tab (FIL-002); open two files → two tabs; open `damaged.pdf` → tab with error marker, app responsive; close tabs; recent list shows files; in compact viewport the tab switcher lists tabs.
- Resource E2E (Chromium): open a PDF repeatedly and confirm via a debug hook (`window.__cm` available only when `ngDevMode`) that the cache never exceeds its budget. No production debug hooks.

## Do not

- Do not build the organization viewer, detection, slides or saving (`write` stays unsupported).
- Do not store PDF bytes or PDF-derived data anywhere persistent (FIL-015, GEN-005).
- Do not add runtime network requests; do not use a CDN for pdf.js.
- Do not change the ports' signatures. If one is insufficient, write the problem to `docs/questions.md` and stop.
