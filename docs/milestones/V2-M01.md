# V2-M1 — Pipeline and quality gates

**Tag at the end:** `v1.1.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M0 done.

**Requirements:** R-44a, R-15a/b, R-14c, #49, R-8d, R-11a (profiles), R-16a…f, R-12c (and their `TOPIC-nnn` from M0).

**Requirement IDs:** NFR-017, NFR-018, NFR-019, ARC-007, ARC-008, PIP-011, PIP-012, PIP-013, PIP-014, PIP-015, PIP-016, PIP-017, PIP-018, PIP-019, PIP-020, TST-009.

Goal: the checks every later milestone relies on exist before features arrive: fast CI on every push, heavy tests on demand, coverage per kind of test, automated checks for unused code, unused dependencies and licenses, a test that no request leaves the app, a small-phone profile, a clean user-visible version, and a self-explanatory tunables file.

## Steps (the owner commits after each)

### S1 — Workflows (R-44a)

1. All workflows get `workflow_dispatch` (`lint-test`, `e2e`, `deploy-web`, `android`, `ios`).
2. `lint-test` (lint, lint self-test, unit tests, build) stays on every branch push. `e2e` no longer runs on every push: it runs on pull requests to `main`, on tags `v*` and manually. `android` and `ios` keep their current triggers; their later release-only jobs are added in M17.
3. Document the trigger table at the top of `docs/android-ci.md` (or a new `docs/ci.md`; update `docs/README.md`).

### S2 — Static checks (R-14c, #49)

1. Add checks to the `lint-test` job and to `npm run lint` (as scripts under `scripts/`, with a self-test case each in `scripts/lint-selftest.mjs`):
   - unused exports/files: use an existing tool already in the dependency tree if one fits; otherwise a small script. Any new dev dependency is named in `docs/decisions.md` first.
   - unused dependencies in `package.json`.
   - license check: every production dependency has a license from an allow-list in `tunables`-style config (e.g. MIT, Apache-2.0, BSD, ISC, SIL OFL); GPL/AGPL fail the check. Output a table to the job log; keep `THIRD_PARTY_NOTICES.txt` generation as is.
2. Existing findings: fix real ones; list intentional exceptions in an allow-list with a reason (`docs/traceability-exceptions.md` style).

### S3 — Runtime request test (R-8d)

Playwright test (Chromium, Firefox, WebKit): start the built app, open a PDF, run detection, switch modes, draw, save a copy; record all requests (`page.on('request')`); fail on any request whose origin is not the app's own origin (and `data:`/`blob:`). The test runs against the production build in the `e2e` workflow.

### S4 — Profiles, coverage, version, tunables (R-11a, R-15, R-16, R-12c)

1. `playwright.config.ts`: add a small Android phone profile (viewport about 360×640, Chromium and Firefox) next to Pixel 7 and Galaxy Tab S9; the `@smoke` subset runs on it.
2. Coverage: unit coverage report (Vitest, existing provider if present) and a combined table "per kind of test" (unit, integration, e2e, real-PDF detection, performance) printed in the job summary and uploaded as an artifact. **No failing threshold** (R-15b). A kind without a source of coverage numbers reports the number of tests instead and says so.
3. Version (R-16): extend `scripts/generate-version.mjs` so that the generated file contains `display` (`vX.Y.Z`, taken from the nearest tag; for tags of the scheme `v1.<n>.0` and `v2.x.y` it is that tag) and `full` (the describe string). `APP_VERSION` exposes both; the info popover shows only `display`; internal places (build log, `window` debug hook in dev builds) may show `full`. Android `versionName` = `X.Y.Z` without `v` and without the describe suffix; `versionCode` stays the commit count. A build check fails when web, Android and iOS versions disagree.
4. `src/config/tunables.ts`: every value gets a comment with unit and meaning; add a small lint check that fails when a numeric value lacks a comment on its line or the line above (allow-list for obvious ones).

## Tests

- Unit: version display parsing (`v1.5.0-3-gabc1234-dirty` → `v1.5.0`; `v2.0.0` → `v2.0.0`; no tag → `v0.0.0`), license allow-list logic, tunables-comment check, all with the requirement ID in the name.
- Lint self-test: each new check has a failing example.
- E2E: external-request test; small-phone smoke.

## Do not

- Do not add production dependencies; dev dependencies only where named in `docs/decisions.md`.
- Do not set a coverage threshold.
- Do not change application behavior.
- Do not edit existing tests (except adding the profile to the project list).

## Acceptance criteria

- [x] All workflows manually triggerable; `e2e` not on every branch push.
- [x] Unused-code, unused-dependency and license checks run in `lint-test` and fail on a seeded example.
- [ ] Request test green on all three engines.
- [ ] Small-phone profile exists and its smoke subset passes.
- [ ] Coverage table appears in the job summary.
- [ ] Info popover shows `vX.Y.Z` only; Android/iOS/web versions are checked for consistency.
- [ ] Every tunable has a unit/meaning comment.
- [ ] Requirement statuses updated; `npm run lint`, `npm test -- --watch=false` and `npm run build` green.

## Owner step

Review, commit, then `git tag v1.1.0 && git push --tags`.
