# V2-M15 — Send to (export)

**Tag at the end:** `v1.15.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M3, M10, M12 done.

**Requirements:** R-21a…g, R-22a/b (disabled in free).

**Requirement IDs:** EXP-001, EXP-002, EXP-003, EXP-004, EXP-005, EXP-006, EXP-007.

Goal: the paid native app can produce one flattened PDF and hand it to another app or save it as a copy. Printing does not exist. The original and the working file are never changed by export.

## Steps (the owner commits after each)

### S1 — Flattened document (R-21a, d, f, g)

1. `core/` plan + `adapters/pdflib` writer: build **one PDF** from the open file in which ink, text and stamps are flattened as standard page content (no editable annotations required, R-21f) and the marks are written into the file metadata (M4 schema, so another copy of this app can read them). Foreign annotations of other apps are preserved as in V1 (SAV-013), unless flattened content already contains them.
2. The working file (autosaved, editable data) and the exported copy are distinct; export never touches the original file or its autosave state (R-21g).
3. Large files: export runs off the main thread where the library allows (scheduler class `saving`), shows progress as an icon, and releases memory afterwards.

### S2 — Delivery (R-21b/c/e)

1. New port `SendFile` (token `SEND_FILE`) in `ports/` with adapters: Capacitor share sheet (Android, iOS) and a "save as local copy" path (existing safe-write code of V1). There is no web adapter: the web build does not provide the token, features inject it as optional, and the button stays visible but disabled through the `sendTo` switch (desktop browsers behave like free: no download).
2. "Send to" button (icon only, tooltip from translations): in the expanded layout a top-bar button next to the settings button, in the compact layout an entry of the bottom-bar More menu, which this milestone then shows in every mode (since V2-M6 it shows in annotation mode only, UIX-036; there is no "save a copy" button any more, DEC-167); behind the `sendTo` switch from M3: paid native on, free and web visible but disabled.
3. File name of the copy: original name plus a fixed suffix from tunables; the user can change it in the system dialog.
4. Errors cross the port as typed results (UI shows an icon).

### S3 — iOS note

The iOS share path is marked `UNVERIFIED(ios)` and added to `docs/ios-unverified.md` for M17.

## Tests

- Unit: flatten plan fixtures (page boxes, rotated pages, annotations on several pages), metadata embedding round trip.
- E2E (paid-native web build with a mocked share adapter): export produces a PDF that pdf-lib and pdf.js open; strokes, text and stamps appear in the rendered pixels; metadata parses and contains the marks; the original file bytes are unchanged; free build: button disabled, no adapter call.
- Manual (owner): share to another app on Android; print is not offered.

## Do not

- Do not add printing, export of single pages or other formats.
- Do not make the exported ink editable.
- Do not add a web download path.
- Do not add dependencies.

## Acceptance criteria

- [ ] Export produces one valid PDF with flattened content and embedded marks.
- [ ] Original and working file unchanged.
- [ ] Share sheet on Android works; free/web visible and disabled.
- [ ] Requirement statuses updated; lint, unit tests, E2E, build green.
