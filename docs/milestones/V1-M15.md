# V1-M15 — Saving into the PDF

**Tag at the end:** `v0.15.0`. **Model:** mid-tier, medium effort; plan step with the strong model recommended; escalate to strong for pdf-lib/PDF-structure bugs. **Prerequisite:** M14 done.

**Requirements:** SAV-001, SAV-002, SAV-003, SAV-004, SAV-005, SAV-006, SAV-008, SAV-009, SAV-010, SAV-011, SAV-012, SAV-013, SAV-014, ANN-005, FIL-006, FIL-010, FIL-016, FIL-017, DET-023, NFR-013, PLT-010.

Goal: everything the user creates (ink, jumps, breaks, stops, aspect ratios, detection results) is written back into the same PDF, safely and without blocking the UI; files that cannot be written offer "save a copy"; existing data is read when a PDF opens.

## Core part (first)

Copy `docs/contracts/core/metadata.ts`, `autosave.ts` and `fixtures/metadata.cases.ts`, `fixtures/autosave.cases.ts` into `src/app/core/`; write the specs first (red), then implement exactly the doc comments:

- `parseMetadata`: the check order and the reasons are in the doc comment and in the 20 `parseCases` (path strings like `marks.jumps[0].pass`); `schemaVersion > CURRENT_SCHEMA_VERSION` → `newer` before any other field check.
- `reconcileMetadata`, `reduceSave`, `saveDecision`: as documented; the autosave fixtures are step sequences (events and checks).

## Steps (the owner commits after each)

### S1 — Metadata and autosave in the stores (SAV-002…005, SAV-008, FIL-010)

- `DocumentStore.buildMetadata()`: assembles `EmbeddedMetadata` from state: `appVersion` = `APP_VERSION` raw string, `pageCount`, `detection` = `{level, pages}` for the **active, complete** run (pages with state `done` or `failed`, systems in display space) else `null`, `marks` from `DocMarks` (`jumps` → `{id, origin, target, pass}`), `aspectRatio` from the per-PDF overrides (`portrait`/`landscape`).
- `hydrateFromMetadata(meta)`: sets marks, ratio overrides, and (if `detection !== null`) a completed `DetectionRun` with the stored pages and level (no detection runs: DET-023).
- `SaveService` (`state/`, one per tab): holds a `SaveState`, feeds it with `reduceSave` from: the document's `changes` stream (strokes), marks edits, ratio overrides, detection completion, `AppLifecycle.onPause`, tab switch/close (`force`); evaluates `saveDecision(state, now, T:saving.autosaveIdleMs)` after every event; `wait` arms one timer (cancel/re-arm on every event), `save` starts a save. Exposes signals `dirty`, `saving`, `failed` for the tab markers: unsaved dot while `dirty` (and not failed), error icon while `failed`, lock icon when read-only.

### S2 — The pdf-lib writer (SAV-001, SAV-006, SAV-010, SAV-013, ANN-005)

`adapters/pdflib/PdfLibWriter implements PdfWriter` inside a worker (Comlink; `apply` honors `AbortSignal` between steps). You may refine `ports/pdf-writer.ts` (it is provisional): write any change to `docs/contracts/ports/pdf-writer.ts` and `docs/changelog.md`. Behavior:

**`listInk(bytes)`:** load with pdf-lib; for each page read `/Annots`; keep annotations with `/Subtype /Ink`. For each: points = all numbers of `/InkList` sub-arrays concatenated into `{x,y}` pairs; `color` from `/C` (1 value gray, 3 RGB, 4 CMYK → hex; missing → `#000000`); `widthPt` from `/BS /W`, else `/Border[2]`, else 1; `opacity` from `/CA` (default 1); `multiply = opacity < 1`; `strokeId` = `/NM` (string) or null; `annotationRef` = `nm:<NM>` if `/NM` present else `obj:<objectNumber>`. Encrypted file → `err('invalid-pdf')`.

**`readEmbeddedJson(bytes)`:** walk the catalog `/Names /EmbeddedFiles` name tree (flat `/Names` arrays and `/Kids`), find the key `T:saving.metadataFileName`, decode the filespec's `/EF /F` stream as UTF-8; none → `ok(null)`.

**`apply(bytes, edits, signal)`:**
1. Remove ink: for each `removeInk` entry find the annotation (`nm:` by `/NM`, `obj:` by object number) in that page's `/Annots`, remove it from the array and delete its objects from the context.
2. Add ink: for each `addInk`: an appearance stream (Form XObject) and an annotation dictionary.
   - Content stream: `q`, stroke color `r g b RG` (0…1), `w w`, `1 J 1 j`, `/GS gs` (only if `opacity < 1` or `multiply`), `x y m` then `x y l` for each further point (a single point is `x y m x y l`), `S`, `Q`.
   - `/GS` ExtGState: `/CA opacity /ca opacity /BM /Multiply` (or `/Normal`).
   - Form XObject: `/Type /XObject /Subtype /Form /BBox [minX-w/2-1, minY-w/2-1, maxX+w/2+1, maxY+w/2+1] /Resources << /ExtGState << /GS … >> >>`.
   - Annotation: `/Type /Annot /Subtype /Ink /Rect` (= the BBox) `/InkList [[x y x y …]] /C [r g b] /BS << /W w >> /CA opacity /NM (strokeId) /F 4 /T (CodexMusicae) /AP << /N <form> >>`; append to the page's `/Annots` (create the array if missing).
3. Embedded JSON (`embeddedJson !== null`): an `/EmbeddedFile` stream (`/Subtype /application#2Fjson`, `/Params << /Size n >>`) plus a `/Filespec` (`/F`, `/UF` = file name, `/EF << /F … >>`, `/AFRelationship /Data`, `/Desc`) registered in the catalog `/Names /EmbeddedFiles` name tree: a flat `/Names` array gets the entry inserted in key order or the existing entry with the same key replaced (old stream and filespec deleted); with `/Kids` replace in the leaf that holds the key, else append a new leaf with `/Limits` (LIM-024). `embeddedJson === null` leaves attachments untouched.
4. Everything else is preserved: other annotations, other attachments, form fields, metadata (SAV-013). Save with `useObjectStreams: false`. Return the complete bytes. Errors → typed (`invalid-pdf`, `out-of-memory`, `cancelled`, `unknown`).

Tests (Vitest/Node with pdf-lib, no browser): on `e2e/fixtures/synthetic-score.pdf`: add 2 ink strokes → re-load: annotation count, `/InkList` values, `/NM`, `/AP`, `/Rect`; `listInk` returns them with `nm:` refs; remove one by `nm:`; a PDF with a foreign ink annotation made by pdf-lib (no `/NM`): `listInk` gives `obj:` ref, removal works; a foreign `/Text` annotation and a foreign attachment survive an `apply`; embedded JSON: write, read back the identical text, write again → still exactly one entry with that name; tree with `/Kids` replaced in the leaf; a damaged file → `invalid-pdf`. When `qpdf` is installed, also run `qpdf --check` on every produced file (skipped with a warning locally if missing; the `lint-test` workflow installs it: `sudo apt-get install -y qpdf`).

### S3 — Save pipeline, triggers, safety (SAV-008…011, SAV-014, FIL-006, FIL-010, FIL-016, NFR-013, PLT-010)

- Per-tab **current bytes** (the bytes last read or written). `performSave()`:
  1. `reduceSave(saveStarted)`; collect edits: strokes in the model not yet saved → `addInk` (convert `InkStroke` to `InkToAdd`, same user-space points); strokes **removed** since the last save that came from the file or were saved earlier → `removeInk` with their refs (a stroke created and erased between saves needs no operation); `embeddedJson = serializeMetadata(buildMetadata())` unless the file's metadata was `newer` (then `null`: never overwrite, ink is still saved).
  2. `PdfWriter.apply(currentBytes, edits, signal)` through the scheduler class `save` (runs in the worker; never starts while a stroke is in progress: the scheduler context and `saveDecision` both know).
  3. `FileAccess.write(ref, newBytes)`. **Only after a successful write**: `currentBytes = newBytes`, mark the strokes saved (give them refs `nm:<id>`), `reduceSave(saveFinished ok)`.
  4. Any failure: keep all in-memory state, `reduceSave(saveFinished not ok)` → error icon; retry only on the next change or forced trigger (the state machine ensures this).
- **Triggers:** idle delay (state machine), `SessionStore.setActive` (force the tab being left), tab close (`closeTab` awaits the save; on failure the tab stays open with the error icon, FIL-006), `AppLifecycle.onPause`/hidden (force every dirty tab; do not await).
- **Read-only (FIL-016):** if the file was opened non-writable or `write` returns `denied`/`unsupported`: tab status `readOnly` (lock icon), no automatic saves; editing continues in memory; the overflow menu (three dots, entry `saveCopy`; enabled whenever a document is open, also for writable files) and a tap on the tab's lock icon offer **save a copy** (SAV-011, PLT-010): `FileAccess.saveCopy('<name> (annotated).pdf', bytes)` with bytes built by the same `apply` pipeline. Web download for Safari/Firefox; the Chromium in-place path writes through `FileSystemFileHandle.createWritable()` (the browser swaps the file at close, so a failed write leaves the original intact; implement `WebFileAccess.write`/`saveCopy` now: `showSaveFilePicker` when available, else an `<a download>` Blob).
- Android in-place writing arrives in M16.
- **Unsaved dot** shows while `dirty && !failed`, disappears after a successful save (FIL-010). Nothing blocks drawing: building and writing happen off the main thread except the final `FileAccess.write` call (chunk large writes where the platform allows).

### S4 — Reading existing data on open, renderer switch (SAV-005, SAV-012, SAV-014, DET-023, ANN-005)

On open, after the bytes are read and the document is ready:
1. `readEmbeddedJson` → `parseMetadata`: `ok` → `reconcileMetadata(meta, pageCount)`: non-null → `hydrateFromMetadata` (detection skipped when `detection !== null`); `null` or `invalid` → ignore the data and detect normally; `newer` → set `metadataNewer` (never overwritten) and detect normally.
2. `listInk(bytes)` → load all strokes into the model flagged `saved` with their refs; **at the same time** change `PdfJsRenderer.renderRegion` to pass `annotationMode: AnnotationMode.DISABLE` so pdf.js no longer draws ink (the app draws every stroke; nothing is drawn twice). Now the eraser also removes ink made by other apps (ANN-005).
3. SAV-012: when detection completes on a writable file whose embedded data had no detection, send a `change` to the `SaveService` so the next autosave embeds the results (a PDF that is only viewed is written once).
4. SAV-014: tab switches never lose unsaved in-memory ink (the per-tab stores persist while tabs are open); failed saves keep it.

## Do not

- Do not store PDF-derived data anywhere except in the PDF itself (FIL-015/DEC-030); do not add a backup or local cache of metadata.
- Do not write the file while a stroke is in progress; do not replace `currentBytes` before the write succeeded.
- Do not add Android write code (M16) or new features to the ink format (no text/shape annotations).
- Do not drop foreign annotations or attachments; do not change the metadata key order or schema without a new `schemaVersion` and migration.
