# V1-M10 — Detection: OpenCV worker, background processing, bars

**Tag at the end:** `v0.10.0`. **Model:** mid-tier, medium effort; plan step with the strong model recommended; escalate to strong on repeated failures (OpenCV/worker issues). **Prerequisite:** M9 done.

**Requirements:** DET-001, DET-002, DET-003, DET-004, DET-012, DET-013, DET-016, DET-017, DET-018, DET-019, DET-020, DET-021, DET-022, ORG-008, ORG-009, ORG-010, NFR-011, NFR-012. (DET-005…011 and DET-024 are the M5 functions this milestone calls.)

Goal: after opening a PDF, systems are detected page by page in the background without hindering the user; organization mode draws the bars; progress is visible; resources are respected. No jumps, breaks or stops yet (M11).

## Core part (first)

Copy `docs/contracts/core/detection-queue.ts` and `fixtures/detection-queue.cases.ts`; write the spec from the fixtures (red), implement:

- `usablePrefix`: count from index 0 while state is `'done'` or `'failed'`.
- `isComplete`: no `'pending'` and no `'running'`.
- `nextPageToProcess(states, priority)`: `priority` if in range and `'pending'`, else the lowest `'pending'` index, else `null`.
- `isProvisional(i, states)`: `states[i] === 'done' && i >= usablePrefix(states)`.

## Steps (the owner commits after each)

### S1 — OpenCV extraction in a worker (DET-002, DET-004, NFR-011, NFR-012)

1. Add OpenCV.js as a **self-hosted** asset: use an npm package that ships a browser build (for example `@techstark/opencv-js`) or the official `opencv.js` file; copy it to the build assets; record the choice and its license in `docs/decisions.md`. It must never be loaded from a CDN and never from the main bundle.
2. Add the worker entry `adapters/workers/detection.worker.ts` (Angular CLI web worker) and `adapters/opencv/OpenCvDetectionEngine implements DetectionEngine` (main-thread proxy, via Comlink; every call takes an `AbortSignal`: on abort, the worker task is flagged and its result discarded; the worker finishes the current OpenCV call but frees everything).
3. In the worker, load OpenCV lazily on the first call (`importScripts`/dynamic import of the local asset), then:

```
extractComponentsWith(cv, imageData, { blockSize, c }):     // pure function taking the cv object -> unit-testable with a fake
    mats = []
    try:
        src   = cv.matFromImageData(imageData);                    mats.push(src)
        gray  = new cv.Mat();  cv.cvtColor(src, gray, cv.COLOR_RGBA2GRAY);   mats.push(gray)
        bin   = new cv.Mat();  cv.adaptiveThreshold(gray, bin, 255, cv.ADAPTIVE_THRESH_MEAN_C, cv.THRESH_BINARY_INV, blockSize, c);   mats.push(bin)   // ink = 255
        labels = new cv.Mat(); stats = new cv.Mat(); cent = new cv.Mat()
        mats.push(labels, stats, cent)
        n = cv.connectedComponentsWithStats(bin, labels, stats, cent, 4, cv.CV_32S)
        components = for i in 1..n-1: { rect: { x: stats.intAt(i, LEFT), y: stats.intAt(i, TOP), width: stats.intAt(i, WIDTH), height: stats.intAt(i, HEIGHT) }, area: stats.intAt(i, AREA) }   // label 0 = background is skipped
        return { width: imageData.width, height: imageData.height, components }
    finally:
        for m in mats: m.delete()          // every Mat, also when an exception is thrown
```

(`LEFT`=0, `TOP`=1, `WIDTH`=2, `HEIGHT`=3, `AREA`=4 are the `cv.CC_STAT_*` columns.) Convert the `ImageBitmap` to `ImageData` through an `OffscreenCanvas` in the worker; close the bitmap afterwards.
4. Map errors: allocation failure/`RangeError` → `err('out-of-memory')`, abort → `err('cancelled')`, anything else → `err('unknown', message)`.
5. Service worker (M2): add the OpenCV asset to the `lazy` asset group with `prefetch` so the app works offline after the first load (NFR-012).

The engine port is `extractComponents(bitmap, signal, { blockSize, c })` and returns `{ width, height, components }`; `blockSize` and `c` come from the level (`T:detection.levels`).

Tests: unit test `extractComponentsWith` with a **fake `cv`** that records `Mat` creations and `delete()` calls: after a normal run and after a run where `connectedComponentsWithStats` throws, every created Mat was deleted exactly once (NFR-011). E2E (Chromium): the detection engine on the rendered page 1 of `synthetic-score.pdf` returns a component list that has no page-sized rectangle (the background is not reported) and contains 4 wide rectangles near the system positions (±3 px × scale).

### S2 — Detection service (DET-001, DET-003, DET-012, DET-013, DET-018, DET-020, DET-022)

`DetectionService` (`state/`) and `DetectionRun` (plain class/state object):

```
DetectionRun { level, states: PageState[], pages: (DetectedPage | null)[] }      // signals inside DocumentStore
start(doc): level = default level; states = all 'pending'; run starts automatically when the tab is ready and no valid
            embedded data exists (embedded data arrives in M15; until then always)
processPage(i):                                                      // runs as a scheduler task of class 'detection'
    info   = pageInfo(i)
    scale  = fitScaleToPixelCap(info.width, info.height, levels[level].renderScale * governor.renderScaleFactor, T:resources.maxCanvasPixels)
    bitmap = renderer.renderRegion({ pageIndex: i, region: (0,0,info.width,info.height), scale })       // closes after transfer
    set    = engine.extractComponents(bitmap, { blockSize, c } of the level)      // components in bitmap pixels + bitmap size
    systems = selectSystems(set.components, { width: set.width, height: set.height }, { width: info.width, height: info.height }, { minSystemWidthRatio, fullWidthSystemRatio } of the level)
    pages[i] = { pageIndex: i, width: info.width, height: info.height, systems }; states[i] = 'done'
on error 'out-of-memory' or 'unknown': retry once with scale * T:detection.retryScaleFactor; if it fails again states[i] = 'failed' (page counts as no systems) and processing continues
```

- One page at a time; the next page to start is `nextPageToProcess(states, priorityPage)`; `priorityPage` is set by `DetectionService.prioritize(pageIndex)` (called by the viewer, S4). Only rectangles are kept; bitmaps are released right after each page (DET-020); results live only in runtime memory (DET-022).
- Levels `fast`/`standard`/`fine` come from `T:detection.levels`; default `T:detection.defaultLevel`. (Changing the level comes in M11.)
- The task is submitted to the scheduler with class `'detection'`. The scheduler context is built from `AppLifecycle` (`visible`, `batterySaver`, `userActive`) and the draw state (`strokeInProgress`, false for now). Implement the web `AppLifecycle`: `visible` from `document.visibilityState`; `batterySaver` from `navigator.getBattery` when available (`null` otherwise); `userActive` true from any `pointerdown/pointermove/wheel/keydown/touchstart` until `T:detection.idleBeforeResumeMs` later; `onPause` from `visibilitychange`/`pagehide`. When `pickNext` returns nothing for detection because of the context, retry when the context changes (signal effect), not by polling.
- `DocumentStore` exposes computed signals: `pagesUsable` (pages inside `usablePrefix`), `systems = flattenSystems(pagesUsable)`, `junctionCount`, `bars = computeBars(pagesUsable)`, `provisionalBars` (for pages `isProvisional`: `computeBars([page])` with every bar marked provisional, junction `-1`), `detectionProgress` (`{done, total}`), `detectionComplete = isComplete(states)`.

### S3 — Resource management (DET-017, DET-018, NFR-011, NFR-012)

- Verify the behaviors with tests using fake `AppLifecycle` and a fake engine: detection does not start while `userActive`, resumes after idle; does not run while hidden; does not run when `batterySaver === true`; a page whose engine returns `out-of-memory` is retried at the lower scale and then marked `failed` without stopping the others; the governor's `renderScaleFactor` is applied.
- Under `governor.level ≥ 2` detection renders at the reduced scale; at level 3 it pauses until the level drops.
- Log nothing to the console in production builds.

### S4 — Bars and progress in organization mode (DET-016, DET-019, DET-021, ORG-008, ORG-009, ORG-010)

- `BarsLayer` inside each page box of `OrganizationViewer`: for every bar of that page: an absolutely positioned element `left 0`, `width 100%` of the page, `top = bar.y × scale`, `height = max(bar.height × scale, 1 px)` (a zero-height bar draws as a 1 px line), color `T:colors.orgBar.tint` at `opacity`. Pages without systems (or failed) get no bars (ORG-009, DET-012).
- Provisional bars (pages that are done but outside the usable prefix) use `provisionalOpacity`, `pointer-events: none`, and show no content (DET-021).
- A page whose state is not done/failed shows a small `processing` icon in its top-right corner.
- When the viewer's visible page set contains a `'pending'` page, call `DetectionService.prioritize` with the nearest such page (the first visible pending page). (DET-021)
- Bottom bar in organization mode: while `!detectionComplete`, show the `processing` icon and `done/total` next to the page indicator (numbers only).
- Selected-bar styling (`selectedOpacity`) is prepared as an input (`selectedJunction`) of `BarsLayer`, both bars of a page change highlighted when either is selected; interaction comes in M11.

## Tests

- Unit: detection-queue specs; `DetectionService` pipeline with fake renderer/engine (unit conversion, level params, retry, failure, prefix, priority); `AppLifecycle` web adapter with fakes.
- E2E (Chromium + WebKit + Firefox where WebAssembly workers are supported): open `synthetic-score.pdf`; within a generous timeout all three pages become done; 12 systems (4 per page) give junctions 0…12; junctions 4 and 8 lie on page changes and have two bars each, so `bars` has **15** entries; organization mode draws 15 bar elements; progress disappears when complete.
- E2E: opening a 3-page PDF and immediately scrolling to page 3 processes page 3 first (observe the order through the debug hook `ngDevMode` only).
- Memory sanity (Chromium): after detection completes no ImageBitmap leak (cache size equals its entries; worker mats freed per the unit test).

## Do not

- Do not detect on the main thread; do not keep bitmaps after a page is processed.
- Do not persist detection results anywhere (M15 embeds them in the PDF).
- Do not add UI for levels, jumps, breaks, stops or numbers (M11).
- Do not load OpenCV in the main bundle or from a CDN; do not add more OpenCV functions than listed.
- Do not "improve" the filter in `core/` or the algorithm of this milestone.
