# V1-M0 — Baseline (owner)

**Who:** you, not the agent. **Tag at the end:** `v0.0.0`. **Requirements:** GEN-004, PIP-008.

Goal: a new Angular app that builds, is pushed to a private GitHub repository, and deploys to Firebase Hosting from `main`. M1 adapts this baseline, so it only has to work, not to be pretty.

## 1. Tools on the Ubuntu PC

- Node.js (current LTS), npm, git.
- Angular CLI: `npm install -g @angular/cli` (or use `npx @angular/cli`).
- Firebase CLI: `npm install -g firebase-tools`, then `firebase login`.
- Not needed yet: Android Studio, JDK (see M3).

## 2. Create the app

```
ng new codexmusicae
```

Answer the prompts:
- Stylesheet format: **CSS**.
- Zoneless (no zone.js): **yes**.
- Server-side rendering / prerendering: **no**.
- Routing: **no** (the app is a single page with tabs).
- Leave the default unit test runner and linter setup of your Angular version. If ESLint (`angular-eslint`) is not included, add it with `ng add angular-eslint`.
- Skip optional AI-tool configuration prompts.

Check: `npm start` shows the Angular starter page; `npm run build` succeeds (output in `dist/codexmusicae/browser`).

## 3. GitHub

1. Create a **private** repository `codexmusicae`, default branch `main`, no license.
2. Push the app (`git remote add origin …`, `git push -u origin main`).
3. Copy the delivered documents into the repo and commit them:
   - `AGENTS.md` (root), `docs/**` (requirements, roadmap, decisions, limitations, changelog, architecture, milestones), `src/config/tunables.ts`.

## 4. Firebase

1. Firebase console → create a project (analytics off is fine).
2. Enable **Hosting**. Enable **App Distribution** and create a tester group (used in M3; costs nothing to enable now).
3. In the repo: `firebase init hosting` — public directory `dist/codexmusicae/browser`, single-page app **yes**, do **not** overwrite `index.html`.
4. Create a **service account** for deployment: Google Cloud console → IAM → service accounts → new, roles **Firebase Hosting Admin** and **Firebase App Distribution Admin**; create a JSON key. Keep the file out of the repo.

## 5. Deploy pipeline (minimal)

Create one workflow that, on push to `main`: checks out, runs `npm ci`, `npm run build`, and deploys to Hosting (the official `FirebaseExtended/action-hosting-deploy` action with `channelId: live`, or `firebase deploy --only hosting` with the service account). No pull-request handling. M1 splits this into the final pipelines.

## 6. GitHub secrets and variables

Settings → Secrets and variables → Actions. Use exactly these names; the later pipelines expect them.

| Name | Kind | Content | Needed from |
|---|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT_CODEX_MUSICAE` | secret | the service-account JSON (whole file) | M0 |
| `FIREBASE_PROJECT_ID` | variable | the Firebase project ID | M0 |
| `FIREBASE_ANDROID_APP_ID` | variable | the Firebase Android app ID (`1:…:android:…`) | M3 |
| `FIREBASE_OWNERS_TESTER_GROUPS` | variable | owners tester group alias, comma separated; receives **every** Android and iOS build, from any branch | M3 |
| `FIREBASE_ANDROID_TESTER_GROUPS` | variable | Android App Distribution tester group alias, comma separated; receives builds of `main` only | M3 |
| `FIREBASE_IOS_TESTER_GROUPS` | variable | iOS App Distribution tester group alias, comma separated; receives builds of `main` only | M18 |
| `ANDROID_KEYSTORE_BASE64` | secret | base64 of the release keystore | M3 |
| `ANDROID_KEYSTORE_PASSWORD` | secret | keystore password | M3 |
| `ANDROID_KEY_ALIAS` | variable | key alias | M3 |
| `ANDROID_KEY_PASSWORD` | secret | key password | M3 |

iOS signing and distribution (M18, optional; the `ios` workflow skips the signed steps while any of these is missing; see `docs/ios-distribution.md`):

| Name | Kind | Content | Needed from |
|---|---|---|---|
| `FIREBASE_IOS_APP_ID` | variable | the Firebase iOS app ID (`1:…:ios:…`) | M18 |
| `IOS_CERTIFICATE_BASE64` | secret | base64 of the Apple Distribution certificate with its private key (`.p12`) | M18 |
| `IOS_CERTIFICATE_PASSWORD` | secret | password of that `.p12` | M18 |
| `IOS_PROVISIONING_PROFILE_BASE64` | secret | base64 of the ad hoc provisioning profile (`.mobileprovision`) | M18 |

`FIREBASE_OWNERS_TESTER_GROUPS`, `FIREBASE_IOS_TESTER_GROUPS` (above) and `FIREBASE_SERVICE_ACCOUNT_CODEX_MUSICAE` are reused.
