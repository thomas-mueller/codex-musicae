# V1-M14 — Drawing tools, undo/redo, eraser

**Tag at the end:** `v0.14.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M13 done (the input resolver already reports role `'draw'`).

**Requirements:** ANN-001, ANN-002, ANN-003, ANN-004, ANN-006, ANN-007, ANN-008, ANN-009, ANN-010, ANN-011, ANN-012, ANN-013, SAV-007. (ANN-005 is completed in M15 when ink from the file enters the model; the eraser built here works on every stroke in the model.)

Goal: pen, highlighter and eraser in annotation mode with smooth live drawing, vector strokes in PDF user space, undo/redo, remembered tool settings. Nothing is saved yet (M15); strokes live in memory per tab.

## Core part (first)

Copy `docs/contracts/core/annotation.ts` + `fixtures/annotation.cases.ts` into `src/app/core/` (the fixtures read the compositions of `composition.cases.ts`, which already exists; the case field `composition` names an entry id, `'SYN'` = `synComposition`). Write the specs first (red), then implement as in the doc comments:

- `simplifyPath`: iterative or recursive Ramer–Douglas–Peucker using distance to the **segment**; keep a point only if its distance is strictly greater than `epsilon`; for a degenerate segment (both ends equal) use the distance to that point.
- `distanceToPolyline`: min over segments (projection parameter clamped to [0,1]); one point → distance to it; empty → `Infinity`.
- `strokeHit`: `distanceToPolyline(p, points) <= radius + widthPt/2`.
- `inkTransforms` / `placementsAt`: translation `(dest - source)` per content; dedupe by page and `|Δ| ≤ 1e-6`; `placementsAt` only contents whose `dest` contains the point (left/top inclusive, right/bottom exclusive).
- `startOwner`: first content in `contents` order containing the point, with its `contentIndex` and translation; none → `null`.
- `slidePointToUser` / `userPointToSlide`: via `displayToUser` / `userToDisplay` and the translation.
- Undo: `pushAction` (append, clear redo, drop oldest beyond depth), `undoStep`, `redoStep`, `applyAction` exactly as documented.

## Steps (commit after each)

### S1 — Tool settings and toolbar behavior (ANN-001, ANN-002, ANN-003, ANN-004, ANN-007)

- `ToolSettingsStore` (`state/`): `pen` and `highlighter` each `{ color, widthIndex }`, persisted through the `Preferences` port (keys `tool.pen`, `tool.highlighter`), defaults `T:annotation.defaultPen` / `defaultHighlighter`; validates stored values (color must be one of the 6 presets, `widthIndex` 0…2, else default).
- Tool buttons (M7 UI): tap an inactive tool → active (toggled look); tap the active tool → inactive. A **long press** (`T:layout.longPressMs`) or the small `levelSelector`-style settings affordance shown on the active pen/highlighter button opens `ToolPopup` (a popup next to the strip, or a sheet in compact layout): a grid of the 6 colors (`T:colors.penPresets` or `highlighterPresets`, the selected one toggled) and 3 width samples (lines of `T:annotation.penWidthsPt` / `highlighterWidthsPt` drawn at screen scale, the selected one toggled). The eraser has no popup. Changes apply immediately and are persisted.
- `UiStore.tool` stays cleared outside annotation mode (already in M7/M13); entering annotation mode never restores a tool (ANN-007).
- Highlighter: opacity `T:annotation.highlighterOpacity`, `multiply: true`; pen: opacity 1, `multiply: false`.

### S2 — Stroke model, undo/redo, events (ANN-006, ANN-009, ANN-012, SAV-007)

- `DocumentStore`: `strokes: Signal<InkStroke[]>`, `undo: Signal<UndoState>` (initial `EMPTY_UNDO`); `addStroke(s)`, `eraseStrokes(list)` (each pushes one `UndoAction` with `T:annotation.undoDepth`), `undo()`, `redo()` using `undoStep`/`redoStep` + `applyAction`; `strokesOfPage(i)` computed index. History is cleared when the tab closes (ANN-006).
- `changes` event stream on the `DocumentStore` (a plain `Subject`): `{type:'change'|'strokeStart'|'strokeEnd', t}`; M15 consumes it. `UiStore.strokeInProgress` signal mirrors start/end.
- Undo/redo buttons (top bar compact; tool strip expanded): disabled when the stack is empty or no tool UI applies; both act on the active tab only.
- Strokes are in PDF user space of their page (SAV-007): never store slide or display coordinates. A stroke referencing a page never changes its page.

### S3 — Live drawing (ANN-008, ANN-009, ANN-010, ANN-011, ANN-013)

1. **Coordinates.** Pure helper `clientToSlide(client, stageRect, view, displayScale, slideSize)` (unit-tested): `slide = slideCenter + (client - stageCenter - pan) / (zoom × displayScale)` where `stageCenter` is the center of the stage rectangle. Cases (stage 800×600 at the origin, slide 940 × 626.667, `displayScale = 800/940`): client (400,300), zoom 1, pan 0 → (470, 313.333); client (0,300) → (0, 313.333); zoom 2, pan (−200, 0), client (400,300) → (587.5, 313.333).
2. **Start (role `'draw'`, tool pen/highlighter):** convert the pointer to slide space, `owner = startOwner(composition, p)`. `null` → the whole gesture is ignored (ANN-010, nothing drawn, no navigation). Otherwise start a stroke owned by `owner.pageIndex`; set `strokeInProgress`; emit `strokeStart`.
3. **Points:** every pointer sample (use `getCoalescedEvents()` when the browser provides it, else the event itself; `getPredictedEvents()` only for the live layer, never stored) is converted with `slidePointToUser(owner, box, p)` **using the owner's translation for all points**, also when the pointer moves over other regions or outside the page (ANN-009). Consecutive duplicate points are skipped.
4. **Live layer:** a dedicated canvas (the `LiveStrokeRenderer` class, **outside Angular reactivity**: no signal writes per point) that has the same geometry and CSS transform as the base slide canvas. Per animation frame draw only the new segments (round caps and joins, width `widthPt × pxPerUnit` with `pxPerUnit = displayScale × dpr`). For the highlighter draw opaque on the live canvas and give the canvas CSS `opacity: T:annotation.highlighterOpacity; mix-blend-mode: multiply` so the live look equals the committed look.
5. **End (pointerup):** `points = simplifyPath(points, T:annotation.simplifyEpsilonPt)`; a stroke with fewer than 2 distinct points becomes a dot of 2 equal points; `id = crypto.randomUUID()` (fallback: counter + random); `addStroke`; clear the live canvas; emit `strokeEnd`. `pointercancel` or a second pointer going down (the policy turns into `'pinch'`) discards the live stroke without any action.
6. **Navigation during a stroke (ANN-013):** the `NavigationHandler` (M13) buffers `Next/Previous/First/Last` commands while `strokeInProgress` and applies them in order right after the stroke ends. Buttons, slider and wheel go through the same commands.
7. Tool active + one pointer = draw; two pointers = pinch/pan (the policy from M13). Tap zones and swipes stay off while a tool is active (ANN-008, already enforced by the policy).

### S4 — Committed ink, eraser, sharpness (ANN-005 part, ANN-012, NFR-002)

- **Committed layer** (`InkLayer`): draws all strokes of the pages shown on the current slide. For each placement in `inkTransforms(composition)` and each stroke of that placement's page, map points with `userPointToSlide(placement, box, p)` and draw a smoothed polyline (quadratic curves through midpoints); highlighter strokes with `globalAlpha = opacity` and `globalCompositeOperation = 'multiply'`. A stroke shown in several placements (repeated systems) is drawn in each (ANN-012). Skip strokes whose mapped bounding box is outside the slide. The layer is cached; it is redrawn only when the slide, the strokes, the orientation or the size change. At zoom > 1, after `T:rendering.zoomSettleMs`, redraw into a viewport-sized canvas at the zoomed scale (respect `T:resources.maxCanvasPixels`) so lines stay sharp; at fit zoom remove it.
- **Eraser** (tool `eraser`, role `'draw'`): on pointer down/move: for each placement in `placementsAt(composition, p)` convert the pointer with `slidePointToUser` (that placement), `radiusPt = T:annotation.eraserHitRadiusPx / (displayScale × zoom)`, and collect all strokes of that page with `strokeHit`. Hit strokes disappear at once from the layer; when the pointer is released **one** `erase` action with all strokes hit during the gesture is pushed (no action if nothing was hit). Works on every stroke in the model (strokes loaded from the file arrive in M15).
- Performance: during a stroke Angular change detection must not run per point (zoneless: no signal writes in the pointer path; a test counts `ApplicationRef.tick` calls during a 200-point stroke: at most 2).

## Tests

- Unit: `annotation.spec.ts` from fixtures; `clientToSlide` table; `ToolSettingsStore` (validation, persistence); `DocumentStore` stroke/undo flows (add, undo, redo, erase group, depth limit); navigation buffering during a stroke.
- Component tests: `ToolPopup` selection and persistence; button toggling; `LiveStrokeRenderer` with a fake 2D context (draws only the new segments per frame; highlighter uses the CSS opacity path).
- E2E (three engines, mouse): annotation mode on the synthetic PDF with the pen active: drag across a system → a stroke appears (pixel sample of the ink layer is the pen color); `undo` removes it, `redo` restores; start a drag on the grey outside the page (zoomed out or enlarged slide) → no stroke; with the pen active tap zones do nothing but PageDown turns the slide; PageDown during mouse-down is applied only after mouse-up; highlighter: pixel over black ink stays dark (multiply) and over white is the color at the configured opacity; eraser over a stroke removes it and undo brings it back; tool color/width survives a page reload; after a zoom the ink stays at the right place (same stroke, `userPointToSlide` equals the drawn pixel position within 1 px); a stroke drawn on a repeated system (create the repeat `4 → 0` in organization mode first) appears on both occurrences.
- E2E (Chromium, CPU throttled 4× through CDP): a 200-point stroke produces no main-thread task longer than `T:budgets.drawingMaxLongTaskMs × T:budgets.ciToleranceFactor`.

## Do not

- Do not save anything to the PDF (M15); do not add stylus detection or palm rejection (M19); no pressure, no shapes, no text, no lasso.
- Do not store display or slide coordinates in strokes; do not write signals per pointer event.
- Do not change the input resolver's rules (`pointerPolicy`), `core/annotation.ts` signatures or fixture values.
- Do not make the eraser touch anything other than the model's strokes.
