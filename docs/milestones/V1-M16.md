# V1-M16 — Platform features: fullscreen, wake lock, Android file access, open-with, tab restore

**Tag at the end:** `v0.16.0`. **Model:** mid-tier, medium effort; escalate to the strong model after two failed attempts on a step (native Android code and browser quirks). **Prerequisite:** M15 done; Android Studio and a device or emulator available. **This is the riskiest milestone:** platform behavior can only be verified on real devices. Work step by step and stop for the owner after S2 and S3.

**Requirements:** FIL-011, FIL-012, FIL-013, FIL-014, FIL-018, FIL-019, PLT-004, PLT-005, PLT-006, PLT-007, PLT-008, NFR-015.

Goal: presentation mode becomes true full screen with the screen kept awake (browser and Android); the Android back button works; Android opens and saves files in place and appears in "Open with…"; tabs and positions come back after a restart.

## Core part (first)

Copy `docs/contracts/core/session.ts` + `fixtures/session.cases.ts` into `src/app/core/`, write the spec (red), implement `parseSession` as documented (validate shape, drop invalid tabs, keep the first of duplicate ids, clamp `activeIndex`, default bad numbers to 0).

## Steps (the owner commits after each)

### S1 — Web: fullscreen and wake lock (PLT-004, PLT-005)

- `adapters/web/WebFullscreen implements Fullscreen`: `enter()` calls `document.documentElement.requestFullscreen({ navigationUI: 'hide' })` (fall back to the `webkit`-prefixed method if the standard one is missing); no API (iPhone Safari) → `err('unsupported')`. `active` signal from `fullscreenchange` (+ prefixed event); `onExternalExit(cb)` fires when `active` turns false without a call to `exit()` (Esc, system gesture).
- `adapters/web/WebWakeLock implements WakeLock`: `navigator.wakeLock.request('screen')`; keep the sentinel; re-acquire on `visibilitychange` to visible while still wanted; `release()`; no API → `err('unsupported')`.
- **Wiring (important):** the browser demands a user gesture. Call `fullscreen.enter()` and `wakeLock.acquire()` **synchronously inside the command handler** of `ToggleMode`/mode switch (the handler runs inside the click/key event; do not move this into an `effect()` or after an `await`). Entering presentation succeeds even if `enter()` fails (then only the app UI is hidden). Leaving presentation (any route: center tap, Esc, switch) calls `exit()` and `release()`. When `onExternalExit` fires while in presentation mode → issue `ExitPresentation` (back to annotation mode, PLT-004).
- Tests: unit with fakes (enter on toggle, exit on leave, external exit returns to annotation, wake lock re-acquire on visibility); E2E Chromium with a click: `document.fullscreenElement` is set in presentation and cleared after Esc/center tap and the mode is annotation; E2E in all engines with `page.addInitScript` replacing `navigator.wakeLock` by a recorder: acquire on entry, release on exit; the unsupported path (delete the APIs in an init script) still enters presentation mode.

### S2 — Android: immersive mode, keep awake, back button (PLT-005, PLT-006, PLT-007)

1. Add `@capacitor/app` (back button, `minimizeApp`). Write a small native plugin `ImmersivePlugin` (Kotlin or Java) in `android/app/src/main/java/app/web/codexmusicae/`, registered in `MainActivity` before `super.onCreate`, methods `enter()` and `exit()`:
   - `enter`: `WindowCompat.setDecorFitsSystemWindows(window, false)`; `WindowInsetsControllerCompat(window, window.decorView)`: `hide(WindowInsetsCompat.Type.systemBars())` and `systemBarsBehavior = BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` (sticky immersive); `window.attributes.layoutInDisplayCutoutMode = LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` (draw under cutouts and rounded corners); `window.addFlags(FLAG_KEEP_SCREEN_ON)`.
   - `exit`: show the system bars again, clear `FLAG_KEEP_SCREEN_ON`, restore the previous cutout mode and `setDecorFitsSystemWindows(window, true)`.
   Run on the UI thread. Re-apply `enter` in `onWindowFocusChanged(true)` while presentation is active (the system may restore the bars after dialogs).
2. `adapters/capacitor/CapImmersiveFullscreen implements Fullscreen` and `CapWakeLock implements WakeLock` (both call the plugin; `WakeLock` can share the flag with `enter`, keep the port semantics); selected in the composition root when `Capacitor.isNativePlatform()`.
3. `adapters/capacitor/CapBackButton implements BackButton`: `App.addListener('backButton', …)` runs the registered handlers from the highest priority; if none returns true call `App.minimizeApp()`. The `NavigationHandler` registers **one** handler (priority 0) that runs the `Back` chain of M13 (popup → picking/selection → presentation → annotation) and returns whether it handled something. This gives PLT-007 without special cases.
4. Safe areas: with `viewport-fit=cover` the WebView exposes `env(safe-area-inset-*)`; verify in presentation that the progress line and slide stay inside the inset bottom edge and content draws under the cutout.
5. Tests: unit with a fake plugin and fake `App` (back chain; minimize when nothing handled); build check (`npm run cap:sync && ./gradlew assembleDebug`) in the Android pipeline; **manual** on a device: presentation hides status and navigation bars, a swipe from the edge shows them transiently, the screen stays on for 5 minutes, back leaves presentation, back in annotation mode minimizes the app, display cutout is used.

### S3 — Android: file access in place and "Open with" (PLT-008, FIL-018, FIL-019)

1. Native plugin `DocumentAccessPlugin` (`@CapacitorPlugin(name = "DocumentAccess")`), methods:
   - `pickDocuments({ multiple })`: `ACTION_OPEN_DOCUMENT`, type `application/pdf`, `EXTRA_ALLOW_MULTIPLE`, flags `FLAG_GRANT_READ_URI_PERMISSION | FLAG_GRANT_WRITE_URI_PERMISSION | FLAG_GRANT_PERSISTABLE_URI_PERMISSION`; for each result `takePersistableUriPermission(uri, READ|WRITE)` in try/catch (a failure of WRITE → try READ only and report `writable: false`); returns `[{ id, name, size, lastModified, writable }]` and stores `id → uri` in the plugin's own `SharedPreferences` (file references only).
   - `openRead({ id })` → `{ handle, size }`; `readChunk({ handle, offset, length })` → base64 string; `closeRead({ handle })`. Chunk size `T:resources.fileChunkBytes`.
   - `openWrite({ id })` → `{ handle }`: chunks go to a temp file in the cache directory (`writeChunk({ handle, base64 })`); `commitWrite({ handle })` copies the temp file to the target in **one native loop** through `contentResolver.openOutputStream(uri, "wt")` (shortest possible window for the truncating write; LIM-011) and deletes the temp file; `abortWrite`.
   - `createDocument({ name })` (`ACTION_CREATE_DOCUMENT`, then the write calls) for **save a copy**.
   - `isPersisted({ id })`, `forget({ id })` (release the persisted permission, delete the mapping), `getPendingIncoming()`, event `incomingFile`.
2. `adapters/capacitor/CapFileAccess implements FileAccess` using the plugin: `pickPdfs`, `reopen(ref)` (`not-found` if the id is unknown, `denied` if the permission is gone), `write` (chunked: the whole transfer must not block the UI; `err('write-failed')` on any error), `saveCopy`, `isSame` (same underlying URI; equal id is enough), `forget`. Reading assembles chunks into one `Uint8Array` without base64 string concatenation of the whole file.
3. **Open with:** in `AndroidManifest.xml` add to the main activity an intent filter: action `android.intent.action.VIEW`, categories `DEFAULT` and `BROWSABLE`, data `mimeType="application/pdf"` with schemes `content` and `file`. In `MainActivity` handle the intent in `onCreate` and `onNewIntent`: for a `content://` URI try `takePersistableUriPermission` (ignore failure) and decide `writable` from `(intent.flags & FLAG_GRANT_WRITE_URI_PERMISSION) != 0` or a successful persist; queue the file in the plugin and emit `incomingFile`. `adapters/capacitor/CapOpenWith implements OpenWith` delivers pending files on registration (cold start) and later ones through the event. If write permission is missing the file is opened read-only (lock icon, save a copy).
4. **Web "Open with" (FIL-019):** add to the PWA manifest `"file_handlers": [{ "action": "./", "accept": { "application/pdf": [".pdf"] } }]` and `"launch_handler": { "client_mode": "focus-existing" }`; `adapters/web/WebOpenWith implements OpenWith` uses `window.launchQueue.setConsumer` (where available) to get file handles, adopts them into `WebFileAccess` (a method `adoptHandle(handle)` returning an `OpenedFile`) and delivers them. Only desktop Chromium supports it; others never call back.
5. Tests: unit for `CapFileAccess` with a fake plugin (chunk assembly, errors map to `FileAccessError`, `reopen` outcomes) and `CapOpenWith` (pending + later events), `WebOpenWith` with a fake `launchQueue`; **manual** on a device: pick a PDF, annotate, close and reopen; edit in place and check the file in another viewer; "Open with" from the Files app (read-write if the provider grants it, otherwise read-only and "save a copy"); a 30 MB PDF opens in at most 10 s and the app stays responsive; kill the app during a save (check that the next open still works or that the original can be recovered from "save a copy"). Record the results in `docs/device-checklist.md` (create it in this milestone with the manual tests of S2 and S3; M17 completes it).

### S4 — Tab and position restore (FIL-011, FIL-012, FIL-013, FIL-014, NFR-015)

- `SessionPersistence` (`state/`): builds a `SessionSnapshot` from `SessionStore` and each `DocumentStore` (`system` = `position.system`; `orgPage` and `orgOffset` = the organization scroll position expressed as page index and display-space distance from that page's top), writes it through the `Preferences` port (key `session`) `T:persistence.sessionDebounceMs` after any change and **immediately** on `AppLifecycle.onPause`.
- At startup `SessionStore.restore()`: `parseSession(await prefs.get('session'))`; null → nothing. For each tab: create it in status `restoring`, call `FileAccess.reopen(ref)`:
  - success → open normally; when the document and playing order are ready, apply the position: `entry = findEntryForSystem(entries, system)` and the organization scroll (FIL-014).
  - `needs-user-gesture`, `denied` (web: Chromium permission prompt needs a click) or `not-found` (browsers that keep no handle) → status `needsReopen` (icon on the tab). One tap on the tab calls `reopen(ref)` **inside the click handler** (grants permission); if that fails with `not-found`, the same tap opens `pickPdfs()` and the picked file replaces the tab's file while keeping the stored position (FIL-013).
  - The tab at `activeIndex` becomes active.
- After startup the mode is always annotation mode (FIL-012), the tool is cleared, presentation is never restored.
- Unsaved in-memory changes cannot survive a killed WebView; what is lost is at most the changes since the last autosave (NFR-015). The immediate flush on pause keeps the session itself current.
- Tests: unit with fakes: snapshot building, debounce and immediate flush, restore outcomes (ok, needs-reopen paths), mode forced to annotation, position applied after readiness, replacing a tab's file keeps the position; E2E (Chromium, input path so handles are missing): open two PDFs, reload the page → both tabs come back as `needsReopen`; clicking one and choosing the file restores the position; the active tab is selected and the mode is annotation.

## Do not

- Do not use a remote `server.url`, extra Capacitor plugins beyond `@capacitor/app` and your own two native plugins, or Android permissions beyond what the Storage Access Framework needs (no `READ_EXTERNAL_STORAGE`, no `MANAGE_EXTERNAL_STORAGE`).
- Do not call fullscreen or wake lock from an `effect()` or after an `await`.
- Do not add iOS code (M18); do not mark device-only behavior as verified: write "manual device test required" in `docs/device-checklist.md` instead.
- Do not store PDF bytes in the preferences store or in native storage; only file references and the session snapshot.
