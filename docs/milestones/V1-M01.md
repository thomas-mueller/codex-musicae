# V1-M1 — Adapt the baseline

**Tag at the end:** `v0.1.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M0 done (`docs/baseline.md` exists).

**Requirements:** GEN-001, GEN-006, I18-001, I18-002, PLT-001, PLT-003, NFR-014, ARC-001, ARC-002, ARC-003, ARC-004, PIP-001, PIP-002, PIP-007, TST-004, TST-005. Read them with `grep -n`.

Goal: turn the `ng new` baseline into the project skeleton: layers with enforced boundaries, tunables, translations, test tooling, and the final pipeline split. No feature code.

## Steps (the owner commits after each)

### S1 — Layers and lint boundaries (ARC-001, ARC-002, ARC-003, PLT-003)

1. Read `docs/baseline.md`; note the Angular version and test runner in `docs/decisions.md` (new `DEC-070`).
2. Create the folders from `docs/architecture.md` ("Folder structure") with a short `README.md` or `index.ts` in each so they are tracked. Create `ports/` with only a `README.md`: ports are written in M4.
3. Enforce the import matrix from `architecture.md` with lint. Use one boundary tool (for example `eslint-plugin-boundaries`, or `no-restricted-paths` from `eslint-plugin-import`); record the choice in `decisions.md`.
4. Ban platform APIs outside `adapters/` and the composition root: `navigator.wakeLock`, `requestFullscreen`/`document.fullscreenElement`, `showOpenFilePicker`/`showSaveFilePicker`, `localStorage`, `sessionStorage`, `indexedDB`, imports from `@capacitor/*`.
5. In `core/`, ban imports from `@angular/*`, DOM globals (`window`, `document`, `navigator`) and third-party packages.
6. Strict TypeScript: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`. Zoneless, standalone, OnPush default via the schematics defaults.
7. Add a **self-test**: a script `npm run lint:selftest` that copies one violating fixture per rule into a temp folder and asserts that lint fails for each. It runs in the lint pipeline.

### S2 — Tunables, i18n, identity (ARC-004, I18-001, I18-002, GEN-001, GEN-006)

1. Place `src/config/tunables.ts` as delivered (already in the repo). Do not change values.
2. Add a lint rule that flags numeric and color literals outside `src/config/` and tests (`@typescript-eslint/no-magic-numbers` with `ignore: [0, 1, -1, 2]` is a start). If the rule is too noisy, lower it to `warn` and record that in `decisions.md`.
3. Add a runtime translation library (recommended: Transloco) with one file `src/assets/i18n/en.json`, language `en`. All text comes through it.
4. Add a check that fails the lint job when a template contains a text node with letters outside the translation pipe or directive (acceptable: `@angular-eslint/template/i18n` configured for text checking, or a small script). Include a violating fixture in the self-test.
5. Set the app title, `<title>` and index metadata to `T:identity.appName` (read from `tunables`). The page shows only a placeholder container; no visible text.
6. Confirm there is no analytics, no external font or script URL in `index.html` and no network call at startup.

### S3 — Test tooling (TST-004, TST-005, PLT-001)

1. Unit tests: use the runner `ng new` generated. If it generated Karma, switch to Vitest following the Angular documentation for the installed version. Add one trivial test whose name contains an ID (`it('ARC-004 tunables export …')`).
2. Playwright: install `@playwright/test`; `playwright.config.ts` with projects `chromium`, `firefox`, `webkit` (desktop) and device projects for a phone and a tablet on Chromium (Pixel/Galaxy Tab profiles), WebKit (iPhone/iPad profiles) and Firefox where available. Use the profile names available in the installed Playwright version.
3. The web server for E2E is the production build served statically (not `ng serve`).
4. One smoke test: the page loads, `document.title` equals the app name, no console errors, no request to a foreign origin.
5. Set `browserslist` per PLT-001 (latest two versions of Chrome, Edge, Firefox, Safari ≥ 16.4; Android Chrome, Firefox, Samsung Internet, Edge). TypeScript target and browserslist are the only places that encode platform minimums.
6. Add to `docs/decisions.md` a short "Safari rule": Safari-only code changes only together with a WebKit E2E test (TST-005).

### S4 — Pipelines (PIP-001, PIP-002, PIP-007, NFR-014)

1. Composite action `.github/actions/build-web/action.yml`: setup Node (version from `.nvmrc` or `package.json` engines), `npm ci`, `npm run build`. Used by all deploy pipelines.
2. Workflow `lint-test.yml`, name `lint-test`: trigger **every push to every branch** (`branches: ['**']`, so tag pushes do not run it). Steps: checkout with `fetch-depth: 0`, setup Node with npm cache, `npm ci`, lint, `lint:selftest`, unit tests, install Playwright browsers (cache them), build, E2E on all projects. Upload the Playwright report as artifact on failure.
3. Workflow `deploy-web.yml`, name `deploy-web`: trigger `workflow_run` on `lint-test`, type `completed`, any branch (no branch filter). Job condition: the triggering run's conclusion is `success`. Checkout `ref: ${{ github.event.workflow_run.head_sha }}` with `fetch-depth: 0`, use the composite action, deploy to Firebase Hosting channel `live` using the secret `FIREBASE_SERVICE_ACCOUNT_CODEX_MUSICAE` and variable `FIREBASE_PROJECT_ID`. Delete the old M0 deploy workflow.
4. Angular budgets in `angular.json`: set the `initial` budget so the build fails above `T:budgets.initialBundleKbGzip`, measured the way Angular measures (check the docs for raw vs. transfer size) and record the interpretation in `decisions.md`.
5. Document in `AGENTS.md` (section "Commands") the exact commands for install, dev server, lint, self-test, unit tests, E2E, build.

## Do not

- Do not write feature code or components beyond the placeholder container.
- Do not add Capacitor, pdf.js, pdf-lib, OpenCV or any dependency not named here.
- Do not change `tunables.ts` values, secrets, the Firebase project or the Hosting target.
- Do not add pull-request deployments or preview channels.
- Do not edit the requirement texts. Report problems in `docs/questions.md`.

## Acceptance criteria

- [x] `npm run lint`, `npm run lint:selftest`, unit tests and `npx playwright test` pass locally.
- [x] A deliberate boundary violation (for example a `core/` file importing `@angular/core`) makes lint fail; the self-test proves it for each rule.
- [x] A push to any branch starts `lint-test`; a push to any branch starts `deploy-web` after `lint-test` succeeds; a failing test prevents deployment.
- [x] The hosting URL still shows the placeholder and the page title is `CodexMusicae`.
- [x] Requirement statuses of the listed IDs are updated (`done` only where a test or check proves it); `AGENTS.md` "Commands" is filled in.
