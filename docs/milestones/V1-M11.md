# V1-M11 — Jumps, breaks, stops, bar content, levels

**Tag at the end:** `v0.11.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M10 done.

**Requirements:** ORG-011, ORG-012, ORG-013, ORG-014, ORG-015, ORG-016, ORG-017, ORG-018, ORG-019, ORG-020, ORG-021, ORG-022, ORG-023, ORG-024, DET-014, DET-015.

Goal: in organization mode the user selects bars, creates and edits jumps, breaks and stops, sees playing-order numbers and badges on the bars, manages jumps in a list, and re-runs detection at another level. The playing order itself comes from the M6 functions.

## Core part (first)

Copy `docs/contracts/core/edits.ts` + `fixtures/edits.cases.ts` and `fixtures/junction-labels.cases.ts`; `junctionLabel` (+ `JunctionLabel`) already exists as a stub in `junctions.ts` (copied in M4); add the exports for `edits.ts` to `core/index.ts`. Write the specs first (red), then implement:

- All `edits.ts` functions as described in their doc comments. Reuse `isValidJump` / `isValidMarkJunction` from `playing-order.ts`. `addJump` appends `{ origin, target, pass, id: nextJumpId }` and increments `nextJumpId`; `removeJump` never changes `nextJumpId`; `toggleBreak`/`toggleStop` keep the lists ascending and unique; `clearJunction` removes jumps whose origin **or** target is the junction.
- `junctionLabel`: index of the first bar with that junction in `bars` order; `ordinal` = number of bars of that page up to and including it; `page` = `pageIndex + 1`.

## Steps (the owner commits after each)

### S1 — Marks in the document model (ORG-017, ORG-024)

- `DocumentStore.marks: Signal<DocMarks>` (initial `EMPTY_MARKS`); methods `addJump`, `removeJump`, `updateJump`, `toggleBreak`, `toggleStop`, `clearJunction` that call the pure functions with the current `junctionCount`; invalid results (null) leave the state unchanged and set a transient `lastRejected` signal (the UI shows a brief error icon on the bar; no text).
- Computed from `core/`: `playingOrder = generatePlayingOrder({ systemCount, jumps: marks.jumps, stops: marks.stops, maxLength: T:playingOrder.maxLength })`, `numbers = systemNumbers(playingOrder, systemCount)`, `forcedBreakAfter = forcedBreaks(playingOrder, new Set(marks.breaks))`.
- Deleting is immediate and has no undo (ORG-024). Marks stay editable only for the usable prefix: junctions beyond it do not exist yet; the viewer shows provisional bars without interaction (M10).
- Marks are per tab and kept in memory (saving comes in M15).

### S2 — Bar content and selection (ORG-011, ORG-012, ORG-013, ORG-014, ORG-022, ORG-023, ORG-010)

- **Selection:** tapping a bar sets `UiStore.selection = { kind: 'junction', junction }`; both bars of a page-change junction get `selectedOpacity`. Tapping empty space (outside bars/chips/badges), `Escape` or back deselects (Escape stays local until M13: `// TODO(M13)`). Tapping a provisional bar does nothing.
- **Row content on each bar** (a single compact row, no numbering toggle):
  1. Numbers of the system **above** the junction: `numbers[junction - 1]` joined with `", "` ascending ("3, 9"); junction 0 shows nothing; both bars of a page-change junction show the same text. Small monospaced digits at the bar's left edge, after the scissors icon if present.
  2. Break: a solid line in `T:colors.breakLine` across the bar's width centered vertically, with the `slideBreak` icon at the **left edge**.
  3. Stop: the `stop` icon.
  4. Jump badges (S3).
  Rows are drawn in an overlay layer above the bar, vertically centered on the bar, and may be taller than the bar (z-index above neighbors); they never change layout.
- **Chip:** a floating `SelectionChip` next to the selected bar (right side, flips below/above to stay inside the viewport) with icons: `jump`, `slideBreak` (toggle; shows toggled look when present), `stop` (toggle), `delete` (only if `junctionHasItems`; clears the junction). Break and stop buttons are disabled on junctions 0 and N (invalid by `isValidMarkJunction`).

### S3 — Jumps: creation, pass, badges, editing (ORG-015, ORG-016, ORG-018, ORG-019, ORG-020)

- **Creation:** `jump` in the chip → `UiStore.pickingTarget = { originJunction }`. In that mode all other bars show a target highlight, a slim hint bar (top of the canvas area) with the `cancel` icon appears, page navigation, scrolling and zoom stay active, and tapping a bar creates `addJump({ origin, target: tappedJunction, pass: 1 })` (tapping the origin again does nothing). `Escape`/`cancel` leaves picking without a change. Picking works across pages; provisional bars cannot be targets.
- **Pass stepper:** right after creation a small popup anchored at the origin bar opens with `−`, the number, `+` (integer ≥ 1; `−` disabled at 1); every change calls `updateJump` immediately. It closes like any popup.
- **Badges:** at the origin bar's right edge: `jump` arrow icon, the target label as `page·bar` from `junctionLabel` (for example "7·1"), and "×pass"; at the target bar's right edge: a matching badge with the origin label. Both in `T:colors.jumpPalette[jumpColorIndex(id, size)]`. Several badges stack side by side from the right.
- **Select a badge** (tap): `UiStore.selection = { kind: 'jump', id }`; the chip then offers `pass` (opens the stepper), `change target` (enters picking with `editJumpId`: the next tapped bar calls `updateJump({target})`), `delete`. **Long press** (`T:layout.longPressMs`) on a badge scrolls the viewer to the other end of the jump (`scrollToJunction`: first bar of the junction, centered, smooth).
- Duplicates (same origin and pass) are allowed; no plausibility messages (ORG-017).

### S4 — Jump list, levels and re-run (ORG-021, DET-014, DET-015)

- **Jump list:** the `jumpList` button opens a `Sheet` (compact) or `Panel` (expanded). Each entry: color dot, from label `p·b`, `→`, to label, `×pass`; tap = scroll to the origin bar (and select the jump); a `delete` icon or swipe-left deletes. Empty list shows nothing but the empty panel.
- **Level selector** (`levelSelector`, three icon steps for `fast`/`standard`/`fine`; current level toggled): choosing another level opens a confirmation dialog (icons only: `cancel` / confirm check) because marks may be lost; confirming calls `DetectionService.redetect(level)`.
- **Re-run:** `DetectionRun` becomes `activeRun` plus optional `candidateRun`. A re-run builds the candidate in the background with the same pipeline; the active run stays displayed and usable meanwhile (progress icon shows the candidate's progress). When the candidate completes: `reconcileAfterRedetection(marks, activeSystemCount, candidateSystemCount)`; the candidate replaces the active run and the (kept or cleared) marks are stored. If the candidate is cancelled (new re-run requested) the old one stays. Failed pages count as no systems.
- Add `DetectionService.redetect(level)` and `cancelCandidate()`; tests with fake engine/renderer for: unchanged count keeps marks; changed count clears; the old bars stay visible until the swap.

## Tests

- Unit: `edits.spec.ts`, `junction-labels` spec from fixtures; `DocumentStore` marks and computed signals (use the playing-order fixtures: configure marks equal to fixture inputs and assert `playingOrder.entries`); stepper logic.
- Component tests: bar row rendering for numbers/breaks/stops/badges (given fake bars and marks); chip button states per junction (0, middle, N); picking mode highlight; `jumpList` entries.

The playing order is then `[1,2,3,4,1,2,3,4,5,…,12]`: the origin bar shows the numbers "4, 8" and a badge `1·1 ×1`; the first bar shows the matching badge `1·5`; set a break on junction 2 and a stop on junction 6 and see the icons; delete the junction items; create a second jump and open the list; delete from the list; change level `standard → fine` → confirm → marks cleared only if the count changes (the synthetic PDF keeps 12 systems at both levels: marks are kept). Use the expected numbers from the M6 fixtures logic, not magic numbers.
- E2E: tapping empty space deselects; long press on a badge scrolls to the other end (assert scroll position changed to that page).

## Changed after review (2026-10-31)

This file stays as the historical contract of M11. The owner's review changed these behaviours; the current wording is in `docs/requirements.md`, the reasons in `docs/changelog.md` and `docs/decisions.md` (DEC-090…DEC-093):

- Numbers are shown on the music systems, not on the bars (S2, ORG-011/012).
- A new jump starts at the number of existing jumps from the same origin plus one (S3, ORG-016).
- Jump badges became markers on the systems with system numbers (S3, ORG-018…020).
- The jump list became the marks list (jumps, slide breaks, stops in playing order) (S4, ORG-021).
- The detection render scales are 100 / 150 / 200 dpi (S4, DET-013, ASM-09).
