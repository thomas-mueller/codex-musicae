# V2-M14 — Rendering robustness and scroll-bar bug

**Tag at the end:** `v1.14.0`. **Model:** mid-tier, medium effort; strongest tier if a root cause is not found after two attempts. **Prerequisite:** M10, M12, M13 done (everything that renders is in place).

**Requirements:** R-27a/b, R-58a…e, R-38a/b, D-19, R-46 (edge tests).

**Requirement IDs:** UIX-031, UIX-032, NFR-021, NFR-022, NFR-023, NFR-024, TST-017.

Goal: pages and tiles are never left blank after zoom, scroll or mode changes; the tests that prove it exist; the reported scroll bar is reproduced and fixed if it is real.

## Steps (the owner commits after each)

### S1 — Reproduce and stress tests first (R-58d)

1. Seeded random stress tests (Playwright, Chromium and WebKit, corpus PDFs, seed printed on failure): rapid page jumps, scroll sequences, zoom in/out sequences, mode switches during rendering, rendering during detection, tab/file switches. After each sequence settle and assert that **no visible tile is blank** (read the tile layer state through the debug hook; a tile counts as blank when its bitmap is missing and no request is pending).
2. Budgets for these runs in `T:budgets` (time to settle, maximum queue length, maximum bitmap memory); measured values printed.
3. Record the failing seeds as regression cases in `e2e/stress/seeds.json`.

### S2 — Fixes (R-27, R-58a…c, R-58e)

1. First candidate (V1 check): in organization mode a tile whose task was cancelled more than `T:rendering.tileRetryMax` (= 3) times is not requested again until the view changes (`features/organization/page-tiles.ts`). Verify with a failing seed; fix only what the tests prove.
2. Keep: visible-first priority, cancellation of stale requests, bounded queue, placeholder scaling during zoom, render after `T:rendering.zoomSettleMs`. Add a **watchdog**: a periodic check (`T:rendering.watchdogIntervalMs`) that re-requests any empty visible area; it must never starve input or drawing (lowest priority class, one request per tick).
3. Correct tile placement after zoom in all three modes.

### S3 — Scroll bar (R-38, D-19)

1. The owner supplies browser, OS and mode (or a screenshot) where a right-hand page scroll bar appears. Reproduce it in a Playwright test (`document.scrollingElement.scrollHeight > clientHeight` or a visible scrollbar width) before changing anything.
2. If reproduced: remove the page-level scroll bar on desktop only; PDF-area scroll bars stay. If it cannot be reproduced: record that in `docs/limitations.md` ("not reproducible") and make no change. Ask in `docs/questions.md` and stop if the owner's information is missing.

### S4 — Tooltip edge test (R-46d)

Add the remaining edge test for tooltips on all four edges in all three modes (M5 built the clamp).

## Tests

- Stress suite as above (nightly job on demand, a short seeded run in the `e2e` workflow).
- Unit: watchdog scheduling (time-injected), retry policy.
- E2E: scroll-bar test if reproduced.

## Do not

- Do not redesign the renderer, scheduler or cache.
- Do not relax a budget to pass.
- Do not remove scroll bars inside the PDF area.
- Do not fix by adding delays.

## Acceptance criteria

- [ ] Stress suite exists, fails on the V1 behavior where blank tiles occur (at least one proven seed, or a documented "none found") and passes after fixes.
- [ ] Watchdog implemented and test-covered.
- [ ] Scroll bar: reproduced and fixed, or recorded as not reproducible.
- [ ] Requirement statuses updated; lint, unit tests, E2E, build green.

## Owner step

Provide the scroll-bar information if S3 asks for it, review, commit, then `git tag v1.14.0 && git push --tags`.
