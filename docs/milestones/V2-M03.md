# V2-M3 — Editions and feature configuration

**Tag at the end:** `v1.3.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M1 done (M2 recommended). The owner has decided the free and paid app IDs (R-22i).

**Requirements:** R-22a…l, R-8a, R-8b, R-8c, D-7, D-9, D-32.

**Requirement IDs:** GEN-011, GEN-012, ARC-009, EDN-001, EDN-002, EDN-003, EDN-004, EDN-005, EDN-006, EDN-007, EDN-008, EDN-009, EDN-010, EDN-011, EDN-012, EDN-013, EDN-014, EDN-015, EDN-016.

Goal: one code base builds a **free** app (also the web app) and a **paid** app. Every paid feature exists in the code and has an on/off switch in a feature-configuration file; the free configuration switches them off and tests prove they are unreachable. The web build stores nothing.

## Steps (the owner commits after each)

### S1 — Feature configuration (R-22e, R-22l)

1. `src/config/features.web.ts` and `src/config/features.native.ts` (separate from `tunables.ts`): a typed object with one boolean per feature, each with a comment (what it switches, which edition). Initial switches: `autosave`, `saveCopy`, `sendTo`, `recentFiles`, `sessionRestore`, `persistSettings`, `persistFileChoices`, `restoreZoom`, `crossFileAutoOpen`, `shareIn`, `webOrganizational` (web only, R-22l). Later milestones add their own switches.
2. The build selects exactly one file (Angular `fileReplacements` or build configurations `web`, `native-free`, `native-paid`); each build bundles only its own file. The paid native file enables all.
3. `FeatureFlags` injection token in `ports/` (read-only signal-free object), provided by the composition root. Features read the token, never the files.
4. Lint rule or check script: every feature key exists in **every** configuration file (a missing key fails the build, R-22k).

### S2 — Free mode behavior (R-22a…d)

1. Free is strictly read-only: no save, no Send to, no export, no persistence. Annotations, marks and organization work in memory and stay temporary.
2. Blocked actions stay **visible but disabled** (existing buttons get a disabled state through the switch; no new strings; icon-only).
3. The persistence ports (`PreferencesPort`, file-handle storage, session store) get a wrapper selected by the switches: with persistence off, nothing is written or read, including recent files, zoom, per-file choices and settings. The paid configuration keeps the V1 behavior unchanged.
4. Autosave is off in free/web; the modified marker remains the only indicator (full UI change in M6).

### S3 — Web stores nothing (R-8b, D-9)

1. Web configuration: `persistSettings`, `sessionRestore`, `recentFiles`, `persistFileChoices` off. The web adapters for `localStorage` (`adapters/web/web-preferences.ts`, key prefix `cm.v1.`) and IndexedDB (`adapters/web/web-file-access.ts`, database `cm-files`) stay in the code for the paid native configuration; they are not constructed in the web build.
2. The PWA service worker keeps caching the app's own files (D-9).
3. Playwright test on the production web build: open a PDF, change settings, draw, switch modes; afterwards assert no cookies, empty `localStorage` and `sessionStorage`, and no IndexedDB databases (`indexedDB.databases()`), on Chromium, Firefox and WebKit.

### S4 — Builds, IDs, privacy (R-22g/h/i, R-8a, R-8c)

1. App IDs: free and paid get distinct IDs in `config/tunables.ts` (`identity.appId`, `identity.appIdPaid`); Capacitor config per variant; iOS bundle IDs likewise. Decided with the owner, fixed here.
2. CI: the `android` workflow builds both variants (debug in CI, release signing as before); the `ios` workflow builds both schemes. A build that starts from the wrong feature file fails a consistency check (free build must not contain paid switches set to true).
3. R-8a/R-8c: no code change expected; add a check that no analytics or crash-reporting package is a dependency (extends `scripts/check-static-compliance.mjs`). Privacy declarations are written in M19.

## Tests

- Unit: feature-key completeness across the configuration files; wrapper behavior with each switch (reads and writes dropped when off); each paid-only action is disabled when its switch is off (IDs `EDN-…` from M0).
- E2E per configuration (web/free, native-free, native-paid, using the Playwright web build with the respective file): free build — no save, no write call is ever made (spy on the file-access port), disabled controls visible; paid build — V1 behavior intact (autosave, recent files, restore).
- Web-storage test (S3).

## Do not

- Do not delete persistence code; do not fork the code base per edition.
- Do not add price, store or payment logic (the paid app is a separate store listing, R-22g).
- Do not change tunables unrelated to identity.
- Do not edit existing tests except to provide the feature configuration they run under (list each).

## Acceptance criteria

- [ ] Both feature files exist, are complete, comment every switch, and are checked for key completeness.
- [ ] Free/web: nothing is persisted; web-storage test green on three engines.
- [ ] Paid native: all V1 behavior unchanged.
- [ ] Distinct app IDs wired for Android and iOS; CI builds both variants.
- [ ] Requirement statuses updated; lint, unit tests, build green.
