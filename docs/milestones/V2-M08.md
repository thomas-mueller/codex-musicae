# V2-M8 — Detection: parameters, rerun, progress

**Tag at the end:** `v1.8.0`. **Model:** mid-tier, medium effort; plan step with the strongest model (new filters in the engine). **Prerequisite:** M2, M4, M5, M7 done.

**Requirements:** R-18a…g, R-19a, R-19c, R-19d, R-19g, R-19i, R-19j, R-37a…c, R-10a…h, D-15, D-16, R-UX1 (popup exception).

**Requirement IDs:** DET-025, DET-026, DET-027, DET-028, DET-029, DET-030, DET-031, DET-032, DET-033, DET-034, ORG-025, ORG-026, ORG-027, ORG-028, ORG-029, ORG-030, ORG-031, ORG-032, ORG-033.

Goal: the three V1 detection level buttons become a technical parameter popup with two new kinds of filter; a single page can be rerun; detection continues in the background where the platform allows it; organization mode shows the annotation mode's progress indicator; highlight and number options live in the settings.

## Steps (the owner commits after each)

### S1 — Engine: new filters (`core/`, `adapters/opencv`, worker)

1. Parameter set `DetectionParams`: `minSystemWidth`, `maxSystemWidth` (units of page width), `minSystemHeight`, `maxSystemHeight` (units of page height), `dpi`. The V1 `fullWidthSystemRatio` stays a tunable, not in the popup. `adaptiveBlockSize` and `adaptiveC` stay tunables.
2. `core/detection.ts` filter: accept a component box only when width and height lie within the limits (**new**; V1 had only a minimum width). Contract and fixtures first (at least 20 cases: boundary values, full-width rule vs. maximum width, tall boxes, tiny boxes).
3. Defaults come from the V1 internal values (V1 `standard` level: 150 dpi, min width 0.5) plus defaults for the new limits that **do not change the results of the corpus compared with V1** (max width and height unrestricted effective values); then tune with the M2 corpus: record the chosen defaults and the corpus effect in `docs/decisions.md`. A corpus entry that gets worse blocks the change.
4. Keep the component boxes per page in memory (needed by M9 hint mode): the worker returns them with the result; memory is bounded by `T:resources` limits and released when the document closes.

### S2 — Parameter popup, rerun, rules (R-18a…c, R-19a/c)

1. Remove the three level buttons. A **short click** on the detection tool offers "all pages", "current page", "cancel"; a **long click** opens the popup with the five parameters (technical on purpose).
2. Auto-detection on a new file; embedded systems skip detection; a page-count mismatch discards the data (V1, SAV-005, DET-023).
3. Rerun of the current page replaces its systems; marks of that page follow the M4 rule (kept only if the page's system count is unchanged, else deleted); undoable as one step (M7). "All pages" keeps V1 behavior (old results active until done).
4. No cancel of a running detection; a short click during a run is ignored (R-18f). Refinement only on finished pages (used by M9).
5. During detection behave as V1 (R-18g): pages in order, the page being viewed first, finished prefix usable, unfinished pages show provisional bars that are not selectable, scrolling/zoom/modes/drawing remain possible, detection yields to input.

### S3 — Background policy and progress (R-18e, D-16, R-37)

1. Web: `pauseWhenHidden` default false so the worker keeps running in a hidden tab (browsers may throttle). Android and iOS: pause in the background and resume on return (V1); write the platform limit into `docs/limitations.md`.
2. Organization mode shows the same progress indicator as annotation mode: a page counter x/n at the right end of the horizontal scroll bar, n = processed pages with a trailing "+" while detection runs. Remove V1's separate left counter in organization mode (the per-page processing icon may stay).

### S4 — Display options (R-19d/g/i/j, R-10)

1. Register in the settings (M5, Display group): "Highlight systems" (a transparent filled area with soft fading edges; color and opacity in tunables), "Highlight vertical-space bars" (V1 look), "Number systems". With the fill on, the number gets a cut-out or a contrasting color.
2. "Number systems" shows the **system number on its page** (D-12); V1 playing-order numbers are removed.
3. Bars are display only: not clickable (R-19g); the V1 chip on tap is removed here only if M10 has not yet replaced it; otherwise leave the chip until M10 and say so in the report.
4. Number weight depends on the aspect ratio of the system's own box (wide and flat bolder, mapping in tunables); size as V1, reduced when it does not fit the width; a safety floor in tunables.

## Tests

- Unit: filter fixtures, parameter popup state, rerun mark rule, number weight mapping, progress indicator text (page counter with "+").
- E2E: corpus run through the new parameters equals V1 expectations; popup changes alter results; rerun current page; hidden-tab detection continues on Chromium web (visibility emulated), pauses on the Android profile.
- Corpus: results with the defaults compared in a table (information) and asserted against `expected.json`.

## Do not

- Do not build the refine tool or hint mode (M9) — only keep the component boxes.
- Do not add levels back; do not expose `adaptiveBlockSize`/`adaptiveC`.
- Do not change the pdf.js rendering path.
- Do not write a foreground service for Android (accepted limit, D-16).

## Acceptance criteria

- [ ] Popup with five parameters; new width/height filters pass fixtures.
- [ ] Defaults tuned on the corpus and recorded; no corpus regression.
- [ ] Page rerun with the mark rule; undo works.
- [ ] Progress indicator in organization mode; background policy per platform; limitation recorded.
- [ ] Highlight, bar and number options in settings; system number per page.
- [ ] Requirement statuses updated; lint, unit tests, E2E, build green.
