# V2-M11 — Annotation tools I: thickness, color, pen and finger

**Tag at the end:** `v1.11.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M5, M7 done.

**Requirements:** R-6a…c, R-7a…g, R-20i, R-52a…c, R-53a/b, D-17, #56.

**Requirement IDs:** ANN-018, ANN-019, ANN-020, ANN-021, ANN-022, ANN-023, ANN-024, ANN-025, ANN-026, ANN-027, ANN-028, ANN-029, ANN-030.

Goal: pen and highlighter get one-value thickness with buttons, a cursor that shows the real stroke, a color chooser, a darker highlighter, and the simplified finger/stylus rule: pen and finger always draw while a tool is active.

## Steps (the owner commits after each)

### S1 — Pen and finger (D-17)

1. With a drawing tool active, **pen, finger and mouse always draw**; two touches zoom and pan; with no tool active one finger pans (when zoomed) or swipes and tap zones work (as V1 without a tool). Palm rejection while the pen is near stays (`core/palm.ts`, V1 rule: touches ignored while the pen is active and for `T:stylus.palmRejectionGraceMs` after).
2. **Remove** the stylus state: `stylusSeen` and `allowFingerDrawing` preferences, the finger-drawing toggle in the pen popup, `pointerPolicy` cases that depend on them. The migration ignores stored `stylus.*` keys. "Reset all settings" has nothing left to clear for them.
3. **Existing tests that may change** (exactly these, each listed in the report): `PP09…PP16` fixtures of `pointerPolicy`, the stylus E2E of V1-M19, tests of `StylusStore`. The palm-rejection tests (`palm.spec.ts`) stay unchanged. Record the accepted consequence in `docs/limitations.md`: with a tool active, fingers cannot swipe or use tap zones; slide changes use pedals, buttons, slider, wheel or keys, or deselecting the tool.
4. `docs/decisions.md`: DEC for the removal (supersedes the V1 stylus decisions).

### S2 — Thickness and cursor (R-7a…g)

1. One thickness value per tool with thinner/thicker buttons replacing the three presets; step, minimum and maximum in tunables; buttons disabled at the limits; memory per tool (persisted through the registry/preferences; V1 stored an index, migrate by mapping the old index to the closest new value).
2. A preview of the stroke next to the buttons. Pointer cursor: a circle at the real stroke size (scales with zoom) in tool color with a contrasting ring; crosshair only for very thin strokes (`T:annotation.cursorCrosshairBelowPx`); a plain circle for thick ones. On touch: a temporary preview after each change (`T:annotation.previewMs`).

### S3 — Color chooser and highlighter (R-6a…c, R-20i, R-52)

1. A long click on a tool opens the popup with palette plus thickness (V1, DEC-106); a long click on a palette color opens a **color chooser** (hue/saturation/lightness or an equivalent native-free control; no new dependency unless named and recorded). Defaults and the long-click duration in tunables (`T:layout.longPressMs`).
2. Pen, text and stamp share one color; the palette and chooser exist only in the pen popup; the highlighter has its own color (R-20i). (Text and stamps arrive in M12; the shared color state is created now.)
3. Highlighter opacity: raise darkness to a fixed value in tunables (start value, then choose by comparing 0.35, 0.45, 0.55 on corpus PDFs; screenshot table in the report); loaded ink with opacity below 1 still counts as highlighter (ASM-18).

### S4 — Drawing rules (R-53a/b)

After changing tool, color or thickness or closing a popup, drawing works immediately; a tap that closes a popup never draws; strokes only start on the drawable PDF area (V1 ANN-010 stays).

## Tests

- Unit: new `pointerPolicy` fixtures (tool active: pen, touch, mouse draw; two touches zoom; palm rejection), thickness stepping and limits, index-to-value migration, cursor shape function (`core/`, fixtures for thin/normal/thick and zoom).
- E2E (Chromium, WebKit): touch draws with a tool active; two-finger pinch; pen after touch; no tool: swipe turns the slide; popup close tap draws nothing; color chooser sets the color.
- Manual (owner, tablet with stylus): palm resting while writing; update `docs/device-checklist.md`.

## Do not

- Do not add pressure sensitivity or tilt (BKL-002).
- Do not add text, stamps or the mover (M12).
- Do not change the stroke storage format.
- Do not add a dependency for the color chooser without recording it in `docs/decisions.md`.

- [ ] Thickness buttons, previews, cursor as specified; old settings migrate.
- [ ] Color chooser; highlighter opacity chosen with evidence.
- [ ] Requirement statuses updated; limitation recorded; lint, unit tests, E2E, build green.
