# V1-M13 — Input layer and presentation mode

**Tag at the end:** `v0.13.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M12 done.

**Requirements:** NAV-001, NAV-002, NAV-003, NAV-004, NAV-005, NAV-006, NAV-007, NAV-008, NAV-009, NAV-010, NAV-011, NAV-012, NAV-013, NAV-014, NAV-015, NAV-016, NAV-017, NAV-018, NAV-019, UIX-009, UIX-018, UIX-019, UIX-020, ARC-006.

Goal: one input layer turns keys, wheel, taps, swipes, pinch and pan into semantic commands; navigation works in all modes with pedals; presentation mode shows only the slide with a thin progress line. True fullscreen, wake lock and Android back come in M16 (here presentation mode only hides the app's own UI).

## Core part (first)

Copy `docs/contracts/core/gestures.ts` + `fixtures/gestures.cases.ts` into `src/app/core/`; write `gestures.spec.ts` from the fixtures (red), then implement exactly the doc comments:

- `classifyTrack`: tap / swipe / none as specified (inclusive thresholds; `maxMove` = largest distance of any sample from the first).
- `tapZoneOf`: `x/w < left` → left, `x/w >= left + center` → right, else center.
- `isDoubleTap`: `0 <= b.t - a.t <= intervalMs` and distance ≤ `distancePx`.
- `wheelStep`: the numbered rules in the doc comment (state `{accum, lastT, stepT}`); `WHEEL_INITIAL` as given.
- `pointerPolicy`: the table in the doc comment. In v1 the input layer always passes `stylusSeen: false` and `allowFingerDrawing: false` (M19 changes only that).

The fixtures use their own constants (`gestureLimits`, `tapZones`, `wheelConfig`) that equal `tunables.gestures` today; the implementation takes limits as arguments.

## Steps (the owner commits after each)

### S1 — Command bus, keyboard, navigation handler, presentation mode (NAV-001…005, NAV-018, NAV-019, NAV-017, UIX-009, UIX-018, UIX-019, UIX-020)

1. `input/CommandBus`: a typed stream of commands: `Next`, `Previous`, `First`, `Last`, `ToggleMode` (annotation ↔ presentation), `ExitPresentation`, `Back` (Esc), `ZoomBy { factor, anchor }`, `ZoomReset`, `Pan { dx, dy }`, `DoubleTapZoom { anchor }`. Components subscribe; no component reads raw key or pointer events for navigation.
2. `KeyboardInput`: one `keydown` listener on `document`. Build the key id as `Shift+` prefix + `event.code`; look it up in `T:keymap` (`next`, `previous`, `first`, `last`, `back`); ignore events with Ctrl, Alt or Meta; ignore `event.repeat` when `T:gestures.allowKeyRepeat` is false; call `preventDefault` for mapped keys (prevents page scroll on Space/PageDown). Typing targets (`input`, `textarea`, the slider `input[type=range]` focused with arrow keys): the slider keeps its own arrow-key behavior only while it has focus.
3. `NavigationHandler` (`state/`), reacting to commands by mode:
   - annotation/presentation: `Next`/`Previous` → `DocumentStore.goToSlide(current ± 1)` (clamped, no wrap, NAV-003); `First`/`Last` → first/last slide. Slide change resets `slideView` to `FIT_VIEW` (NAV-015).
   - organization: `Next`/`Previous` → scroll to next/previous page (NAV-005); `First`/`Last` → first/last page; zoom persists.
   - `Back` (Esc), in this priority order (NAV-018): close an open popup → cancel jump-target picking, else deselect → presentation mode → annotation mode → nothing. Replace the temporary local Escape listeners from M7/M11 by this command (remove the `// TODO(M13)` markers).
   - `ToggleMode`: annotation → presentation and back; `ExitPresentation` → annotation.
4. **Presentation mode** (`PresentationView`, `features/presentation/`): the app chrome is hidden (M7 already hides the bars); the stage fills the viewport and hosts the same `SlideView` (always `FIT_VIEW`, zoom commands ignored: NAV-017). Entering presentation (UIX-018): keep the current slide; `UiStore.tool = null`; `slideView = FIT_VIEW`; first time in this orientation: `AspectRatioService.captureForOrientation(viewportWidth, viewportHeight)` (SLD-014). The progress line (UIX-020): an absolutely positioned bar at the bottom edge, height `T:layout.progressLineHeightPx`, color `T:colors.progressLine`, width = `progress × 100%` with `progress = n > 1 ? index / (n - 1) : 1`, `pointer-events: none`, inside the safe area (`padding-bottom: env(safe-area-inset-bottom)`). Mouse cursor hides after `T:layout.cursorHideMs` without movement and shows again on movement (UIX-019).
5. Pedals arrive as keys (NAV-019): works in all modes and with a tool active (the keyboard path does not look at the tool).

### S2 — Pointer input: taps, swipes, tap zones, policy (NAV-006…010, ARC-006)

1. `input/PointerInput`: attach pointer events (`pointerdown/move/up/cancel`) to the stage element of annotation, presentation and organization; track each active pointer's samples `{x, y, t}` (from `event.timeStamp`); `touch-action: none` on the slide stage, `pan-y pinch-zoom`-style handling left to the browser in organization mode (native scrolling).
2. **The single resolver (ARC-006):** on every `pointerdown` build a `PointerContext` (`mode`, `toolActive`, number of active pointers, `zoomed = view.zoom > 1 + 1e-6`, `stylusSeen: false`, `allowFingerDrawing: false`, `pointerType`) and call `pointerPolicy`. No other code decides draw vs. navigate. For role `'draw'` emit nothing yet (M14 consumes it); for `'gestures'` collect the track; for `'pinch'`/pan see S3; for `'org-select'` forward the pointer to the bar/badge handlers (M11).
3. On `pointerup` of a `'gestures'` pointer: `classifyTrack(track, viewportWidth, T:gestures)`:
   - `'tap'` and `policy.tapZones`: `tapZoneOf(x, viewportWidth, T:gestures.tapZones)` → left `Previous`, right `Next`, center `ToggleMode`. Mouse clicks count as taps (NAV-007).
   - `'swipe-left'` → `Next`, `'swipe-right'` → `Previous`, only if `policy.swipes` (presentation always; annotation only at fit zoom with no tool active; both given by the policy).
   - vertical swipes and anything else → nothing (NAV-010).
4. In organization mode taps never navigate (policy has `tapZones: false`); bars/badges/chips are handled by their own elements before the stage sees the event (they stop propagation).
5. In annotation mode with a tool active and a single pointer, the policy is `draw`: tap zones and swipes are off (ANN-008); the pedal, buttons, slider and wheel still navigate.

### S3 — Wheel, pinch, pan, double tap (NAV-011…016)

- `WheelInput` on the stage:
  - annotation/presentation at fit zoom, no modifier: `wheelStep(state, {deltaY, deltaMode, t: event.timeStamp}, T:gestures.wheel)` → `Next` for `+1`, `Previous` for `-1`; `preventDefault`.
  - zoomed in (`zoom > 1`): the wheel pans (`Pan` with deltas converted to px; `Shift+wheel` pans horizontally); it never turns slides (NAV-012).
  - `ctrlKey` wheel (trackpad pinch also arrives as ctrl+wheel): `ZoomBy { factor: Math.exp(-deltaY * T:gestures.wheel.zoomSensitivity), anchor: pointer position }` in annotation and organization mode; ignored in presentation (NAV-013, NAV-017). `preventDefault` so the browser page zoom does not trigger.
  - organization mode without modifier: native scroll (do nothing).
- Pinch (two pointers, policy `'pinch'`): factor = current finger distance / distance at the previous move, anchor = midpoint; `ZoomBy`; one-finger pan when `policy.pan` (zoomed): `Pan` from pointer deltas. The `NavigationHandler` applies `ZoomBy` with `zoomAround(...)` and limits (annotation: `T:zoom.min`/`T:zoom.max`; organization: `orgZoomLimits`, with `scrollAfterZoom` for the scroll container), `Pan` with `clampPan` (annotation) or by scrolling the container (organization).
- Double tap (organization, outside bars/badges/chips): `isDoubleTap` on consecutive taps → `DoubleTapZoom { anchor }`: toggles between fit-width and `T:gestures.doubleTapZoomFactor` × fit-width with `scrollAfterZoom` (NAV-016). In annotation mode double tap does nothing (it would delay the tap zones).
- All zoom commands are ignored in presentation mode (NAV-017).

## Tests

- Unit: `gestures.spec.ts` from fixtures; `KeyboardInput` mapping with synthetic `KeyboardEvent`s (each mapped key; Ctrl+key ignored; repeat ignored; Shift+Space = previous); `NavigationHandler` with a fake document (clamping, first/last, Back priority chain, zoom reset on slide change, org page navigation); progress value function (`index/(n-1)`, `n=1` → 1, `n=0` → hide).
- Component tests: `PresentationView` renders only the stage and the line; line width for given indices; cursor hide timer with fake timers; entering presentation clears the tool and zoom and captures the ratio once per orientation.
- E2E (three engines, mouse-based, deterministic): annotation mode on the synthetic PDF: click in the left/right/center tap zones (x = 10%, 90%, 50% of the stage) → previous/next/presentation; presentation: `Esc` returns to annotation; PageDown/ArrowRight/Space → next, PageUp/ArrowLeft/Shift+Space → previous, Home/End; wheel one notch → one slide, two quick notches (100 ms apart) → one slide; Ctrl+wheel zooms in annotation, ignored in presentation; zoomed wheel pans and never turns the slide; a swipe by mouse drag (dx = 20% of the width, 150 ms) turns a slide in presentation mode and in annotation mode without a tool, but not with a tool active (`pen` toggled) and not when zoomed; in organization mode PageDown scrolls one page and a click never navigates; double-click on empty page area toggles zoom.
- E2E (Chromium only): the same swipes through CDP `Input.dispatchTouchEvent`, a pinch with two touch points; touch tap zones.
- Resolver test: a table test of `pointerPolicy` fixtures plus a code-search test that fails if any file other than the `input/` resolver imports `pointerPolicy` or inspects `pointerType` for navigation decisions (a simple grep-based unit test).

## Do not

- Do not implement drawing, stylus handling, saving, fullscreen, wake lock or the Android back button (M14/M15/M16/M19).
- Do not read raw pointer/keyboard/wheel events in components for navigation; all through the command bus.
- Do not add remappable keys, a settings screen or gestures beyond those listed.
- Do not change `core/gestures.ts` signatures or fixture values.
