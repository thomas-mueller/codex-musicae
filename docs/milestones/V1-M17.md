# V1-M17 — Hardening: corpus, round trip, performance, checklists

**Tag at the end:** `v0.17.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M16 done. After this milestone v1 can be released (M18, M19 are optional).

**Requirements:** PLT-011, NFR-001, NFR-002, NFR-016, TST-002, TST-003, TST-006, TST-007, TST-008.

Goal: protect what exists. Detection quality becomes measurable and regressions visible; saving is proven to round-trip; the performance budgets are enforced in the pipeline; manual and tester checklists exist; every `done` requirement is traceable to a test.

## Steps (the owner commits after each)

### S1 — Golden detection corpus (TST-002)

1. Script `scripts/make-corpus.mjs` (pdf-lib, plus `pngjs` as dev dependency for raster pages; deterministic, seeded pseudo-random numbers) generates into `e2e/corpus/` (committed):

| File | Content | Expected systems per page |
|---|---|---|
| `engraved-clean.pdf` | the synthetic score of M8 (3 pages × 4 systems) | `[4,4,4]` |
| `engraved-single.pdf` | 1 page, 1 system, no frame | `[1]` |
| `engraved-mixed-sizes.pdf` | A4 portrait, Letter, A3 landscape, 3 systems each | `[3,3,3]` |
| `flat-staves.pdf` | 1 page, 8 single 5-line staves, no joining barline (full width) | `[8]` |
| `title-then-score.pdf` | page 1: only a filled 300×300 pt block (a "logo"); page 2: 3 systems | `[0,3]` |
| `blank.pdf` | 2 empty pages | `[0,0]` |
| `scanned-noise.pdf` | 2 raster pages (1654×2339 px, paper grey 245, ink 30, seeded speckle noise density 0.0005) with 4 systems each | `[4,4]` |
| `scanned-frame.pdf` | like `scanned-noise` plus a dark 6 px page border | **known limitation LIM-002**: record the actual result; the test asserts it so changes are noticed |

2. `e2e/corpus/expected.json`: `[{ "file": "...", "level": "standard", "systemsPerPage": [..], "note": "...", "knownLimitation": "LIM-002" | null }]`.
3. Playwright test (Chromium, `ngDevMode` debug hook that exposes the detected system counts per page): for each entry whose file exists, open it, wait until detection is complete, compare `systemsPerPage`; also run the same files at levels `fast` and `fine` and write the result table into the test output (no assertion, information only).
4. Real scores: a folder `e2e/corpus/real/` (only PDFs you own or that are in the public domain; keep it out of git if you prefer: add it to `.gitignore`) — `expected.json` entries whose file is missing are skipped. **Workflow for a detection problem:** copy the PDF into `real/`, add the expected counts, the test fails, then tune the level values in `src/config/tunables.ts` (never the algorithm) until it passes without breaking the other entries, record the change in `docs/changelog.md`.

### S2 — Save round trip and file validity (TST-003)

- E2E (all three engines; "save a copy" works everywhere): open `synthetic-score.pdf` → wait for detection → draw two strokes (pen, highlighter), create a jump, a break and a stop, change the aspect ratio → "save a copy" → the downloaded bytes are checked in the Playwright **Node process**: pdf-lib loads them; 2 ink annotations with correct `/InkList` point counts; the embedded JSON parses (`parseMetadata` → `ok`); contains 12 systems, the jump, break, stop and ratio; `qpdf --check` passes when available (CI installs `qpdf`).
- Re-open the downloaded copy in the app: no detection runs, the same marks and strokes are present, erasing one stroke and saving a copy again yields one annotation.
- Repeat the exercise with a copy that already contains a foreign ink annotation and a foreign attachment (made with pdf-lib in the test): both survive, the foreign ink is erasable.
- Property-style test: apply 20 random sequences (seeded) of add/erase/undo/redo through the stores, save a copy, reopen, and compare the set of strokes (ids and points) with the in-memory set.

### S3 — Performance budgets (NFR-001, NFR-002, NFR-016, TST-008)

1. Script `scripts/make-large-pdf.mjs` creates `e2e/perf/reference-120.pdf` (generated in CI, git-ignored): 120 pages A4; pages 1–100 vector synthetic systems (4 per page), pages 101–120 raster as in `scanned-noise` (so the file is a realistic mix).
2. Playwright project `perf` (Chromium only, runs in `lint-test` as a separate job after the others; thresholds come from `T:budgets` multiplied by `T:budgets.ciToleranceFactor`; each test prints its measurement):
   - **open to first slide:** from `setInputFiles` until the first slide canvas is drawn ≤ `openToFirstSlideMs`.
   - **slide change (NFR-001):** 50 consecutive `Next` commands in annotation mode with warm prefetch; time from the command to the next animation frame after the canvas update; the 95th percentile ≤ `slideChangeP95Ms`.
   - **detection impact (DET-017, NFR-002):** while detection runs on the 120 pages, perform 20 slide changes and a 200-point stroke; no main-thread long task (PerformanceObserver `longtask`) above `drawingMaxLongTaskMs`; the stroke's added latency (pointer event dispatch to the next frame) ≤ `drawingMaxAddedLatencyMs`.
   - **memory (NFR-016):** after scrolling organization mode through all pages and zooming to the maximum, the JS heap (CDP `Performance.getMetrics` `JSHeapUsedSize`) ≤ `maxJsHeapMb`; the bitmap cache's reported size ≤ its budget.
   - **CPU throttling run:** repeat the slide-change test with CDP `Emulation.setCPUThrottlingRate` = 4 and report (no assertion): it estimates a small tablet.
3. A breached budget fails the job. Do not relax a number to make it pass; if the code is slow, fix the code or open a question in `docs/questions.md`.

### S4 — Cross-browser matrix and traceability (PLT-011)

- The whole E2E suite runs on every Playwright project: Chromium, Firefox, WebKit, plus the device projects for phone and tablet (Android: Chromium profiles; iPad/iPhone: WebKit profiles). Tests that cannot run on an engine (File System Access, fullscreen, wake lock details, CDP touch) are skipped **explicitly** with a reason; no silent skips.
- Script `scripts/check-traceability.mjs` (runs in `lint-test`): collects requirement IDs from `docs/requirements.md` (status and target) and from test names (`it(...)`/`test(...)` strings containing `TOPIC-nnn`). It fails if (a) a requirement with status `done` appears in no test name and is not in the allow-list `docs/traceability-exceptions.md` (device-only items, each with a reason), or (b) a test names an ID that does not exist. It writes `docs/traceability.md` (generated, committed): ID, status, number of tests.
- A smoke subset (`@smoke` tag: open PDF, navigate, draw, save a copy) runs on all device profiles on every push; the full suite on the three desktop engines.

## Do not

- Do not change `core/`, algorithms, thresholds in `tunables.ts` (except level values for corpus tuning as described), or relax budgets to get green.
- Do not add real copyrighted scores to the repository.
- Do not skip tests silently; every skip names its reason.
