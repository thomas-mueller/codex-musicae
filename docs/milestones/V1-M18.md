# V1-M18 — iOS shell and compile check (optional, unverified)

**Tag at the end:** `v0.18.0`. **Target:** `v1-optional` (drop this milestone first if time or budget runs short). **Model:** mid-tier, medium effort. **Prerequisite:** M17 done.

**Requirements:** GEN-003, PLT-012, PLT-013, PLT-014, PIP-004, PIP-010.

Reality check: the owner has no Mac. Everything written here is checked only by a **CI compile on a macOS runner**; behavior can only be verified by a tester who builds the app on a Mac. Therefore: all iOS-specific code is marked `// UNVERIFIED(ios)`, and the requirement statuses PLT-013 and PLT-014 stay `todo` until a person has run the app on an iPad or iPhone. iOS **Safari** (the web app) is a core v1 target and is not part of this milestone.

Goal: an `ios` Capacitor shell that compiles, with the native pieces mirrored from Android through the same plugin API, plus a CI job and a hand-over document for a tester with a Mac.

## Steps (the owner commits after each)

### S1 — Shell and configuration (GEN-003, PLT-012)

1. Add `@capacitor/ios`; `npx cap add ios`; the `ios/` folder is tracked (the owner commits it) (respect the generated `.gitignore`). Bundle ID `T:identity.appId` (`capacitor.config.ts` already uses it); display name `T:identity.appName`; **deployment target iOS 16.4** in the single place the project uses (Xcode project setting or the generated config); no remote `server.url`.
2. `Info.plist`: declare PDF as a supported document type (`CFBundleDocumentTypes` with content type `com.adobe.pdf`, role Viewer/Editor, handler rank Alternate), `LSSupportsOpeningDocumentsInPlace = YES`, `UIViewControllerBasedStatusBarAppearance = YES`. A small Node script `scripts/check-ios-config.mjs` parses `Info.plist` and the deployment target and fails if these are missing (runs in `lint-test`; this is the only automated proof for PLT-012 besides the compile).
3. Placeholder app icon and launch screen.
4. Safe areas: the web layer already uses `env(safe-area-inset-*)` and `viewport-fit=cover`; add nothing in native code for this.

### S2 — Native plugins mirroring Android (PLT-013; all `// UNVERIFIED(ios)`)

Implement in Swift, with the **same JS plugin API** as on Android so that the TypeScript adapters of M16 are reused unchanged (only the platform selection in the composition root changes: `isNativePlatform()` and platform `ios`):

- `DocumentAccessPlugin` (`pickDocuments`, `openRead`/`readChunk`/`closeRead`, `openWrite`/`writeChunk`/`commitWrite`/`abortWrite`, `createDocument`, `isPersisted`, `forget`, `getPendingIncoming`, event `incomingFile`):
  - Picker: `UIDocumentPickerViewController(forOpeningContentTypes: [.pdf], asCopy: false)` (open in place, multiple selection).
  - Persistence: store **security-scoped bookmarks** (`bookmarkData`) per file id in the plugin's own storage (references only); `reopen` resolves the bookmark and calls `startAccessingSecurityScopedResource()` (balanced `stop…` after use); stale bookmarks → `denied`/`not-found`.
  - Read in chunks of `T:resources.fileChunkBytes`. Write: chunks to a temp file, then one coordinated replace with `NSFileCoordinator` (`.forReplacing`) into the target (shortest window). Save a copy: write a temp file, present `UIDocumentPickerViewController(forExporting:)`.
- `ImmersivePlugin` (iOS): hide the status bar and the home indicator in presentation mode through a `CAPBridgeViewController` subclass that overrides `prefersStatusBarHidden` and `prefersHomeIndicatorAutoHidden` and calls `setNeedsStatusBarAppearanceUpdate()` / `setNeedsUpdateOfHomeIndicatorAutoHidden()`; keep-awake via `UIApplication.shared.isIdleTimerDisabled`.
- "Open with" / "Open in…": handle `application(_:open:options:)` (Capacitor forwards it as the app-URL-open event of `@capacitor/app`); read the URL with security scope, deliver through `incomingFile`, `writable` true only if a bookmark could be created and a write probe is allowed.
- No back-button plugin (iOS has none); leaving presentation mode is by center tap or Esc.

### S3 — CI: `ios` workflow (PIP-004, PIP-010)

Workflow `.github/workflows/ios.yml`, name `ios`, one job like `android`: trigger `workflow_run` on `lint-test`, completed, success only; owner's decision: on every branch for now, `main` only later (the commented `- main` line); runner `macos-latest`; checkout `head_sha` with `fetch-depth: 0`; composite action `build-web`; `npx cap sync ios`; build for the simulator **unsigned**: `xcodebuild -project ios/App/App.xcodeproj -scheme App -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build` (the project uses Swift Package Manager, so no workspace); upload the build logs as artifact on failure. This part needs no Apple account and no secrets.

Then the signed part (PIP-010), **skipped while the Apple secrets are not set** (the job stays green): a signed **ad hoc** archive and export (`-sdk iphoneos`, Release, manual signing from a temporary keychain, profile installed from a secret), IPA validation (bundle ID, version, build number, minimum iOS), and `firebase appdistribution:distribute` to the owners group (every run) and the iOS tester group (`main` only). Secrets and variables are listed in `docs/milestones/V1-M00.md` §6; how to obtain them without a Mac is in `docs/ios-distribution.md`. The agent never creates secrets. TestFlight and the App Store stay `later` (BKL-001).

### S4 — Hand-over document for a tester with a Mac (PLT-014)

Create `docs/ios-unverified.md`:
- a table of every `// UNVERIFIED(ios)` location (file, what it must do, how to check);
- build instructions: install Xcode, open the `ios` project, choose a **Personal Team** (free) for signing, run on the simulator or a connected device;
- a checklist (each OK / problem): app starts; open a PDF from Files (in place) and save back; "Open in…" from Files; presentation hides status bar and home indicator; screen stays on; fullscreen/orientation; pedals; memory with a 50 MB PDF; note the iOS and Xcode versions;
- how to report (screenshots, version text from the info icon).

## Tests

- Unit: the shared TypeScript adapters are already tested with fake plugins (M16); add a platform-selection test (iOS picks the Capacitor adapters but registers no `BackButton`).
- `check-ios-config.mjs` runs in `lint-test`; the unsigned build in the `ios` workflow must be green on `main`.
- Nothing else can be verified automatically; do **not** claim otherwise.

## Do not

- Do not put Apple credentials, certificates or profiles into the repository or the workflow text: signing material comes only from GitHub secrets the owner adds. No TestFlight or App Store steps.
- Do not change the web app's behavior for Safari; do not fork TypeScript adapters for iOS if the plugin API can stay identical.
- Do not mark PLT-013 or PLT-014 `done`.

## Acceptance criteria

- [ ] The `ios` workflow's unsigned build is green; `check-ios-config` passes; every iOS source file carries the `UNVERIFIED(ios)` marker.
- [ ] `docs/ios-unverified.md` exists and is complete.
- [ ] The signed steps are skipped while the secrets are missing; PIP-010 becomes `done` only after one run has uploaded an IPA to Firebase.
- [ ] Statuses: GEN-003, PLT-012, PIP-004 `done`; PLT-013, PLT-014 stay `todo` with a note "unverified, needs a Mac".
