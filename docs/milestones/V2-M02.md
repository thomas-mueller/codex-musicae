# V2-M2 — Real-PDF corpus

**Tag at the end:** `v1.2.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M1 done; the owner has delivered the real PDFs (M0 owner task): local files and/or URLs only, nothing else.

**Requirements:** R-13a…g, R-14a, D-22.

**Requirement IDs:** TST-010, TST-011, TST-013, TST-014, TST-015, TST-016 (TST-012, the license note, is dropped: set its status to `dropped`).

Goal: detection regressions and performance are measured on real scores. The V1 mechanism (`e2e/corpus/expected.json`, `e2e/detection-corpus.spec.ts`) is extended, not replaced; generated synthetic scores disappear, only failure-case fixtures stay.

## Steps (the owner commits after each)

### S1 — Corpus format and the corpus script (R-13a…c)

The owner's only input: PDF files in `e2e/corpus/real/` and/or URLs, one per line (blank lines and `#` comments allowed), in `e2e/corpus/urls.txt`. No license notes, names or checksums.

1. One script `scripts/corpus.mjs`, run as `npm run corpus` (no arguments needed; `--force` as in S2). It does everything in order: (a) downloads each URL of `urls.txt` into a cache folder (git-ignored), file name taken from the URL (collisions get a numeric suffix); (b) writes `e2e/corpus/urls.lock.json` (`{ url, file, sha256 }`, committed) on first download and **verifies against it afterwards**; (c) **skips with a warning** when a download fails or the checksum differs (never fails the job); (d) runs the expectation helper of S2 for all new PDFs; (e) prints a short summary (found, downloaded, skipped, new entries to review). Optional `npm run corpus -- --offline` skips downloads. This script runs in tests and CI only; the shipped app makes no such request (R-8d).
2. Extend `expected.json` entries: `file`, `source` (`folder` | `url`), `systemsPerPage`, `note` (may be empty), `knownLimitation` (as V1), plus detection parameters used (in M2 still the V1 level; M8 replaces the level by the parameter set). The script generates all of it; the owner only reviews.
3. No license field and no `LICENSES.md`.

### S2 — Expectation helper (R-13d)

A module `scripts/make-expected.mjs` (called by `npm run corpus`, also runnable alone): opens each corpus PDF headless through the existing detection debug hook and writes a proposed `expected.json` entry (systems per page). It **never overwrites an entry the owner has edited** (an entry carries `"reviewed": true`) unless called with `--force`. The owner reviews the proposal manually (the first correct reading is a human decision).

### S3 — Test wiring (R-13e)

1. `e2e/detection-corpus.spec.ts`: iterate all entries (folder and cached URL files); skip entries whose file is absent with a visible reason; assert `systemsPerPage`; tolerate `knownLimitation` entries as in V1 (the actual result is asserted so changes are noticed).
2. A `perf` test uses the largest real PDF (and the real PDF with the most pages) instead of the generated `reference-120.pdf` (`scripts/make-large-pdf.mjs` removed, its CI step removed, budgets in `T:budgets` re-measured and adjusted **by the owner's decision only**; list the new numbers in the report).

### S4 — Replace synthetic fixtures (R-14a, D-22)

1. Keep only failure-case fixtures: `damaged.pdf`, a zero-page PDF, a blank page PDF, an encrypted PDF (from `scripts/make-test-pdfs.mjs`, reduced to these). Remove `synthetic-score.pdf` and `scripts/make-corpus.mjs` with its outputs, and `scripts/make-large-pdf.mjs`.
2. Tests that use the synthetic score are switched to a named real PDF of the corpus (`e2e/corpus/real/…`) with the expected counts from `expected.json`. **Edits to existing tests are allowed only to change the fixture file name and the expected counts that follow from it**, each listed in the report.
3. Unit tests that build PDFs in memory with pdf-lib stay (they are not "dummy data" of the app).

## Tests

- Unit: checksum verification and skip-with-warning logic of the loader, "never overwrite reviewed entries" logic of the helper (names with IDs `TST-…` from M0).
- E2E: corpus run on Chromium (all entries), smoke on Firefox and WebKit (first three entries).

## Do not

- Do not change detection code or tunables to make a corpus entry pass; record a failing entry as `knownLimitation` and note it in `docs/questions.md` for M8.
- Do not add dependencies.

## Acceptance criteria

- [ ] At least 15 real PDFs (folder and/or URL list) with reviewed expectations.
- [ ] `npm run corpus` works with no arguments, from only PDFs and/or `urls.txt`.
- [ ] Loader skips unavailable or mismatching downloads with a warning.
- [ ] Helper script does not overwrite reviewed entries without `--force` (tested).
- [ ] No generated synthetic score or large PDF remains; failure-case fixtures stay.
- [ ] Corpus and perf specs green; changed test names/fixtures listed.
- [ ] Requirement statuses updated; `npm run lint`, unit tests and build green.

## Owner step

Review the proposed expectations (the key quality step), commit, then `git tag v1.2.0 && git push --tags`.
