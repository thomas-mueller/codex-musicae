**Tag at the end:** `v1.10.0`. **Model:** mid-tier, medium effort; plan step with the strongest model. **Prerequisite:** M4, M5, M6, M7, M8, M9 done.

**Requirements:** R-19b, R-19f, R-28a…r, R-29a…f, R-30a…e, R-40a…c, R-59a, #59, D-10…D-14, D-26.

**Requirement IDs:** ORG-042, ORG-043, ORG-044, ORG-045, MRK-018, MRK-019, MRK-020, MRK-021, MRK-022, MRK-023, MRK-024, MRK-025, MRK-026, MRK-027, MRK-028, MRK-029, MRK-030, MRK-031, MRK-032, MRK-033, MRK-034, MRK-035, MRK-036, MRK-037, MRK-038, MRK-039, MRK-040, MRK-041, MRK-042, MRK-043.

Goal: the user creates, labels and manages marks through tools on the **ends of systems**. The V1 chip on a tapped bar is replaced; the data model is M4's (marks on systems).

## Steps (the owner commits after each)

### S1 — Tool strip and active areas (R-19b/f, R-28a…c, R-28n/o)

1. Organization tools: detection, refine, delete, bookmark, start, stop, jump, slide break. No tool is active by default; pressing the active tool again deactivates it; only one at a time; choosing another tool cancels a half-defined mark.
2. Active areas are the left and right ends of a system; width `T:marks.endZoneRatio` (start value 0.2, tuned on devices and recorded). Right end: jump start, stop, slide break. Left end: jump target, start, bookmark. With the jump tool the right end sets the start, the left end the target. The wrong end does nothing. Bars are not tap targets.
3. The V1 chip UI (jump, break, stop, delete on a tapped bar) is removed; the temporary M4 mapping is deleted.

### S2 — Jump flow and candidates (R-28d, R-28g…j, D-10)

1. Choosing the jump start prompts for the target and vice versa (target first is new). The chosen system is highlighted at the clicked end; candidates (both directions, all systems) at the opposite end, same width.
2. Candidate opacity modes in the settings (Display group), abstract labels: linear (default), exponential, constant; N, H and floor in tunables.
3. Pass number: after choosing both ends a stepper with the V1 default (existing jumps from the same start + 1) appears (D-10).
4. Cancel: tapping elsewhere, Escape, tapping the chosen system again, Android back, and the cancel icon.
5. Conflicts as V1: no plausibility checks; the M4 rules (one stop per system, none on the last system, one start per file).

### S3 — Labels, colors, markers (R-28e/f/l/r, R-29, R-59a, #59, D-12, D-26)

1. Label inside the colored marker: `<file>:<page>:<system>` (file omitted for the same file), jumps `start -> target` with `×n` above 1; optional user text editable (long click on a marker, text field) and shown after the automatic part. No length limit: the marker grows or wraps and never overlaps another marker or leaves the screen (layout function in `core/` with fixtures).
2. Colors: bookmarks use their own color set in tunables, assigned cyclically; start marks fixed green, stop marks fixed red; jump colors as V1 (`T:colors.jumpPalette`). Several marks on one system sit side by side. The stop marker is larger and colored; the start marker is similar and labelable.
3. Creating marks never scrolls the view on its own (R-28p/q): tests compare scroll positions before and after.

### S4 — Cross-file, marks list, visibility (R-28m, R-30b…d, R-40)

1. Cross-file bookmarks and jumps: targets only from open files, picked by switching to the other file; the pending state survives the switch; closing the source or the other file cancels it. A user-triggered file switch is the only allowed scroll.
2. Marks list (organization mode only, playing order, D-14): the button is grayed out when no marks exist (including cross-file marks referencing this file); a tap navigates and selects; delete by swipe or trash icon as V1; no editing, no filter; unreached items dimmed at the end; labels as in the markers.
3. Marks are hidden in annotation mode by default; global setting "Show marks while annotating" (Display group); never shown in slide mode.

## Tests

- Unit: active-area hit testing (`core/`), label layout fixtures (long texts, many markers), candidate opacity functions, jump state machine (both orders, cancel paths), cross-file pending state.
- E2E (Chromium, WebKit, phone, tablet): create each mark kind, pass-number stepper, label text, marks list, undo of each, save, reload, scroll-position tests, hide/show in annotation mode, cross-file jump between two corpus files.
- Manual (owner, tablet): usability of the 20 % end zones on a real score; adjust the tunable.

## Do not

- Do not change the playing-order algorithm (M4) or the schema.
- Do not add editing from the marks list or a filter.
- Do not add print-order numbers.
- Do not show marks in slide mode.
