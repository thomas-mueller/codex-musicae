# V2-M6 — Top bar and files

**Tag at the end:** `v1.6.0`. **Model:** mid-tier, medium effort (plan: strong if S4 looks unclear). **Prerequisite:** M3, M4, M5 done.

**Requirements:** R-1a…n, R-54a…k, R-30f…k, D-1, D-5, D-6, D-8, D-20.

**Requirement IDs:** FIL-020, FIL-021, FIL-022, FIL-023, FIL-024, FIL-025, FIL-026, FIL-027, FIL-028, FIL-029, FIL-030, FIL-031, FIL-032, FIL-033, FIL-034, FIL-035, FIL-036, FIL-037, FIL-038, FIL-039, FIL-040, FIL-041, FIL-042, FIL-043, FIL-044, FIL-045, FIL-046, FIL-047, NFR-020, MRK-016, MRK-017.

Goal: the V1 tab bar becomes one file entry with a list; saving follows the overwrite rules; files can be shared in; inactive files release memory; referenced files open across files.

## Steps (the owner commits after each)

### S1 — File entry and list (R-1b…i, R-1g, D-20)

1. Replace tabs (`features/tabs/`) by one entry in the top bar: name, status marker (unsaved dot, error, read-only lock, needs-re-open: same marker position, R-1c), "x" — in this order. The entry uses almost the full top-bar width; ellipsis only as fallback (R-1h).
2. A click on the entry opens the list of all open files at full width (the V1 compact behavior everywhere, FIL-004). Order is opening order (R-1i); no reordering.
3. Buttons left and right of the entry: previous/next file, icon only, disabled at the ends (R-1f). "+" right of them opens the file picker (replaces the V1 open button); long press (V1 `LongPressDirective`) opens the recent-files list; recent files are switched off by the feature switch in free/web.
4. Existing tab tests and selectors are **explicitly allowed to change** to the new structure; list them.

### S2 — Saving and closing (R-1a, R-54a…f, R-54h…k, D-5, D-6)

1. No Save button; autosave triggers as V1 (idle 3 s, switch, close, hidden, never during a stroke); autosave off when the switch is off (free/web).
2. **Overwrite dialog** (R-54a): at the first autosave of a file per session, once per file per session, also for the save after detection (SAV-012 stays, D-5). Until the answer nothing is written, changes stay in memory, the modified marker stays. Buttons: "Overwrite", "Save as new file" (the new location becomes the file of the entry, replacing the V1 "save a copy" behavior for this dialog), "Cancel". Checkbox "do not ask again" for this file or for all files (R-54c), persisted; the per-file choice is keyed by **file name** (D-1) and cleared by "Reset all settings".
3. Unwritable file: one warning per file per session with "Save as new file"; the marker stays; shared-in copies without write access are read-only (R-54f).
4. **Closing** (D-6): a paid file saves before closing (failure keeps it open with the error marker, FIL-006); a modified file in free/web asks for confirmation on every close and drops the changes when confirmed; an unmodified or read-only file closes silently.

### S3 — Share-in and memory (R-1j, R-1k…n)

1. Android: add an intent filter for `SEND` of `application/pdf` next to the existing `VIEW` one (`android/app/src/main/AndroidManifest.xml`); handle the shared URI through the existing open path (FIL-018). iOS: share sheet / "Open with" through the existing URL-open event (`UNVERIFIED(ios)`, marked). Web: unchanged.
2. No file-count limit and no eviction logic. When a file becomes inactive its rendered data (bitmaps) is released (change from V1: the shared LRU kept it). Referenced files look like other files. Add a memory test (below).

### S4 — Cross-file opening (R-30f…k, D-1, D-8)

1. File identity as V1 (FIL-002): same entry, same URI, else equal name, size and last-modified time. R-30k: opening a file that matches an open file switches to it.
2. Opening a file with cross-file marks tries to open each referenced file: lookup **by file name** among open files and files with persisted access (Android URI permission, iOS bookmark, web handles in the paid configuration). No match, several matches or no file access → **warning**, metadata untouched, the user opens the file manually (R-30g). In slide mode an unresolved jump stops the presentation at that position (R-30h).
3. Closing a referenced file keeps the marks and shows an immediate warning with "Don't show again" (persisted, reset by Reset all) (R-30i). An already open file stays current; referenced files open in the background (R-30j).
4. In free/web, cross-file marks work in the session and files are opened manually (D-8).

## Tests

- Unit: file-entry state machine, overwrite-dialog rules (once per file per session, answer handling, detection save), name-keyed choices, file lookup by name (none/one/several), close rules per edition.
- E2E: open three files, switch with prev/next/list, close with unsaved changes in free/web (confirmation) and paid (autosave then close), overwrite dialog flow, cross-file open with a missing file (warning), duplicate open (switches), mobile profile layout of the entry.
- Memory: open 30 corpus PDFs on a Chromium profile with a reduced heap limit; the bitmap cache size reported after switching away drops to the inactive file's released value (R-1l); no out-of-memory.
- Manual (owner, device-checklist): share a PDF from another Android app into the app; iOS items stay `UNVERIFIED(ios)` and are collected for M17.

## Do not

- Do not implement reordering, a file-count limit or print.
- Do not store cross-file references anywhere except in the source file (M4).
- Do not use paths or fingerprints for identity.
- Do not change autosave timings.
