# V2-M6 — Top bar and files

**Tag at the end:** `v1.6.0`. **Model:** mid-tier, medium effort (plan: strong if S4 looks unclear). **Prerequisite:** M3, M4, M5 done.

**Requirements:** R-1a…n, R-54a…k, R-30f…k, D-1, D-5, D-6, D-8, D-20.

**Requirement IDs:** FIL-020, FIL-021, FIL-022, FIL-023, FIL-024, FIL-025, FIL-026, FIL-027, FIL-028, FIL-029, FIL-030, FIL-031, FIL-032, FIL-033, FIL-034, FIL-035, FIL-036, FIL-037, FIL-038, FIL-039, FIL-040, FIL-041, FIL-042, FIL-043, FIL-044, FIL-045, FIL-046, FIL-047, NFR-020, MRK-015, MRK-016, MRK-017, UIX-022, UIX-035, UIX-036, UIX-037, UIX-038.

Goal: the V1 tab bar becomes one file entry with a list; saving follows the overwrite rules; files can be shared in; inactive files release memory; referenced files open across files.

## Steps (the owner commits after each)

### S1 — File entry and list (R-1b…i, R-1g, D-20)

1. Replace tabs (`features/tabs/`, now `features/files/`) by one entry in the top bar: name, status markers, "x" — in this order (FIL-021, FIL-022, DEC-165). Below 600 px the top-bar entry has no "x"; the list rows keep it (owner). Unsaved changes are a red "*" directly at the end of the name; the full name is hover text only while shortened and never shows together with a marker tooltip; the lock follows the name after a space, as tall as its text, and saves a copy; the other statuses are icons behind them. All that apply are shown; the narrow bar shows only the most important of the other icons. The entry and the current list row lie on a pale blue pill. It uses almost the full top-bar width; ellipsis only as fallback (R-1h).
2. A click on the entry opens the list of all open files at full width (the V1 compact behavior everywhere, FIL-004). Order is opening order (R-1i); no reordering.
Note: undo and redo are not top-bar controls from M7 on (UIX-034); M6 places no undo/redo button and removes none.
3. Buttons left and right of the entry: previous/next file, icon only, disabled at the ends (R-1f); below 600 px width the bar has neither (owner). The open-file button, **leftmost** in the bar and with a file-opening icon (owner, 2026-11-27; R-1g said "+" on the right), opens the file picker and replaces the V1 open button; holding it opens the recent-files list; recent files are switched off by the feature switch in free/web. No control has a right-click action (UIX-022).
4. Existing tab tests and selectors are **explicitly allowed to change** to the new structure; list them.
5. **Top-bar More button and version** (UIX-035, UIX-036, DEC-164):
   - Expanded layout: remove the More button, `POPUP_OVERFLOW_TOP` and its case in `popup-host.html`/`.ts`. Add a `saveCopy` icon button before the settings button in `top-bar.html`; it is disabled without a document or when the `saveCopy` switch is off, and calls `SessionStore.saveCopy()`.
   - Settings view: show the `APP_VERSION` display value (PIP-018) as plain text below the four groups, labelled with `a11y.versionInfo`. It is neither a fifth group nor a registry setting; "Reset all settings" still ends General.
   - Remove the info popover (`POPUP_INFO`), the info button in the bottom-bar More menu, and the `info` icon and translation keys that nothing uses any more (all seven languages).
   - The compact layout is otherwise unchanged: the bottom-bar More button stays, with the aspect-ratio buttons and "save a copy".
6. For item 5 these tests are also **explicitly allowed to change**; list them, and keep their requirement IDs and checks on the new controls:
   - Unit: `popup-host.spec`, `popup-host.free.spec` (the "save a copy" cases, including EDN-003/008/011, move to a top-bar spec), `testing/version-wiring.spec` (checks the settings view instead of the popover and `popup-host.ts`), `settings-view.spec` (new UIX-035 case).
   - E2E: `shell-controls.spec` (UIX-004/005 control lists; FIL-007: expanded "save a copy" is disabled without a document; UIX-013/015: split the popover test, Escape and outside tap on the compact More menu, the version in the settings mode), `tooltips.spec` (opens More in the compact layout only; the right-edge controls must still be covered), `free-edition.spec`, `web-storage.spec`, and `saveCopyDownload` in `support/saving.ts` (opens More in the compact layout only).
   - `bottom-bar.spec` and `icons.spec` use the compact More menu and should pass unchanged.
7. **Narrow mode button** (UIX-037, DEC-165): below 600 px width the three mode buttons are one button that opens them, so that the file entry fits. For this these tests are also **explicitly allowed to change**: every E2E spec and helper that clicks a mode button (through `support/modes.ts`), and new cases in `mode-switch.spec`.
8. Also **explicitly allowed to change** (owner, 2026-11-27, during S1): `testing/settings-editions.spec` (provides `APP_VERSION` for the settings view) and `features/settings/language-switch.spec` (finds the open-file button by its name; the version string counts as allowed text).
9. **Font** (UIX-038, owner, 2026-11-27, during S1): all text uses the sans-serif stack `T:typography.fontFamily`; where monospace kept digits aligned, tabular figures do.

### S2 — Saving and closing (R-1a, R-54a…f, R-54h…k, D-5, D-6)

1. No Save button; autosave triggers as V1 (idle 3 s, switch, close, hidden, never during a stroke); autosave off when the switch is off (free/web).
2. **Overwrite dialog** (R-54a): at the first autosave of a file per session, once per file per session, also for the save after detection (SAV-012 stays, D-5). Until the answer nothing is written, changes stay in memory, the modified marker stays. Buttons: "Overwrite", "Save as new file" (the new location becomes the file of the entry, replacing the V1 "save a copy" behavior for this dialog), "Cancel". Checkbox "do not ask again" for this file or for all files (R-54c), persisted; the per-file choice is keyed by **file name** (D-1) and cleared by "Reset all settings".
3. Unwritable file: one warning per file per session with "Save as new file"; the marker stays; shared-in copies without write access are read-only (R-54f).
4. **Closing** (D-6): a paid file saves before closing (failure keeps it open with the error marker, FIL-006); a modified file in free/web asks for confirmation on every close and drops the changes when confirmed; an unmodified or read-only file closes silently.

### S3 — Share-in and memory (R-1j, R-1k…n)

1. Android: add an intent filter for `SEND` of `application/pdf` next to the existing `VIEW` one (`android/app/src/main/AndroidManifest.xml`); handle the shared URI through the existing open path (FIL-018). iOS: share sheet / "Open with" through the existing URL-open event (`UNVERIFIED(ios)`, marked). Web: unchanged.
2. No file-count limit and no eviction logic. When a file becomes inactive its rendered data (bitmaps) is released (change from V1: the shared LRU kept it). Referenced files look like other files. Add a memory test (below).

### S4 — Cross-file opening (R-30f…k, D-1, D-8)

1. File identity as V1 (FIL-002): same entry, same URI, else equal name, size and last-modified time. R-30k: opening a file that matches an open file switches to it.
2. Opening a file with cross-file marks tries to open each referenced file: lookup **by file name** among open files and files with persisted access (Android URI permission, iOS bookmark, web handles in the paid configuration). No match, several matches or no file access → **warning**, metadata untouched, the user opens the file manually (R-30g). In slide mode an unresolved jump stops the presentation at that position (R-30h).
3. Closing a referenced file keeps the marks and shows an immediate warning with "Don't show again" (persisted, reset by Reset all) (R-30i). An already open file stays current; referenced files open in the background (R-30j).
4. In free/web, cross-file marks work in the session and files are opened manually (D-8).
5. A reference whose target system no longer exists in the open target file counts as **unresolved** (MRK-015, moved from V2-M4): it is kept, and edits in the target file never modify the source file. `core/marks` (V2-M4) already keeps such references; M6 adds the resolution that decides this.

## Tests

- Unit: file-entry state machine, overwrite-dialog rules (once per file per session, answer handling, detection save), name-keyed choices, file lookup by name (none/one/several), unresolved references to a vanished system (MRK-015), close rules per edition.
- E2E: open three files, switch with prev/next/list, close with unsaved changes in free/web (confirmation) and paid (autosave then close), overwrite dialog flow, cross-file open with a missing file (warning), duplicate open (switches), mobile profile layout of the entry, the narrow mode button, no More button in the expanded top bar, "save a copy" from the top bar, the version in the settings mode in both layouts.
- Unit also: the expanded top bar has no More button and its "save a copy" follows the document and switch rules; the settings view shows the version (UIX-035, UIX-036).
- Memory: open 30 corpus PDFs on a Chromium profile with a reduced heap limit; the bitmap cache size reported after switching away drops to the inactive file's released value (R-1l); no out-of-memory.
- Manual (owner, device-checklist): share a PDF from another Android app into the app; iOS items stay `UNVERIFIED(ios)` and are collected for M17.

## Do not

- Do not implement reordering, a file-count limit or print.
- Do not store cross-file references anywhere except in the source file (M4).
- Do not use paths or fingerprints for identity.
- Do not change autosave timings.
