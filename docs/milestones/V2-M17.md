# V2-M17 — Hardening

**Tag at the end:** `v1.17.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M16 done.

**Requirements:** R-11a/b, R-1n, R-54e, R-15a/b, R-22j/k (test completeness), R-44a, TST-002, TST-003, TST-006…008 (V1 hardening items re-run).

**Requirement IDs:** PLT-017, TST-018, TST-019, TST-020, TST-021.

Goal: protect what exists before the improvement milestone. Everything V2 added is covered by the full suite on all device profiles, by an Android emulator job, by performance and memory checks, and by the tester documents.

## Steps (the owner commits after each)

### S1 — Full suite and traceability

1. The whole E2E suite runs on every Playwright project (desktop Chrome/Firefox/Safari, small phone, Pixel 7, Galaxy Tab S9, iPhone, iPad); tests that cannot run on an engine are skipped **explicitly** with a reason.
2. `scripts/check-traceability.mjs` must pass for all V2 requirements (`done` requires a test name containing the ID, or an entry in `docs/traceability-exceptions.md` with a reason); regenerate `docs/traceability.md`.
3. Configuration matrix (R-22j/k): the persistence-relevant features run in both configurations (free/web: nothing persisted, paid: persisted); a feature without a switch in every configuration fails the build (M3 check re-run).

### S2 — Real-PDF and performance (R-13, R-15, TST-008)

1. Corpus run on all entries (Chromium) and the detection table per parameter set; coverage report per kind of test (M1) archived with the release.
2. Performance budgets from `T:budgets` re-run with the largest real PDF: open to first slide, slide change p95, detection impact on drawing, JS heap, bitmap cache size. Compare to V1 numbers in the report; a regression above the budget fails the job (no relaxing without the owner's decision).
3. **Low-memory stress** (R-1n): open 40 corpus PDFs one after another and switch among them on a Chromium profile with a reduced heap limit and CPU throttling; no crash, no blank tile, memory returns to a bounded level.

### S3 — Android emulator job (R-11a, D-23)

1. A workflow job (release tags and manual only) starts an Android emulator image **for a tablet** (and, if the runtime budget allows, a small phone), installs the debug APK of the paid variant, and runs a smoke script: open a corpus PDF, wait for detection, draw, save, reopen. Use a script runner already in the toolchain (Playwright against the WebView via Chrome DevTools, or `adb` plus Capacitor's WebView debugging); new tools are named in `docs/decisions.md` first.
2. Record runtime and flakiness in `docs/android-ci.md`; the job never blocks ordinary pushes.

### S4 — iOS verification package (R-54e)

Update `docs/ios-unverified.md` and `docs/tester-checklist-ios-safari.md` with the V2 items for a tester with a Mac or an iOS device: autosave and reopen with files from the Files app, iCloud Drive and another provider; share-in; Send to; overwrite dialog; read-only shared-in copies; save-after-detection flow. All remain `UNVERIFIED(ios)` until the tester reports.

### S5 — Checklists and release notes

1. `docs/device-checklist.md`: add V2 items per milestone (end zones, pinch, side fill, share-in, export, hints) and the release checklist.
2. `docs/release-notes-template.md`: update for V2 (version `vX.Y.Z`, changes, limitations, checks).
3. Collect the owner's **improvement list** for M18 as `docs/v2-improvements.md` (empty template: item, source, priority, requirement it touches); fill it with everything found while running this milestone.

## Do not

- Do not change application behavior (bugs found go to `docs/v2-improvements.md` or `docs/questions.md`; a blocking bug is fixed with its own test).
- Do not relax budgets or skip tests silently.
- Do not set a coverage threshold.

## Acceptance criteria

- [ ] Full E2E green on all profiles (explicit skips only).
- [ ] Traceability passes; configuration matrix covered.
- [ ] Corpus, performance and low-memory runs documented; Android emulator job runs on a tablet.
- [ ] iOS verification package and checklists updated; improvements template exists.
- [ ] Requirement statuses updated; lint, unit tests, build green.

## Owner step

Run the device checklist on your tablet, send the iOS package to a tester if available, fill `docs/v2-improvements.md`, review, commit, then `git tag v1.17.0 && git push --tags`.
