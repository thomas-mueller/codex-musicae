# V2-M19 — App-store publishing and release

**Tags at the end:** `v1.19.0` and, on the same commit, annotated **`v2.0.0`**. **Model:** mid-tier, medium effort; smallest tier for texts and translations. **Prerequisite:** M18 done and features frozen. Owner tasks from M0 (store accounts, business and tax preparation, native-speaker reviewers) are complete or well advanced.

**Requirements:** R-2a/b, R-34a…d, R-35a, R-16a…f, R-32a, R-22g/h/i, R-8c, D-3, D-4.

Goal: four store listings (free and paid, Google Play and App Store) are ready to submit from the `v2.0.0` commit, with all texts, documents, images and the release note.

## Steps (the owner commits after each)

### S1 — Icon and image source (R-2a/b)

1. A single source image for app icon and favicon, **at least 1024 × 1024**, without alpha for iOS: the owner provides a new or redrawn version (V1's favicon is 720 × 720); the agent cannot invent the design.
2. Script `scripts/build-icons.mjs` (or the extended existing one) generates all sizes: web favicon, PWA 192/512 (maskable), Android launcher mipmaps and adaptive foreground, iOS `AppIcon` 1024 and the set, store icon 512 (Play). Free and paid may carry a visible marker difference defined by the owner.
3. Build check: all required sizes and formats exist and have the right dimensions and alpha rules.

### S2 — Store texts and documents (R-34a…d, D-3)

1. In `docs/store/` (one folder per store, one file per language): app name, subtitle/short description, full description, what's new — in all seven languages for the free and the paid listing. Texts are short and factual; the free listing says what is read-only; the paid listing says it is a one-time purchase.
2. Documents: privacy policy (states: no data collected, no tracking, no network requests besides the app's own assets), Google Play data-safety answers, Apple privacy answers, age rating answers, support contact text, Apple review notes (how to test, no login needed, sample PDF), export compliance (no encryption beyond the OS). The legal assessment is the owner's or a lawyer's (R-8c); the agent drafts only.
3. Screenshot suggestions: a list per store (device size, screens, caption keys) in `docs/store/screenshots.md`; the owner takes the screenshots on real devices or emulators (the Playwright profiles can produce web screenshots for the free listing).
4. Native-speaker review of the six non-German languages (the owner arranges the reviewers): track in `docs/i18n-status.md`; a language that is not reviewed is either published as "machine-assisted" or removed from the language list before release (owner decision).

### S3 — Identifiers, versions, builds (R-16, R-22g/h/i)

1. App IDs (M3) and display names for the four listings are final; no change after the first publication.
2. Version consistency: all four builds show `v2.0.0`; Android `versionName` `2.0.0`, `versionCode` from CI auto-increment (commit count); iOS marketing version `2.0.0` and build number from CI; the M1 check passes on the `v2.0.0` commit.
3. CI release jobs produce signed Android bundles (AAB) for both variants and the iOS archives (unsigned IPA as in V1 if signing is not set up); upload steps stay manual (owner).

### S4 — Flyer and release note (R-35a)

A simple one-page flyer as PDF and JPG (`docs/store/flyer.*`), content from the store texts; no video. GitHub release note from `docs/release-notes-template.md`: version, changes since V1, limitations (including the Android/iOS background-detection limit and the accepted file-name identity), checks run.

### S5 — Owner checklist (no agent work)

1. Price decided (suggestion about 4.99 EUR), imprint and tax data complete, business registration done (D-4, R-32a).
2. Store listings created; privacy and data-safety forms filled from `docs/store/`; screenshots uploaded; review notes supplied; test tracks (Play internal testing, TestFlight) checked with the signed builds.
3. Submit; after approval publish.

## Tests

- Build checks for icons and versions (unit/script tests with IDs).
- A script test that every store text file exists for all seven languages and both listings, within the stores' length limits (kept in tunables-style config).
- The full CI (lint, unit, E2E, Android emulator job) is green on the release commit.

## Do not

- Do not change app behavior or features (that was M18).
- Do not publish, submit, change GitHub secrets or store consoles; those are owner actions.
- Do not state in store texts anything the app does not do (no cloud, no printing, no accounts).
- Do not add analytics or any network use.

## Acceptance criteria

- [ ] Icons generated from one 1024+ source; build check green.
- [ ] Store texts and documents for all seven languages, both listings; screenshot lists; flyer; release note.
- [ ] Versions consistent on the `v2.0.0` commit; signed bundles produced.
- [ ] Requirement statuses updated; `docs/changelog.md` closed for V2.
- [ ] Lint, unit tests, E2E, Android emulator job, build green.

## Owner step

Review, commit, tag `git tag v1.19.0` and then, last, `git tag -a v2.0.0 -m "v2"` on the same commit, `git push --tags`, publish the GitHub release note, and submit the four listings.
