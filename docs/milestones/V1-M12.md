# V1-M12 — Slide rendering in annotation mode

**Tag at the end:** `v0.12.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M11 done (marks, playing order, detection exist).

**Requirements:** SLD-007, SLD-008, SLD-009, SLD-010, SLD-011, SLD-012, SLD-014, SLD-015, SLD-016, SLD-017, SLD-018, NAV-020. (SLD-001…006, SLD-013 are the M5/M6 functions used here.)

Goal: annotation mode shows the score slide by slide in playing order: composition with filler and dimming, the stored aspect ratio, navigation by buttons and slider, "slide x of n(+)", and sharp zoom through buttons. Gestures, keys, wheel and presentation mode come in M13. No drawing yet (M14).

## Core part (first)

Copy `docs/contracts/core/composition.ts` + `fixtures/composition.cases.ts` into `src/app/core/`, and `fixtures/entry-lookup.cases.ts`; `findEntryForSystem` already exists as a stub in `slides.ts` (copied in M4); add the export for `composition.ts` to `core/index.ts`. Write the specs first (red), then implement exactly the algorithm in the doc comment of `composeSlide`:

```
stackTop = (plan.height - plan.stackHeight) / 2
onSlide  = all system indices firstSystem..lastSystem of the regions
for each region (y running from stackTop):  desired = (cx - W/2, area.y, W, area.height), source = desired ∩ page, dest = (source.x-desired.x, y+(source.y-desired.y), source.w, source.h)
filler-top (stackTop > 1e-9) above regions[0]; filler-bottom below the last region, each clipped to its page
overlays: vertical intervals of padded areas of systems on the filler's page that are NOT on the slide, intersected with the filler source,
          mapped to slide space, merged, emitted as full-width rectangles; sorted by y
```

`findEntryForSystem`: first entry equal to the system; else the first entry holding the smallest value greater than it; else the last entry; empty → −1.

## Steps (the owner commits after each)

### S1 — Slide model in the document store (SLD-012, SLD-014, SLD-015, SLD-016)

In `DocumentStore` (computed signals over `core/`):

- `paddings = computePaddings(pagesUsable, T:detection.fallbackPaddingPageHeightRatio)`; `geoms: SystemGeom[]` = for each system: `{ index, pageIndex, box, padded: paddedArea(box, paddings[pageSlot], pageSize) }` (match padding to its page by `pageIndex`, not by array position).
- `slideWidth = referenceWidth(geoms)` (guard: no systems → `slides = []`).
- `aspectRatio` (effective) from `AspectRatioService`: `doc.ratioOverride[orientation] ?? global[orientation] ?? initialAspectRatio(screenW, screenH arranged for the orientation, T:aspectRatio)`, where `orientation = orientationOf(UiStore.viewport)`.
- `slides = packSlides({ entries: playingOrder.entries, forcedBreakAfter, systems: geoms, slideWidth, aspectRatio })`, `slideCount`, `slideCountIsFinal = detectionComplete`.
- **Position:** `position = { entry: number; system: number }` per tab (`entry` = entry index of the first entry on the current slide, `system` = its system index). Current slide = `slideIndexOfEntry(slides, entry)`. When the **playing order** changes (marks, detection swap) recompute `entry = findEntryForSystem(entries, system)`; when only ratio or orientation changes the entries are unchanged and `entry` stays (so a second pass is not lost). Navigating sets `entry = slides[i].entryStart` and `system = entries[entry]` (SLD-012).
- `AspectRatioService` (`state/`): global defaults per orientation in the preferences store (keys `ratio.portrait`/`ratio.landscape`), `captureForOrientation(width, height)` (used from M13 at the first presentation entry per orientation; implement and unit-test now), `showMore()` / `showLess()` which call `stepAspectRatio(current, 'more'|'less', T:aspectRatio)` and write `doc.ratioOverride[orientation]` (in memory; saved by M15 even for new values; on read-only files it simply stays in memory: SLD-015). Both buttons are disabled when the step would not change the value.
- Unit tests with fixture-style cases: override beats global beats screen fallback; orientation change picks the other override; position mapping after a jump edit with repeated systems; ratio change keeps the entry.

### S2 — Slide drawing (SLD-007, SLD-008, SLD-009, SLD-010, SLD-011)

`SlideView` component (`features/slides/`) shown in annotation mode when the active tab is ready and `slideCount > 0`:

1. `composition = composeSlide(plan, geoms, pageSizes)` for the current slide.
2. `displayScale = fitScale({ width: plan.width, height: plan.height }, stageSize, 'contain')` (SLD-010: the slide is fitted into the stage; the rest is canvas grey from the stage background). Because `plan.width` is the same for all normal slides, `displayScale` is the same for all of them (SLD-011); enlarged slides get a smaller `displayScale`.
3. One base `<canvas>` of the fitted slide size × `min(devicePixelRatio, T:resources.devicePixelRatioCap)`, reduced if it would exceed `T:resources.maxCanvasPixels`. Draw with a pure function `drawComposition(ctx, composition, bitmaps, pxPerUnit)` (kept free of Angular so it is unit-testable with a recording fake context):
   - `fillStyle = T:colors.canvasGrey`, `fillRect` over the whole canvas (areas outside the page stay grey);
   - for each `contents[i]`: `drawImage(bitmap, dest.x*pxPerUnit, dest.y*pxPerUnit, dest.width*pxPerUnit, dest.height*pxPerUnit)`;
   - for each overlay: `globalAlpha = T:colors.overlayOpacity`, `fillStyle = T:colors.canvasGrey`, `fillRect(0, y*pxPerUnit, width*pxPerUnit, height*pxPerUnit)`, then `globalAlpha = 1`.
4. Bitmaps come from `renderRegionCached` with region = `content.source` and scale = `pxPerUnit` (the helper from M8 caps and retries). All pieces of a slide are fetched first (scheduler class `visible`), then drawn once, so the old slide stays until the new one is complete.
5. After drawing, prefetch the neighbors' pieces with class `prefetch` (`governor.prefetchNeighbors` slides before and after; 0 under pressure). A slide change with warm cache must complete in ≤ `T:budgets.slideChangeP95Ms` (NFR-001; checked in M17).
6. Empty states: `slideCount === 0` and detection incomplete → centered `processing` icon; complete without systems → centered `error` icon with a tooltip.

### S3 — Navigation controls and ratio buttons (SLD-016, SLD-017, NAV-020)

- Bottom bar: `SlideIndicator` "x / n" (n+ while `!slideCountIsFinal`), `previous`/`next` buttons (disabled at the ends), slider (`<input type="range" min="1" max="n">`; expanded layout inline, compact in the popup opened by tapping the indicator) — every change calls `DocumentStore.goToSlide(i)`; the slider updates the display on `input` events, rendering follows at animation-frame rate.
- `showMore`/`showLess` buttons call the `AspectRatioService` (expanded: bottom bar; compact: overflow menu).
- Entering annotation mode with no position shows slide 0.

### S4 — Zoom and sharp re-render (SLD-018, NFR-007 reuse)

- Per-tab `slideView: ViewState` (`FIT_VIEW` default) in `DocumentStore`. Zoom buttons: `zoomIn`/`zoomOut` multiply by `T:zoom.buttonStep` around the stage center using `zoomAround(view, factor, center, {min: T:zoom.min, max: T:zoom.max}, fittedSlidePx, stageSize)`; `zoomReset` sets `FIT_VIEW`. Zoom resets to `FIT_VIEW` on every slide change (NAV-015).
- The base canvas is transformed with CSS (`translate(panX, panY) scale(zoom)`) immediately (stretched bitmap).
- After `T:rendering.zoomSettleMs` without changes and while `zoom > 1`: compute the visible rectangle of the slide in slide units, convert to px at the zoomed scale, `tilesCovering(visiblePx, zoomedSizePx, T:resources.tileSizePx)`, and for each tile draw the composition pieces that intersect it (reuse `drawComposition` with a clip/offset) into a tile canvas positioned in the stage; tiles replace the stretched part. Abort stale tile tasks when the view changes (NFR-008). Back at fit zoom the tile canvases are removed.
- Pan: with zoom > 1 the buttons only zoom around the center; panning arrives with gestures in M13 (the pan state exists but no input changes it yet).

## Tests

- Unit: composition and entry-lookup specs; `drawComposition` with a recording fake context (assert the exact `drawImage`/`fillRect`/`globalAlpha` calls for fixture cases CP01, CP02, CP06 at a pixel scale of 1); `AspectRatioService`; position mapping; padding-by-page matching with a document where page 0 has no systems.
- Component tests: `SlideIndicator` ("1 / 3+" while processing, "1 / 3" when final), button disabling, slider events.
- E2E on `synthetic-score.pdf` (three engines): annotation mode after detection: indicator shows `1 / n`; `next` increments; `showMore` changes `n` (more systems per slide → fewer slides); zoom in/out/reset work and zoom resets after `next`; overlays exist only where expected (assert by canvas pixel sampling in Chromium: a pixel in a dimmed filler band is lighter-grey than pure black ink and darker than paper white, sampled where CP02-like geometry applies — if the geometry is hard to hit, assert via the unit test only and skip the pixel test with a comment).
- A test with jumps from M11: create the repeat `4 → 0`; the slide count increases accordingly (compare with `packSlides` on the computed playing order, not magic numbers).

## Do not

- Do not implement gestures, keyboard, wheel, tap zones, presentation mode, drawing or saving.
- Do not change `core/` signatures or the packing algorithm; do not scale page content differently than `pxPerUnit`.
- Do not render whole slides at zoom as one huge canvas; tiles only after settling.
- Do not store slide results or bitmaps outside the LRU cache.
