# V1-M9 — Organization mode as a normal PDF viewer

**Tag at the end:** `v0.9.0`. **Model:** mid-tier, medium effort. **Prerequisite:** M8 done.

**Requirements:** ORG-001, ORG-002, ORG-003, ORG-004, ORG-005, ORG-006, ORG-007, NFR-007.

Goal: organization mode shows the whole PDF like a normal viewer: continuous vertical scroll, button zoom from fit-page to 4× fit-width, lazy tiled rendering, page indicator, previous/next page and a page slider. Pinch, wheel zoom and double-tap come in M13; here zoom works through buttons only.

## Core part (first)

Copy `docs/contracts/core/view.ts` and `fixtures/view.cases.ts` into `src/app/core/`; write `view.spec.ts` from the fixtures (red), then implement all functions of `view.ts` (including the slide-view functions `clampPan`, `zoomAround` and `tilesCovering`, even though some are used later). Hints:

- `fitScale`: `contain` = `min(vw/cw, vh/ch)`, `width` = `vw/cw`.
- `orgZoomLimits`: `min = Math.min(1, fitScale(page,viewport,'contain') / fitScale(page,viewport,'width'))`, `max = maxZoom`.
- `scrollAfterZoom`: `((s + a) * n / o) - a` per axis.
- `layoutPages`: running `top`, each page `size * scale`, `gap` between pages.
- `pageAtOffset`: first page with `y < top + height + gap/2`; empty → `-1`; beyond the last → last.
- `tilesCovering`: loop over grid columns/rows of `ceil(content/tile)`; keep cells with positive-area intersection; clip to the content; row-major order.
- `clampPan`/`zoomAround`: formulas are in the doc comments.

## Steps (the owner commits after each)

### S1 — Viewer structure and layout (ORG-001, ORG-002, ORG-006, ORG-007)

1. `OrganizationViewer` component (`features/organization/`), shown when `UiStore.mode === 'organization'` and the active tab is ready. It replaces `PagePreview`.
2. A scroll container (`overflow: auto`, native scrolling, momentum on touch) containing a sizer element whose height is the total of `layoutPages(pageSizes, scale, T:rendering.orgPageGapPx)` and whose width is the widest page at `scale`. Pages are absolutely positioned boxes with the page-white background; around them the canvas grey (GEN-008). `scale = fitWidthScale * zoom`, where `fitWidthScale = fitScale(widestPage, viewport, 'width')` and the viewport is the scroll container's client size.
3. Zoom state per tab in `DocumentStore.orgZoom` (default 1 = fit-width) and the scroll position per tab (`orgScroll`), restored when the tab becomes active again. Zoom never changes when the page changes (ORG-006). Horizontal swipes do nothing here (no handler).
4. No drawing tools in this mode (ORG-007): tools are already cleared by M7.
5. The viewer reads page sizes from `DocumentStore.pageInfos` (display space).

### S2 — Lazy tiled rendering (ORG-002, NFR-007, NFR-008)

- Visible set: pages whose layout box intersects the scroll viewport extended by `T:resources.orgRenderPagesAround` pages above and below.
- For each visible page, render **tiles**: `tilesCovering(visibleRectOfThatPage, pageSizeAtScale, T:resources.tileSizePx)` in page-local px at the current scale; each tile is a `<canvas>` positioned inside the page box. A tile's render request: region = tile rect / (scale × dpr) in display space, scale = `scale × min(devicePixelRatio, T:resources.devicePixelRatioCap)` (then `fitScaleToPixelCap`-checked by `renderRegionCached`). Use the scheduler class `visible` for tiles inside the viewport and `prefetch` for the margin pages.
- While a tile is missing, show the page's white background (no spinner text). When the zoom changes: keep old tiles scaled by CSS transform until `T:rendering.zoomSettleMs` after the last change, then render new tiles and drop old ones (abort stale tasks: NFR-008).
- Pages leaving the visible set release their canvases (bitmaps stay in the LRU cache until evicted).
- When `governor.prefetchNeighbors` is 0 the margin pages are not rendered.

### S3 — Navigation and zoom controls (ORG-003, ORG-004, ORG-005)

- `PageIndicator` in the bottom bar: "x / n" where x = `pageAtOffset(layout, scrollTop + viewportHeight/2, gap) + 1`, n = page count (all pages, including those without systems later). Updates on scroll (throttle to animation frames).
- `previous`/`next` buttons scroll to the top of page x−1 / x+1 (smooth, ≤ 200 ms; instant if `prefers-reduced-motion`); disabled at the ends. Page slider (a native `<input type="range">` styled with CSS) in expanded layout, in the popup opened from the indicator in compact layout: dragging scrolls to the page.
- Zoom buttons: `zoomIn` = `zoom × T:zoom.buttonStep`, `zoomOut` = `zoom ÷ T:zoom.buttonStep`, both clamped to `orgZoomLimits(widestPage, viewport, T:zoom.max)`; `zoomReset` = back to fit-width (zoom 1). Anchor: the viewport center; scroll adjusted with `scrollAfterZoom`. `zoomOut` disabled at the minimum (fit-page), `zoomIn` at the maximum.
- All three zoom buttons and the page controls are enabled when the tab is ready.

## Tests

- Unit: `view.spec.ts`; store tests for zoom/scroll persistence per tab.
- Component tests: `PageIndicator` text for scroll positions (with a fake layout); button enabling at ends.
- E2E on `synthetic-score.pdf` (three engines): organization mode shows "1 / 3"; scrolling the container to the second page shows "2 / 3"; `next` button moves one page; slider moves; zoom in raises the sizer width by the step; zoom reset restores fit-width; zoom stays after `next`; only canvases of visible pages exist (count ≤ visible tiles + margin); no tile is larger than `T:resources.tileSizePx`; switching tabs restores the scroll position.
- Chromium: the rendered tile has dark pixels where the staff lines are (sample a few coordinates).

## Do not

- Do not add pinch, wheel zoom, double-tap, keyboard navigation or swipes (M13).
- Do not draw bars or detection results (M10).
- Do not render whole pages as single canvases at high zoom; tiles only.
- Do not use `CSS zoom` or layout-changing zoom hacks that break the scroll position; use the sizes computed from `scale`.
